# Plan

This repository maintains two product editions. Determine the target from the user's request and the
paths being edited: `tdd-first/project` or `tdd-optional/project`. For a change affecting both editions,
read both policies and preserve each edition's intended behavior. Use existing authorization and decisions.

Read the selected product's `PROJECT-POLICY.md`, `templates/`, and
`examples/skills/plan/SKILL.md` with its relevant references. The
[selected-edition guide](../../../README.md) explains adoption and the maker/product boundary.
For maker-history documents, use the applicable form as a writing aid and root governance; do not
silently treat the maker repository as a product or invent a new approval requirement.

Follow the selected example to write executable implementation order and verification for the selected edition. Resolve its repository-relative paths against that
product folder while authoring the template; in an adopted project they resolve against the product root.
Keep the actual request, required design inputs and evidence; do not fabricate acceptance or test results.
The user may already have authorized this stage. Questions and status requests do not trigger implementation.

The product forms and examples are the maintained sources. Do not add another embedded form here.
Changing an optional-edition plan does not require manufacturing a RED result. Changing the first edition
does not remove its test-first default. Scope changes update the affected authoritative documents.
