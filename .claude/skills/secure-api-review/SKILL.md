# 조회 API 보안 리뷰

우리 조직이 조회 엔드포인트에서 반복해서 다친 자리를 규칙 넷으로 굳힌 것이다.
대상은 **고객 데이터를 읽어 응답으로 내보내는 엔드포인트** — 우리 레포에서는
청구 상태 조회 API(`src/claims_status/`)가 그 원형이다.

읽는 순서는 아래 넷이고, 규칙마다 **무엇을 보는가 · 무엇이 위반인가 · 어떻게
확인하는가**가 붙어 있다. 규칙 밖의 것(성능·스타일·네이밍)은 보지 않는다.

## 규칙 1 — 인증: 모든 조회는 기존 인증 경로를 지난다

**본다**: 핸들러가 호출자 신원을 어디서 얻는가. 그 신원이 조회 대상 청구건의
소유자와 대조되는가.

**위반**:

- 인증을 거치지 않는 익명 경로가 하나라도 있다. 「내부 전용」·「헬스체크」·
  「배치가 쓴다」는 사유가 아니다. 내부망은 인증이 아니다.
- 새 인증 수단을 이 엔드포인트만을 위해 만들었다. 조회용 토큰·고정 API 키·
  쿼리스트링 비밀값은 전부 여기 해당한다. 기존 세션 인증을 쓴다.
- 신원은 확인했는데 **소유권을 확인하지 않았다**. 로그인한 사람이면 남의
  청구건도 조회되는 것은 인증 통과가 아니라 인가 부재다.

**확인**: 인증을 벗긴 요청과 남의 청구 ID 를 넣은 요청 두 가지를 실제로 태워
본다. 둘 다 200 이 아니어야 한다. 안 태웠으면 「확인 못 함」이라고 적는다.

## 규칙 2 — 입력 검증: 받은 값의 모양을 먼저 정한다

**본다**: 경로·쿼리·본문으로 들어온 값이 상류 조회나 저장소 접근에 닿기 전에
모양 검사를 지나는가.

**위반**:

- 청구 ID 를 검사 없이 상류 조회 키로 넘긴다. 형식(접두 · 길이 · 허용 문자)을
  먼저 확정하고, 어긋나면 상류에 닿기 전에 거절한다.
- 페이지 크기·기간 같은 수치에 상한이 없다. 상한 없는 조회는 상류 부하 사고로
  돌아온다.
- 검사에 실패했는데 요청을 계속 처리한다(경고만 찍고 통과). 검사는 거절까지가 하나다.
- 거절 응답이 「무엇이 왜 틀렸는지」를 내부 구조로 설명한다. 거절은 하되 내부를
  비추지 않는다.

**확인**: 형식이 어긋난 값·상한을 넘긴 값을 넣어 상류 호출이 **일어나지 않는지**까지
본다. 400 만 보고 넘어가면 상류에 이미 닿은 뒤일 수 있다.

## 규칙 3 — 응답 허용 목록: 상류 레코드를 그대로 내보내지 않는다

우리가 가장 많이 다친 자리다. 상류 청구 레코드에는 주민등록번호·가입자 성명·
내부 메모가 함께 들어 있고, 그 레코드를 그대로 반환하면 전부 나간다.

**본다**: 응답이 만들어지는 자리가 어디이고, 그 자리가 **허용 필드 목록**을
거치는가.

**위반**:

- 상류 레코드를 그대로 반환한다. 변수 이름을 바꾸거나(`payload = record`)
  펼쳐 담아도(`{**record}`) 같은 위반이다. **이름이 아니라 출처가 판정 기준이다.**
- 응답을 만드는 자리가 둘 이상이다. 통로가 둘이면 다음 사람이 새 통로를 하나 더 만든다.
- 허용 목록이 두 곳에 있다. 한쪽만 늘어나면 다른 쪽은 조용히 낡는다.
- 허용 목록이 **제외 목록**으로 쓰였다(「이 필드만 빼고 전부」). 상류에 새 필드가
  생기면 그날로 샌다. 넣을 것을 적지, 뺄 것을 적지 않는다.

**확인**: 상류 레코드에 없던 필드를 하나 넣어 보고 그것이 응답에 나타나지
않는지 본다. 나타나면 허용 목록이 아니라 제외 목록이다.

## 규칙 4 — PII 는 로그와 에러에 남기지 않는다

**본다**: 로그·예외 메시지·추적 이벤트에 실리는 값이 무엇인가.

**위반**:

- 상류 레코드 전체나 요청 본문 전체를 로그에 찍는다. 디버깅용 임시 코드도 위반이다 —
  임시 코드가 가장 오래 산다.
- 예외 메시지에 조회 대상의 식별 정보가 그대로 실린다. 스택트레이스가 응답으로 나간다.
- PII 를 「마스킹했다」면서 앞뒤 몇 자를 남긴다. 부분 노출도 노출이다.
- 감사 로그가 필요해서 남긴다면 **무엇을 남기는지 목록으로 고정**돼 있어야 한다.
  「필요하면 다 남긴다」는 목록이 아니다.

**확인**: 위반 경로(없는 청구 ID · 권한 없는 조회 · 상류 타임아웃)를 태우고 그때
찍힌 로그 줄을 직접 읽는다. 정상 경로만 보면 에러 경로의 유출을 못 본다.

## 보고 형식

- 규칙 번호마다 한 줄: **위반 있음 / 없음 / 확인 못 함**. 셋 중 하나만 쓴다.
  안 본 것을 「없음」으로 적지 않는다.
- 위반은 `파일:줄` 로 지목하고 무엇이 위반인지 한 문장. 고쳐 주지 않는다.
- 확인란에 적힌 실측을 하지 않았으면 「확인 못 함」이라고 쓴다.

## 이 스킬의 한계

이것은 **조언적 통제**다. 읽히면 작동하고 안 읽히면 작동하지 않는다. 규칙 3 의
단일 통로·단일 허용 목록·단일 등록처는 사람이 안 읽어도 지켜져야 하므로 뒤에
기계를 하나 두었다. **리뷰를 마치기 전에 `scripts/check_endpoints.sh` 를 돌리고
그 출력을 요약에 포함하라.**
