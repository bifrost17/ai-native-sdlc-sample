# 개발 중인 기능의 테스트와 공개

GitHub Flow의 main은 기존 사용자 흐름을 유지하며 배포 가능하게 둔다. 코드 통합, 환경에 배포,
사용자에게 기능 공개는 서로 다른 결정이다. 합의한 **공개 단위**가 완성·검증되고 담당자가 공개를
수락하기 전에는 일반 사용자에게 열지 않는다. 독립적으로 완성·수락한 다른 기능은 먼저 제공할 수 있다.
이것은 우리 팀의 운영 선택이며, 모든 변경에 feature flag를 요구하는 GitHub Flow 규칙은 아니다.

## 필요한 경우에만 제어 선택

| 상황 | 기본 선택 |
|---|---|
| 한 PR로 완결되는 수정, 문서 변경, 호출되지 않는 안전한 호환 준비 | 추가 플래그 없이 기존 검증·배포 절차 사용 |
| 여러 PR의 미완성 기능이 일반 사용자용 배포물에도 들어감 | 단기 **release flag**로 일반 OFF, 개발·테스트 환경 또는 허용한 시험 대상만 ON |
| 큰 내부 구현 교체 | 안정된 인터페이스 아래 구·신 구현을 공존시키는 branch by abstraction; 전환 제어는 필요한 경우만 |
| 별도 미리보기 환경에서만 시험 | 환경 분리로 시험하되, main을 배포했을 때 미완성 기능이 열리지 않는지도 확인 |

한 공개 단위의 제어 지점을 도입하고 이후 PR에서도 같은 판단·설정을 재사용한다. PR마다 숨기는 코드를
넣었다 빼지 않는다. 작은 서비스는 기존 환경 변수나 설정 파일로 충분할 수 있다. 설정 반영에 재시작이나
설정 배포가 필요한지는 명시한다. 실시간 전환·다수 대상 관리가 필요해질 때 기존 SDK/서비스를 검토한다.

## 제어해야 하는 경계

- 미완성 release flag는 미설정·유효하지 않은 값·평가 오류 때 OFF가 기본이다. 기존 동작은 유지한다.
  캐시나 원격 설정을 쓴다면 오래된 값의 효력과 OFF 전파 지연도 정한다. 운영용 kill switch의 안전값은 별도 판단이다.
- 버튼이나 메뉴만 숨겨서는 부족하다. 직접 접근 가능한 API/명령과 쓰기·알림·외부 호출·작업 예약/실행 등
  실제 효과의 경계도 막는다. 시작 시 실행, 백그라운드 작업, 저장소 migration처럼 화면과 무관한 경로를 살핀다.
- 서버의 테스트 대상은 신뢰된 환경·인증 정보에서 정한다. 사용자가 임의로 보낸 쿼리·쿠키·로컬 설정을
  공개 권한으로 믿지 않는다. 플래그는 기존 인증·권한 검사를 대체하지 않는다.
- OFF라도 빌드·시작·기존 기능이 깨지거나 스키마가 비호환이면 통합 준비가 된 것이 아니다. OFF는
  이미 쓴 데이터나 진행 중인 작업을 되돌리지 않는다. 필요하면 호환 단계와 별도 복구 방법을 설계한다.

## spec, plan, 리뷰에 남길 것

별도 필수 문서를 늘리지 않고 해당 변경의 기존 절에 기록한다.

- **spec / Design·AC:** 공개 단위, 일반 기본 상태와 테스트 대상, 제어 경계·설정 실패 시 동작,
  공개 조건과 중단 시 유지할 계약. 정책의 결정자·기록 위치를 참조한다.
- **plan / Order·Proof:** 관련 PR마다 main에서 실행 가능한 부분, 일반/테스트 노출 상태, 남은 범위와
  OFF/ON 확인을 연결한다. 사용할 제어 이름·설정 위치, 담당자, 공개·중단 방법과 제거 조건도 함께 적는다.
  공개 단위가 끝나기 전 ON 시험은 그 PR 범위의 증거이며 전체 AC 통과가 아니다.
- **리뷰·공개:** 일반 OFF에서 기존 흐름과 직접 접근 차단, 테스트 ON에서 해당 기능, 최종 공개 전 전체
  공개 단위와 되돌릴 OFF 경로를 확인한다. 필요한 플래그 상호작용을 시험하며 모든 조합을 강제하지 않는다.
  공개 결정은 실제 코드 판·대상·설정 값·결정자·근거와 함께 프로젝트의 기존 운영 기록에 남긴다.
  테스트 ON 수락이나 PR merge가 일반 공개 수락을 대신하지 않는다.

예: 담당자 목록과 집계를 한 공개 단위로 합의했다면 PR1은 목록을 시험 가능하게 만들고 일반 OFF,
PR2는 같은 제어 아래 집계를 완성하고 일반 OFF를 유지한다. 두 PR 모두 기존 기능이 동작해야 한다.
전체 확인 후 담당자가 설정으로 공개한다. 아직 테스트하지 않은 일반 설정·대상에서 성공을 가정하지 않는다.

공개 후 안정성 관측과 필요한 되돌림 기간이 끝나면 담당자가 제어 제거를 결정한다. 먼저 최종 동작을
유지하는 소스·시험·문서를 반영하고, 그 설정을 읽는 구버전/복구 버전이 남아 있는지도 확인한 뒤 설정을
정리한다. OFF 기본값을 읽는 코드가 남았는데 설정부터 지우면 기능이 다시 꺼질 수 있다. 상시 권한이나
운영 제어는 단기 릴리스 플래그와 구분한다. 고정 만료 일수나 별도 관리 시스템은 요구하지 않는다.
