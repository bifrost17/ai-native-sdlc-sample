# 무엇이 정본인가 — the repo as the source of truth

플레이북 레슨 4 는 아티팩트마다 정본을 **하나 지명하라**고 요구하고 세 가지 구성을 든다:
이슈 트래커가 정본 · 레포가 정본 · 둘을 잇는 하이브리드. 이 레포는 그중 **「레포가 정본」**
을 택한다. 안 정하면 다음 사람이 추측하고, 추측이 두 갈래로 갈리는 날 두 기록이 서로를
반박한다.

## 선언

> **intent · spec · plan · 코드 · 시험 · 그 사이의 결정은 전부 이 저장소가 정본이다.**
> 외부 시스템(이슈 트래커 · 결재 · 사내 위키)에 같은 내용이 있으면 그쪽이 **사본**이다.
> 충돌하면 저장소가 이긴다.

따라서:

- 승인은 **머지된 PR** 이라는 사건이고, 그 사건은 git 이 안다(`docs/STATUS.md`).
- 별도의 승인 원장 파일을 두지 않는다. 원장은 해시 체인을 붙여도 다시 체인을 계산해
  위조할 수 있고, 그 위조는 검사기가 rc=0 으로 통과시킨다. git 의 커밋 그래프가 이미
  그 일을 하고 있으므로 두 번째 원장은 위험만 늘린다.
- 아티팩트의 시각 필드를 늘리지 않는다. `created`(첫 대화 시각 · 발의자 신고값) 하나만
  두는데, 그것이 git 이 모르는 유일한 값이기 때문이다.

## `record:` 필드의 뜻

intent 의 frontmatter 에는 `record:` 가 있다. 값은 **외부 기록의 ID 하나** 또는 `none` 이다.

```
record: LEGAL-2291      # 사내 트래커의 그 건 — 링크일 뿐이다
record: none            # 외부 기록 없음
```

이 필드가 뜻하는 것과 뜻하지 않는 것:

| 뜻한다 | 뜻하지 않는다 |
|---|---|
| 저 바깥에 같은 사안의 기록이 있다 | 저쪽이 정본이다 |
| 사람이 그 ID 로 이력을 더 찾아볼 수 있다 | 저쪽 상태가 이 아티팩트의 상태다 |
| 감사 때 두 세계를 잇는 실이 된다 | 저쪽이 닫히면 여기도 닫힌다 |

검증기는 `record:` 의 **존재와 비어 있지 않음**만 본다. 외부 시스템에 그 ID 가 실재하는지
묻지 않는다 — 그건 이 레포가 소유하지 않은 어휘이고, 소유하지 않은 어휘를 열거하는 검사는
다음 판에 죽는다.

## 레거시와 붙일 때의 갈림길

사내에 이미 결재·요구관리 시스템이 있으면 셋 중 하나를 **고르고 문서에 적는다.**

| 구성 | 정본 | 이 레포가 하는 일 | 대가 |
|---|---|---|---|
| A. 레포가 정본(이 레포의 선택) | git | 저쪽엔 `record:` 링크만 | 저쪽 결재 흐름을 쓰는 사람이 두 곳을 본다 |
| B. 트래커가 정본 | 트래커 | 아티팩트에 트래커 ID 를 박고 상태는 **읽기만** | 승인 증거가 git 밖에 있어 사슬이 반쪽이 된다 |
| C. 하이브리드 | 단계마다 다름 | 단계별로 정본을 표에 못 박고 동기화 지점을 만든다 | 동기화가 깨진 날을 아무도 모른다 — 대조 검사가 별도로 필요하다 |

**고르지 않은 것이 최악이다.** B 나 C 로 간다면 이 문서를 고치고, `docs/STATUS.md` 의
「전이 · 증거」 표에서 *증거* 열을 그 시스템의 사건으로 바꿔 적어야 한다. 코드만 바꾸고
이 지면을 두면 다음 사람이 이 지면을 충실히 따라 사슬을 반대로 잇는다.

## 이 선언이 만드는 제약

- 아티팩트를 저장소 밖(위키·문서 도구)에서 먼저 쓰고 나중에 붙여 넣지 않는다 — 그러면
  `created` 와 첫 커밋 사이가 벌어지고, 레슨 2 의 leading 지표(첫 대화 → 커밋)가 거짓이 된다.
- 비엔지니어 발의는 이슈 폼으로 받되, **폼의 값이 파일이 되는 순간**부터 저장소가 정본이다.
- 외부 시스템의 상태를 이 레포로 자동 동기화하지 않는다. 동기화는 정본을 둘로 만든다.
