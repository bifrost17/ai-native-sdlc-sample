# 개발건별 문서와 이름 규칙 보완

2026-09-13. 출발판 `182deba756111635f6cda182b7a795aa0926ea47`, 작업 브랜치 `codex/change-document-naming`.
사용자는 신규 개발·추가 개발·유지보수 요청이 어떤 문서 묶음에 기록되며 어떤 이름으로 구분되는지
확인하고 모호한 부분을 보완하도록 요청했다.

## 확인과 결정

기존에도 `intent/<NNNN>-<slug>/` 개발건 폴더 안에 `intent.md`, `spec.md`, `plan.md`를 두었다.
첫 번호와 병렬 중복을 피하라는 안내는 있었으나 slug 규칙, 후속 요청의 기존 건 재사용·신규 분리,
완료된 기록과 현재 설계의 관계는 명확하지 않았다.

[북극성](../verification/north-star-playbook.html)의 L2~L4에서 의도·설계·계획을 공유 저장소에 남겨
사람과 에이전트가 이어받고, 피드백에 따라 영향 문서를 갱신하는 취지를 기준으로 보완했다.
번호·slug·완료 뒤 신규 번호는 그 취지를 적용한 팀 규칙이며 플레이북이 정한 보편 양식으로 주장하지 않는다.

- 개발건은 폴더, 문서 역할은 고정 파일명으로 구분한다. 상세 설계는 spec이 필요한 문서를 연결한다.
- 번호는 제품 저장소 안에서 최소 네 자리로 증가시키고, 영문 소문자·숫자 단어를 하이픈으로 연결해 목적을 쓴다.
  사용자는 자연어로 요청하며 에이전트가 기존 범위를 확인해 경로를 정한다. 문서 제목·본문은 요청자의 언어를 쓴다.
- 진행 중인 같은 목표는 기존 폴더를 갱신한다. 독립적으로 완료할 목표와 완료 기능의 후속 개발·수정은
  새 폴더에서 이전 계약을 연결한다. 여러 PR·세션·에이전트가 같은 개발건을 수행할 수 있다.
- 질문이나 동작·설계·검증 계획이 바뀌지 않는 오탈자 정리에 문서 세트를 새로 만들지 않는다.
- 후속 spec은 이전 기준판·경로·절과 변경·보존 범위를 연결한다. 현재 공통 설계 정본이 바뀌면 함께 갱신하고,
  과거 수락과 결정은 Git 이력에 보존한다. 이전 설계 전체 복제나 새 상태 장부는 필요하지 않다.

당시에는 두 배포판의 변경 기록 규칙을 함께 보완했다. 2026-09-15 이후 현행 정본은
[선택형 변경 기록 규칙](../../tdd-optional/project/intent/README.md) 하나다.
각 배포판의 CLAUDE·PROCESS·GIT-WORKFLOW가 당시 정본으로 연결됐고, 선택 작성 예시 capture-intent도
새 문서를 만들기 전에 기존 개발건을 확인하도록 보완했다. TDD 정책과 문서 양식의 항목은 바꾸지 않았다.

## 리뷰와 검증

Sol/medium 독립 리뷰는 실제 변경 10개 파일로 첫 기능, 같은 목표의 후속 대화, 일부 PR만 통합한 건,
완료 기능의 버그, 독립 유지보수, 오탈자, 독립 목표 둘, 상태 질문, 번호 충돌, 공통 설계 변경을 대조했다.
두 문구 보완 뒤 10개 시나리오를 문서 기준으로 통과 판정했다. [리뷰 전문](change-document-identity-review.md).

- `make check`: unittest 102개 실행(1개 건너뜀), hooks 28개, eval fixture 8개, managed settings 확인 통과.
- 최종 리뷰 문구 반영 뒤 `test_template_editions.py` 3개 통과: 복사한 제품 내부 참조와 양판 계약 등을 확인했다.
- 선택형의 기존 Codex explicit-only patch를 임시 복사본에 offset/fuzz 없이 적용했다.
  capture-intent 본문 보존, 명시 호출 정책, 변환본 quick_validate, 양판 규칙·예시 일치를 확인했다.
- `git diff --check` 통과. [명령 결과와 변환본 해시](change-document-identity-checks.txt)에 보존했다.

기본형에도 Codex adapter가 있다고 가정한 첫 임시 검사 시도는 없는 경로에서 중단됐다.
실제 adapter가 있는 선택형으로 확인 범위를 정정했다. 기본형 Codex 설치 성공을 주장하지 않는다.

## 반영 범위와 한계

root는 문서 구조와 요청 분류의 모호함이 해소됐고 기존 정책을 유지한다고 판단했다.
이번에는 제품 개발 실험이나 자연 스킬 선택 실험을 실행하지 않았다. 따라서 북극성의 실행 주석·점수를
새 성공으로 올리거나 0033·0034 등 과거 실험 판정을 바꾸지 않는다.

제작용 보완을 로컬 main에 통합한다. org-skills 패키지 본문·manifest는 바꾸지 않았으므로
패키지 버전은 기본형 0.1.9·선택형 0.1.5를 유지한다. 프로젝트 작성 예시는 이 Git 판으로 식별한다.
기존 제품·전역 설치·보존된 실험 작업 공간은 자동 갱신하지 않았다. 기존 제품에 적용할 때는
이 변경 규칙과 진입 문서, 채택한 경우 capture-intent 예시를 제품의 로컬 변경과 함께 비교해 갱신한다.
