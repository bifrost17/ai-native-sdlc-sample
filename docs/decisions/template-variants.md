# TDD 기본형과 선택형의 최상위 폴더 분리

현재 상태: **2026-09-15 [단일 템플릿 결정](single-template.md)으로 대체됨.** 아래는 2026-09-12의
두 배포판 분리 기록이다. `tdd-first/` 관련 경로는 현재 배포 파일이 아니며 삭제 직전 Git `b9af49a`에서 읽는다.
기존 사용자 설치는 당시에도 변경하지 않았다. 보존 범위·실행 증거·미검증 범위는 [배포판 검증 기록](../verification/variants/README.md)에 있다.

## 결정

최상위에 **`tdd-first/`와 `tdd-optional/`**을 둔다. 각 폴더는 하나의 채택 가능한 배포판이다. 두 배포판 안에는 제품 저장소로 복사할 `project/`와 선택 설치할 `org-skills/`를 구분한다.

제작 저장소 전체와 실제 사용 템플릿은 다르다. 출발 사용 후보 `codex/use-template-0026@84a77b3`에는 `PROJECT-POLICY.md`, 문서 양식·가이드·작성 스킬 예시가 있고 활성 `.claude` 설정·훅은 없다. 이 구분을 유지했다. [현재 README](../../README.md)는 두 배포판으로 안내한다. 제작 저장소의 테스트·실험·연구 자료를 제품 템플릿에 모두 복사하지 않는다.

`tdd-first`는 현재의 새·변경 동작 test-first 기본과 기존 예외를 유지한다. `tdd-optional`은 작업별로 TDD, 동작별 구현 후 테스트, 기존 테스트 활용, 혼합을 선택한다. 인수 조건, 문서 정합성, 독립 검증과 사람의 의사결정 구조는 두 판에서 유지한다.

`…`는 생략 표시이며 상대 판을 읽는 링크나 의존성을 뜻하지 않는다. 각 판의 `project/`에는 필요한 파일이 실제로 모두 있다. 기존 팀 정책 자료 중 채택 제품이 실행 중 읽어야 하는 것은 채택 과정에서 그 제품 안에 포함하거나 프로젝트의 실제 정책으로 채운다.

## 양쪽에서 같게 유지할 것과 달라질 것

| 영역 | 공통으로 유지 | 판별 차이 |
|---|---|---|
| intent·spec | 문제·범위·요구사항·설계·인수 조건, 다문서 연결 | 테스트 작성 순서를 spec에 강제하지 않는다. 양식은 가능하면 동일하게 유지. |
| plan | 실제 변경 파일, 순서·의존성, PR·통합·공개 상태, 위험과 완료 증거 | 기본형은 first-test/RED 중심. 선택형은 검증 방식과 선택 이유, 동작별 구현·검증 순서를 표현. |
| 프로젝트 정책 | 역할·수락·보안·데이터·운영·기존 검증 보존 | 기본형의 test-first 기본을 선택형에서는 작업별 선택으로 변경. 선택 자체를 예외 승인으로 취급하지 않음. |
| 작성 스킬·예시 | 충분한 설계·실행 가능 계획, 영향 문서 갱신 | 선택형 예시에 TDD와 작은 구현 후 테스트를 모두 포함. 지침과 예제가 한 방식을 다시 강제하지 않도록 맞춤. |
| TDD 스킬 | 선택했을 때 의미 있는 RED→GREEN을 확인하는 방법 | 기본형은 새·변경 동작에서 사용. 선택형은 TDD가 선택된 작업에서 사용. 자동 선택 설명과 본문 모두 조정. |
| 피드백·검증자 | 계약·문서·실제 결과 대조, 회귀 보호, 독립 검토 | 기본형은 test-first 실행 증거. 선택형은 합의한 방식과 검증의 충분성; TDD 미사용만으로 결함 판정하지 않음. |
| 사람 판단·승인 | 현재의 승인·병합·운영 권한 구조 | 이번 분리로 별도 승인 단계나 상태 검사기를 추가하지 않음. |

차이는 `plan.md` 한 파일로 끝나지 않는다. 기본형의 TDD 전제는 [계획 스킬](../../tdd-first/project/examples/skills/plan/SKILL.md), [TDD 스킬](../../tdd-first/org-skills/skills/tdd/SKILL.md), [피드백 스킬](../../tdd-first/org-skills/skills/sdlc-feedback/SKILL.md), [Claude 검증자](../../tdd-first/org-skills/agents/sdlc-verifier.md), [OpenCode 검증자](../../tdd-first/org-skills/opencode/agents/sdlc-verifier.md)에도 있다. 선택형은 이 연결 전체를 같은 선택 규칙으로 맞췄다. 연구 근거와 적용 한계는 [TDD 비교 보고서](../research/tdd-vs-test-after/README.md)를 따른다.

선택형에서도 버그 수정은 먼저 증상을 재현하는 진단을 권장한다. 다만 `docs/PROCESS.md`의 재현 안내를 모든 경우의 자동 테스트 선작성 의무로 연결하지 않는다. 수동·임시 스크립트 재현과 영구 회귀 테스트를 구분하고, 선택한 방식에 맞게 검증한다. 구현 후 만든 테스트를 기준판에 재생한 경우에도 원래 TDD를 수행했다고 소급하지 않는다.

## 소스와 사용 경계

1. **제품 채택 단위는 `project/`의 내용이다.** 새 제품 저장소의 루트에 복사한다. 제작 저장소 아래에서 `cd tdd-optional/project`만 한 상태를 독립 제품 실행과 같다고 가정하지 않는다. 제품별 Git 루트·지침·검증 명령을 가진 별도 작업 공간에서 확인한다.
2. **스킬은 해당 판의 패키지를 선택 설치한다.** 두 판의 플러그인 식별자를 구분하고, 기존 식별자와 기존 설치는 기본형에 대응시킨다. 새 선택형에 기본형 패키지가 함께 적용되지 않도록 설치 안내와 실제 로드 경로를 확인한다. 이름 분리만으로 실행 지침 충돌이 해결됐다고 판단하지 않는다.
3. **활성 작성 스킬·훅을 기본 설치하지 않는다.** 현재 사용판의 `examples/skills/` 방식을 유지한다. 제작용 `.claude/hooks/`, `INTENT_TASK=fix`, 제작 검증 명령을 제품 템플릿에 자동 포함하지 않는다. 조직이 이미 선택한 통제는 그 적용 범위 안에서 유지한다.
4. **두 판은 외부 공통 폴더에 실행 의존하지 않는다.** `../../common`이나 symlink로 정책·양식을 조립하지 않는다. 선택한 `project/`와 선택 설치 패키지가 독립적으로 읽히게 한다. 연구·출처 링크는 별개다.
5. **공통 내용의 작은 중복을 허용한다.** 공통 양식·정책를 바꾸는 작업에서는 양쪽 영향도 같이 검토한다. 현재 단계에서 상속·overlay·생성기·자동 동기화 규칙을 추가하지 않는다. 판별 차이를 diff로 읽을 수 있는 단순한 구조를 우선한다.
6. **제작 규칙과 제품 규칙을 구분한다.** 루트 `CLAUDE.md`와 제작 도구는 두 판을 만드는 작업의 범위와 대상 경로를 명시한다. 기본형 규칙이 선택형 결과물에 무조건 적용되지 않도록 현재 상위 TDD 문구와 작성 스킬의 참조를 함께 정리한다.

`project/`에서 형제 `org-skills/`를 필수 상대 경로로 읽게 하지 않는다. 설치 안내는 각 판의 README가 맡고, 스킬 내부의 동반 검증자·참고 자료는 패키지 안에서 연결한다. 제작 연구에 대한 출처는 보존 커밋의 외부 URL 등으로 연결하며, 실행할 때 제작 저장소의 연구 폴더를 요구하지 않는다. OpenCode 설치 문서의 고정 SHA·patch도 해당 판으로 맞춘다.

## 기존 경로의 처리

| 분리 전 자산 | 채택한 처리 |
|---|---|
| 사용 후보 브랜치의 제품용 파일 | 고정한 판을 `tdd-first/project/`의 출발점으로 가져온다. 이후 기본 소스는 이 폴더로 명확히 한다. |
| `templates/`와 제품용 작성 스킬·예시 | 각 `project/templates/`, `project/examples/skills/`, `project/docs/sdlc-authoring/`로 모은다. 제작용 복사본과 배포판을 서로 다른 최신 정본으로 유지하지 않는다. |
| 루트 `org-skills/` | 기본형 패키지로 옮기고 선택형을 파생한다. marketplace source, 설치 설명, 상대 참조를 갱신한다. |
| 루트 `.claude/` | 제작에 필요한 도구만 유지한다. 작성 작업이 어느 판을 대상으로 하는지 알고 해당 양식·예시를 읽게 한다. |
| `docs/research`, 기존 실험·intent 이력 | 공통 위치에 유지. 과거 커밋·실행 결과를 새 선택형 결과로 이름만 바꾸지 않는다. |
| 기존 북극성 주석 | 당시 판과 실행 근거를 보존. 선택형의 의도적 차이와 미검증 범위는 별도 문서에 기록. |
| tests·evals·CI | 제작 루트에 유지하되 검사 대상 판의 경로를 명시. 두 판을 실제 채택 구조로 분리한 공간에서 확인한다. |

현재 실험 브랜치와 고정 커밋은 역사적 근거로 보존한다. 폴더의 현행 소스와 과거 실행 기준판을 구분하고, 모든 옛 기록의 경로를 현행 판으로 치환하지 않는다.

## 이 구조를 구현할 때의 완료 기준

- 기본형은 이동 전후 정책·양식·스킬의 의미가 유지된다. 선택형은 프로젝트 지침·plan·스킬·검증자가 동일한 선택 규칙을 갖는다.
- 각 `project/`를 별도 제품 루트로 옮겼을 때 필요한 문서·예시의 상대 링크가 연결된다. 다른 판이나 제작 전용 파일을 필수로 요구하지 않는다.
- 필요한 경우 선택 설치한 스킬과 Claude/OpenCode 검증자가 올바른 판·경로를 읽는다. 설치 발견·파싱 성공과 실제 사용은 구분한다.
- 기본형의 기존 TDD 행동과 선택형의 TDD 선택/미선택 동작을 작은 실제 작업에서 각각 확인한다. 기존 정적 테스트나 intent/spec 중심 eval 통과만으로 이 차이를 입증했다고 하지 않는다.
- 공통 인수 조건·회귀 검증·문서 갱신·사람의 결정 구조가 유지된다. 새 선택형의 검증 전에는 기존 실험의 통과 판정을 승계하지 않는다.

이 설계의 분리 단위는 **개발 방식별 배포판**이며, 각 배포판의 사용 단위는 **제품 템플릿과 선택 설치 스킬**이다.
