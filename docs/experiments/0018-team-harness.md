# 0018 — 실행되는 독립 검토와 자동 보완

목표를 **중요한 spec·plan 누락이 사람의 별도 상기 없이 독립 검토와 보완으로 이어지는 것**으로
수정했다. 사용 템플릿은 `add296d` 그대로 두고 별도 [팀 명령](../../team-harness/README.md)을
구현·사용자 위치에 설치했다. 문서 의미는 독립 모델이 판단하며 실행 도구는 호출·기록·재개·오류
인계를 맡는다. 정상 질문·수락 대기와 문서 변경이 필요 없는 작업은 별도로 평가한다.

## 실행 경계

`sdlc-claude --project … --chain … --base …`는 개발 응답 뒤 독립 검토를 실행한다. 구체적 보완
판정이면 같은 개발 세션을 최대 두 번 자동 resume하고 마지막 판도 재검토한다. pass/wait는 rc0,
unknown·오류·미해결 상한은 rc2다. wait를 작업 완료로 세지 않는다. 원본 업무 요청·HUMAN 답변,
현재 문서·기준 대비 변경과 실제 실행 근거를 함께 검토한다.

개발은 Sonnet/low, 최종 검토는 Sonnet/medium이며 검토는 tools 없이 별도 세션에서 실행한다.
초기 low 검토의 실패를 근거로 검토 역할만 조정했다. 검토에 safe-mode를
적용해 프로젝트 CLAUDE.md 자동 주입을 끄고, 제공한 증거만 판단하도록 한다. 개발 프로필은
restricted, hooks/MCP/선택하지 않은 플러그인 off다. Git 작업은 HUMAN이 수행한다. 팀 스킬을
실행하거나 조직의 기존 통제·병합 권한을 모두 재현한 실험으로 주장하지 않는다.

## 비교 가능한 업무와 통제

[v4 데이터](datasets/v4/manifest.json)는 F02/seed102를 재사용한다. 실제 대화는 PR1 통합
`28b8fa8`에 후보를 적용한 `8dbf319f19fd8be2e006151867363b7867665bfb`의 별도 얕은 clone에서
시작했다. 제작 스크립트·하네스·oracle을 제품 저장소에 복사하지 않았다. Codex root가 제품
책임자 HUMAN, Claude Code가 AGENT다. HUMAN은 업무 조건·수락·Git을 맡고 문서 갱신을 상기하지 않았다.

H01은 기존 summary 구현 뒤 내부 자동화를 위한 JSON 출력을 요청한다. 개발 응답 뒤 실험
도우미가 spec/plan을 이전 판으로 한 번 되돌리며 실제 개발·검토 모델 응답은 변조하지 않는다.
각 주입의 앞/뒤 파일과 해시를 보존했다. **주입한 누락은 자연 발생한 AGENT 실패가 아니다.**
정상 갱신을 되돌린 상태에서 독립 검토와 자동 복구가 실제 동작하는지를 시험한다.

## 실패를 보존하고 검토 입력을 보완

첫 정상 T1은 계획된 summary 구현·8개 시험·수동 동작이 확인되어 pass였다. 설계·계획 이탈이
없으므로 spec/plan을 형식적으로 수정시키지 않았다.

T2의 개발 AGENT는 JSON 기능과 spec/plan을 실제 갱신했다. 실험이 두 문서를 되돌린 뒤 검토자는
현재 문서에 요구가 없는데도 과거 Edit와 완료 요약을 믿고 pass했다. 검토 지침에 현재 파일 우선을
강조한 T3도 같은 문제를 놓쳤다. **두 판정은 HUMAN 감사에서 실패로 재분류했다.** 원본 pass 결과를
덮어쓰지 않는다. 코드·시험 통과나 과거 문서 편집 이력은 현재 문서 정합성의 증거가 아니었다.

보완한 실행 도구는 원본 공개 transcript를 보존하되 검토 입력에는 현재 문서·변경 파일 전체를
별도로 제시한다. 과거 Read/Edit/Write 본문과 지난 완료 주장·검토 이유는 현재 파일의 근거에서
제외하고 작업·결과·원본 해시 참조로 남긴다. 실제 Bash 명령·결과와 모든 HUMAN 업무 요청·수락은
유지한다. 문서 내용을 판단하는 문자열 규칙은 추가하지 않았다.

동일 누락 상태의 검토 전용 재실행은 현재 spec R1–R7/AC1–AC8과 PR2 계획에 JSON 요구가 없음을
명확히 찾아 revise했다. 지침 문구만의 효과로 주장하지 않는다. 입력 구성과 검토 격리도 함께 바뀌었다.

수락 spec을 커밋한 뒤에는 다른 누락이 드러났다. plan 내용은 새 요구를 담았지만 Upstream은 이전
`892d6a5`를 가리켰다. low 검토는 이를 통과했고, 검토 전용 재실행에서도 현재 HEAD와 plan의 참조를
혼동하거나 사소한 차이로 해석했다. 이 결과도 실패다. 같은 입력에서 Sonnet/medium이 실제 오래된
plan 참조와 HUMAN 수락 `76a38cc`를 대조해 revise했다. [개정 spec](../../intent/0018-team-harness/spec.md)에
따라 검토만 medium으로 바꿨다. 개발은 low이며 Opus나 높은 추론을 기본값으로 올리지 않았다.

대화 맥락도 유지한다. 과거 pass의 완료 주장은 해시 참조로 남기지만, wait의 실제 질문·선택지는
보존해 HUMAN의 짧은 답변을 해석할 수 있게 했다. 기록이 없거나 근거가 불충분하면 인계한다.

## 최종 실행과 판정

**HUMAN은 수정한 목표의 관측 범위를 통과로 판정한다.** 8회 HUMAN 대화와 2회 자동 보완이
같은 개발 세션에서 실행됐다. 이전 실패를 새 통과로 소급하지 않으며 전체 SDLC 성공률로 계산하지 않는다.

| 실제 runtime turn | 결과와 HUMAN 판정 |
|---|---|
| 01 | 계획된 summary, pass. 문서 영향 없음 |
| 02·03 | 주입된 현재 spec/plan 누락을 pass한 실패. 원본 유지 |
| 04 → 자동 05 | 누락 revise → 실제 자동 resume으로 spec/plan 복구 → pass |
| 06 | 새 spec 수락 후 plan의 오래된 참조를 pass한 실패 |
| 07 → 자동 08 | 검토 medium에서 참조 누락 revise → 자동 resume으로 수락 SHA 갱신 → pass |
| 09 → 10 | 미래 업무의 질문·범위 수락 대기 wait → 짧은 답변과 보류 결정 pass, 파일 변경 없음 |

HUMAN이 수락한 spec은 `76a38cca43a4cf5b17432bd289256120b30916b0`다. 최종 제품
`0732201e8fb413ccf59361948aca63f27b4f5099`는 바로 그 커밋을 부모로 하며 plan·코드·시험·README를
함께 담았다. plan은 해당 수락 SHA를 참조한다. 제품 시험은 10/10, 독립 CLI는 15개 통과이며
질문·보류 대화 후에도 제품이 바뀌지 않았다.

H02는 과거 자연 누락의 원본 두 턴과 diff를 `d22a9fe`에 재구성한 검토 전용 사례다. H03은 같은
입력의 spec/plan에 의미 없는 주석만 추가했다. 최종 medium 검토는 두 사례 모두 revise했다.
중간에 필수 feedback 필드 누락으로 구조화 출력이 실패한 두 호출은 unknown으로 보존했다.
필수 세 필드를 지침에도 명시한 뒤 각 한 번의 재검토로 성공했다. H03 피드백 끝의 불필요한
직렬화 문자열도 기록했으며 올바른 의미 판정을 무오류 출력의 보장으로 일반화하지 않는다.

## 회귀와 범위

독립 제품 확인은 15개 CLI 사례(기본/JSON·담당자·없는 담당자·대소문자·목록·조회·완료 후 집계·
빈 데이터)와 읽기 전용을 대조했다. 기존 시험 5개/helper 2개의 AST와 fixture SHA256
`c038196ad9f748e482a446e4025e4c6c0746b23942c39f5f457ad37dd9a53795`를 보존했다.

| 구간 | 평가 범위 |
|---|---|
| 업무·요구·설계 | 최신 업무 추가와 실제 현재 spec의 정합성, 정상 HUMAN 결정 대기 |
| 계획·인계 | JSON 범위·검증 계획·수락 spec 참조, plan과 구현의 같은 커밋 |
| 구현·검증 | 제품 기능·기존 동작·실제 시험 결과, 독립 검토의 false pass도 실패로 보존 |
| 실행 계층 | 오류/timeout/비JSON/상한/stale/재개, 원본 보존과 독립 검토 격리 |
| 고정 가이드 | 영향 없는 역할·양식·원문은 이전 0015–0017 근거 재사용 |
| 조직 경계 | 실제 팀 스킬·PR 승인 권한·호스티드 CI·배포·장기 성공률은 이번 미관측 |

초기 독립 코드 검토는 오류 뒤 resume 불능, reviewer 자동 문서 주입, installer 임시 symlink의
비소유 파일 손상, symlink loop의 rc1을 발견했다. 모두 수정하고 각각의 회귀 시험을 추가했다.
모의 백엔드 시험은 실행 계층의 근거이며 실제 의미 판단이나 Claude 호출의 성공 증거로 세지 않는다.

## 설치·기록·한계

사용자 전용 `~/.local/share/intent-sdlc-harness` 및 `~/.local/bin/sdlc-claude`에 설치했다.
PATH·개인 Claude 설정·사용 템플릿은 수정하지 않았다. 실행 기록은 프로젝트 밖의
`~/.local/state/intent-sdlc-harness/12ed90a4-c429-4e7b-a7ef-07183dfb4f32/`에 있다.
최종 판은 매 turn 검토 지침 원문·runtime/prompt SHA·실제 argv·입력 digest·결과·모델·비용·시간을
남긴다. 초기 T1–T3는 지침 파일 자체를 턴별 저장하기 전의 실행이며 그 한계를 숨기지 않는다.

직접 `claude` 호출은 이 경로를 거치지 않는다. 작은 사슬·텍스트 파일을 대상으로 검증했으며
지원하지 않는 입력·과도한 크기는 인계한다. 독립 모델의 무오류나 사람의 승인 책임을 대체하지 않는다.
검토 도구와 템플릿을 분리해 템플릿을 범용 절차 검사기로 키우지 않았다.

8회 HUMAN 대화·2회 자동 보완·검토 전용 비교를 보존했다. 기록 커밋은 제품 0732201을 바꾸지 않는다.
공개 자료의 이메일은 가렸으며 원래 실행 digest와 공개 바이트 hash의 차이는 manifest에서 구분한다.
