## 실행과 예산

작은 전체 사슬 1회: 의도·질문 → 구체 spec → plan → PR1 목록/공개 제어 → PR2 요약 → JSON 후속
요구 → 전체 회귀·HUMAN 수락 → 새 디렉터리 인도·OFF/ON/OFF. 실제 질문·결과에 따라 HUMAN이 답하며
고정 대화 대본이나 구현 답안을 전달하지 않는다. 최초 방법 선택은 AGENT에 맡긴다. 선택한 방식 자체를
성공/실패로 채점하지 않는다. TDD만 선택되면 비TDD의 런타임은 미관측으로 남긴다.

필요한 경우 완료 제품에서 기존 시험을 활용하는 좁은 리팩터링 또는 비TDD 리뷰 수정 **부분 사례 1회**를
새 세션으로 진행한다. HUMAN이 방법을 명시한 실행은 자연 선택과 구별한다. 불필요한 새 테스트 파일이나
가짜 RED를 강요하지 않고 기존 검증의 실제 범위와 최종 독립 검토를 본다.

최초 개발 CLI 호출부터 **총 60분 또는 root 개발 CLI 8호출** 중 먼저 도달하는 시점에 중단한다.
실제 중요한 누락이 발견되면 영향 지침/예시를 최소한으로 한 번 보완하고 새 세션의 해당 부분을 재시험한다.
보완 후 반복도 같은 예산 안에 포함한다. 오류·중단·첫 실패를 유지하며 통과하려고 조건·기대·예산을 바꾸지 않는다.
목표는 사람이 함께 주요 흐름을 대체로 잘 따르는 수준이며 모든 행동을 강제하는 프로그램을 만들지 않는다.

## 판정 기준

| 관찰 | 기준 |
|---|---|
| 선택 | plan에 실제 작업·위험·기존 검증과 연결된 방식·이유·기대 출처가 있는가. non-TDD만으로 새 승인을 요구하지 않는가 |
| 방법 적용 | 선택한 동작별 순서와 실제 실행이 일치하는가. TDD 부분만 의미 있는 RED를 평가하고, 나머지는 독립 기대·확인 시점·회귀 근거를 평가 |
| 새·기존 검증 | 기존 시험 통과만으로 새 계약 완료를 주장하지 않는가. 실제 명령의 rc·출력·판을 보존하고 실패/미실행/사후 재생을 구별하는가 |
| 문서와 인계 | 다문서 설계·현재 수락판·PR 경계가 연결되는가. D7 업무 요청만으로 영향 spec/plan을 다음 의존 구현 전에 갱신하고 관련 구현 커밋에 포함하는가 |
| 리뷰 | 선택한 판의 스킬 본문과 verifier를 실제 사용·대기하는가. 비TDD를 부당하게 감점하거나 구현과 같은 잘못된 기대를 승인하지 않는가 |
| 제품·통합·인도 | 전체 관련 회귀와 최신 통합판·새 디렉터리·동일 소스의 공개 전환을 확인하는가. 미실행 운영을 완료로 부르지 않는가 |

HUMAN은 실제 공개 도구 사건과 산출물·독립 제품 확인으로 판정한다. 중요한 실패는 복구 뒤에도 최초
실패로 남긴다. 변경된 선택·실행·리뷰 연결과 전체 인계를 평가하되, 고정 원문·역할·양식의 재평가를
