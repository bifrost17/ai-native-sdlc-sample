## 발견과 선택

[0030](0030-optional-sonnet.md)은 후속 JSON의 spec→plan→구현→시험·같은 커밋을 지켰다. 그러나
최신 변경 뒤 독립 검토를 두 번 누락했고 sdlc-feedback 본문은 한 번도 로드하지 않았다. 팀 패키지는
설명으로 스킬 사용을 판단한다고 안내하지만 **채택한 팀의 프로젝트 진입 지침에 연결하는 예시가 없다**.
이는 호출 실패의 유일한 원인이라는 주장이 아니라 작게 보완·확인할 수 있는 전달 공백이다.

북극성 V4-11은 구현에서 벗어난 plan을 같은 커밋에 갱신하며 동기화 hook은 고려 사항으로 둔다.
V7-08/09의 verifier 예시는 완료 전에 실제 동작을 확인해 보고하고 수정·승인을 맡지 않는다.
0030의 좋은 문서 동기화는 유지하고 이 이벤트 연결만 명확히 한다. 기록 오판마다 새 규칙을 추가하거나
검토자 오류를 없애려고 시도하지 않는다.

## 변경 범위와 리뷰

- 선택형 팀 패키지에 **명시적으로 채택한 팀만** 제품 CLAUDE.md에 넣을 짧은 안내 예시를 제공한다.
  계획 구현/실질 변경에서 sdlc-feedback의 관련 절을 읽고 완료 전에 최신 범위를 검토한다는 연결이다.
  현황 질문·단순 산문 수정에는 실행하지 않으며 기존 동등 검토를 중복 실행하지 않는다.
- Claude/OpenCode 설치 안내에서 이 선택 예시와 실제 이름/경로를 연결한다. 순수 `project/`에는
  특정 팀 스킬 이름·활성 파일을 넣지 않는다. 기존 스킬 본문과 verifier 기준·TDD 선택 정책도 유지한다.
- 패키지/marketplace 판을0.1.3으로 맞추고 완결 복사·strict validation·OpenCode patch 적용을 확인한다.
  새 훅·프로그램·의미 검사·상태 양식·사전 승인 단계·모델 상향은 만들지 않는다.
- root가 작성하고 Sol high 독립 리뷰가 범위·설치 연결·실험 교란을 확인한다. 정적 검증 후 실제
  developer는 Sonnet/medium, 실험 사본의 native도 Sonnet/medium을 유지한다.
