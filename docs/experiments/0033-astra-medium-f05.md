추가보다 상태 저장·동시 변경·여러 소비자의 통합을 다루되 사내 로컬 시제품 범위로 제한한다.

## 실행 조건

- 소스: `8813277c4b0f20008f40d503be75fd3587d52c54`, `tdd-optional`, 팀0.1.4.
- 개발: **Codex CLI0.153.4 · gpt-6-astra · medium**. 요청 모델/추론을 다른 모델로 대체하지 않는다.
- 독립 검토: 설치된 기준을 읽는 fresh native `gpt-5.6-sol/high`. named custom-agent 자동 선택은
  0032에서 미검증이므로 실제 파일 읽기와 별도 문맥·보고·대기를 관측한다. 구현 하위 작업의 모델은
  난도와 사용자 범위에 맞게 정하고 기록한다. 하위 작업 사용 자체는 합격 조건이 아니다.
- Codex root가 [HUMAN 페르소나](PERSONA.md)의 제품 오너·엔지니어·통합 담당을 맡는다.
  실제 질문·제출·실패에 반응하며 고정 후속 대본을 쓰지 않는다. 실제 조직의 출시 승인은 아니다.
- 프로젝트별16개 스킬을 전체 폴더로 설치한다. 전역 스킬/config/메모리는 실행에서 제외하고
  전역 설치는 변경하지 않는다. 진입 AGENTS는 공통 CLAUDE와 채택한 feedback 절차만 연결한다.
- workspace-write/never를 유지한다. Git은 HUMAN이 수행한다. loopback HTTP 실행이 sandbox에서
  제한되면 필요한 실제 검증을 HUMAN이 수행해 결과를 전달하고, AGENT의 직접 실행과 구별한다.
  허용된 임시 Python cache를 사용한다. 막힌 동작을 우회하거나 임의로 권한을 확대하지 않는다.

원자적 실패·반복 거부, 낡은 version의 충돌과 두 경쟁 요청, 필터·CSV 일치, 기본 OFF/개발 ON/다시
OFF와 기존 JSON CLI의 독립성을 확인한다. 웹 UI·로그인·외부 연동·실제 배포·부하 보장은 범위 밖이다.

원본 v7 manifest의 template SHA는 이전0027 필수형 실험의 역사적 값이다. 이번에는 공개 데이터와
HUMAN 결정만 재사용하고 **선택형0.1.4**를 별도 export한다. `human.json`의 test-first 평가 문구도
자동 필수 조건으로 승계하지 않는다. AGENT가 선택한 작업에만 TDD 순서를 평가하고, 다른 방식은
독립 기대·동작별 검증·회귀 근거로 평가한다.

순수 사용판 `220342646f7dc799f0a78d4314544ddd85e0e367`에서 설치·공개 baseline seed
`dcc6663a266cda8c342d609a5f715bda84507c5a`를 만들었다. 기준 CLI3시험을 확인했고 maker/옛 제품
정답의 Git 객체와 HUMAN 자료는 복사하지 않았다. 새 제품은 독립 clone이다.

## 진행과 예산

1. 새 S1에서 질문과 의도·요구/설계·계획을 작성한다. HUMAN이 실제 파일을 읽고 각 문서 집합의
   커밋과 수락 이유를 기록한다. 미정 조직 정책을 발명하지 않고 중요한 계약을 대화로 정한다.
2. 수락된 문서·SHA·공개 코드만 새 S2에 인계한다. S1 대화·HUMAN oracle·과거 제품 정답은 전달하지
   않는다. 현재 stage와 수락을 추측하지 않도록 실제 인계 자료를 준다.
3. 계획에서3~4개 구현 PR 정도의 경계와 통합 순서를 정한다. 의존성과 검증이 이해되는 묶음이면
   실제 개수는 AGENT 제안을 검토해 수락한다. 각 PR은 최신 main에서 분기하고 HUMAN이 실제 리뷰·
   로컬 merge를 수행한다. 분할마다 동작·공개 경계와 기존 회귀를 확인한다.
4. 첫 HTTP 변경 구현·시험을 읽고 원본 SHA/diff를 고정한 뒤 작은 후속 업무 변경을 처음 공개한다.
   문서명·스킬명·갱신 순서를 prompt에 덧붙이지 않는다. 영향 spec 정본/intent/plan 갱신과 다음
   의존 검증/구현 순서, 같은 커밋을 공개 사건으로 확인한다.
5. 같은 합성 DB의 후속 동작, 전체 기존·신규 회귀, 동시 두 쓰기, CSV/API 일치, 같은 소스의 공개
   전환과 통합판 새 복제본의 인도를 확인한다. 결과가 충분하면 추가 전체 반복 없이 종료한다.

첫 개발 CLI부터90분 또는 root CLI16회 중 먼저 도달할 때까지, 개별 호출은 최대15분이다.
native 대기도 이 시간에 포함한다. 60분에 남은 범위와 자원 소비를 재점검한다. 준비용 하위 에이전트는
설치/기록 helper와 HUMAN 관측기 검토만 맡으며 제품 AGENT 실행으로 세지 않는다.
정상적인 사람 리뷰·수정 대화는 같은 실행의 일부다. 원본 실패는 보존하고 결과가 나올 때까지 반복하거나
개발 모델/추론을 몰래 바꾸지 않는다. 중요한 방법론 결함이 반복될 때만 최소 보완을 별도로 판단하며,
새로운 승인/의미 검사기를 추가하지 않는다. 예산 내 미완료는 미완료로 남긴다.
