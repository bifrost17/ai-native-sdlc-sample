2026-09-12. 개선점을 찾기 위한 관측 비교다. 가장 가까운 대조는 같은 F04 업무 데이터와 개발 모델
Muse Spark 1.3/xhigh를 사용한 [0026 A/B](../0026-muse-spark.md)다. 더 큰 F05의
[0027](../0027-muse-larger.md), 리뷰 수정 부분 사례인 [0028](../0028-review-tdd.md)은 보조 근거다.

앞선 필수형 계열은 분리 전 0.1.5/0.1.6/0.1.7이며 **현행 tdd-first 0.1.8의 새 실행이 아니다**.
0029는 선택형 0.1.1에서 시작해 0.1.2로 보완했다. 제품 양식·팀 지침·사람의 개입·문맥도 달라졌으므로
테스트 작성 순서만 바꾼 실험이 아니다. native 모델은 실제 Muse로 확인했지만 child variant는 default/
미표기였으므로 xhigh는 설정 근거와 실제 metadata의 한계를 구분한다.

## 이번에 적용한 것

선택형 0.1.2는 문서 선행 갱신을 제품 CLAUDE에 드러내고 두 verifier에 시간 순서의 증거 한계를
연결했다. 원래 있던 규칙을 보강한 것이며 새 승인·새 스킬·필수 기록 양식·의미 검사기는 만들지 않았다.
공통 HUMAN 페르소나의 일괄 RED 평가도 판과 선택 방식에 맞게 고쳤다. 과거 데이터 원문은 유지했다.

PR 경계·실행 기록·잘못된 검토 의견은 실제 HUMAN 대화에서 복구했다. 실수마다 정책 문장을 늘리지
않았으며, 이번 소스 보완 대상은 선택형이다. 공통 발견을 현행 필수형의 재시험 완료나 적용 완료로
표시하지 않는다. 다음 필수형 점검 때도 같은 공통 관찰 축을 사용하면 회귀 여부를 비교할 수 있다.

## 결과를 해석할 때

- 0029 원실행은 **6개 개발 호출**, 부분 재시험·기록 정정은 **2개 호출**. 합계8회, 약40분.
  0026 A/B의 9회/10회와 직접 속도 비교하지 않는다. 0029는 D1–D6을 처음부터 설명해 질문·수락
  조건이 다르고 부분 재시험도 새 문맥·명시한 non-TDD·새 지침이라는 여러 차이가 있다.
- 원실행 최종20시험, 보완 부분26시험과 각각 새 디렉터리55명령/9추가 판정이 통과했다. 이 수를
  0026의 13/31시험과 비교해 품질 순위를 매길 수 없다. 시험의 분할·묶음·관찰 수단이 다르다.
- 첫 전체 실행의 문서 순서 실패와 재시험의 검토 오판은 그대로 보존한다. 최초 방법 선택의 정확도,
  TDD 우월성, 선택형 우월성, 보완 문구 하나의 인과 효과나 일반 성공률은 입증하지 않는다.
- 전체 0.1.2 사슬을 새로 수행한 것은 아니다. 변경된 진입/검토 연결과 명시한 비TDD 부분을 새 세션으로
  확인하고 기존 전체 제품의 회귀·인도를 다시 평가했다. 자연스러운 비TDD 선택·UI 탐색·실제 운영은 미관측이다.
