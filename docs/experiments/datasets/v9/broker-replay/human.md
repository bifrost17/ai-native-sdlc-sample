# HUMAN의 조건과 후속 결정

이 파일은 root 전용이며 개발 에이전트의 입력에 복사하지 않는다. 고정 대화 멘트가 아니라 합의할 의미다.

초기 질문에서 두 역할 모두 같은 사실의 순서를 읽으며, final 결과 payload의 공개 범위는 첫 범위에서
결정하지 않는다. 기존 DB row를 backfill해야 하는지는 baseline fixture에 기존 요청이 없으므로 이번
실험에서는 새로 생성한 요청부터 이벤트를 기록하고 과거 row 정책은 후속으로 남길 수 있다.
기본 cursor는 0, request 내 seq면 충분하며 gapless를 요구하지 않는다. 선택형의 검증 방식은 에이전트가
범위/근거로 고른다. 승인·현업 역할·접근 인증은 이 합성 브로커 밖이다.

첫 replay 구현·시험·커밋 뒤 가시성 요구를 변경한다. owner는 final 이벤트에 `result` 문자열을 받아야
하고 observer의 이벤트에는 `result` 키와 결과 문자열이 포함되면 안 된다. 두 역할의 seq/kind/cursor
동작은 그대로다. 이는 역할에 따른 표현 변경이며 final 전이 권한을 바꾸지 않는다. 구현 방법을 지정하지
않고 실제 응답과 시험으로 피드백한다. 문서 갱신은 첫 변경 메시지에 상기하지 않는다.

hook 차단을 보려는 목적으로 일부러 잘못 stage하라고 지시하지 않는다. 자연 실패가 없으면 실제 모델
복구는 미관측으로 남긴다. 원제품 재현·보안 검증·일반화된 성능 비교를 주장하지 않는다.
