# 0034 북극성 기반 문서 보완·부분 재검증

Status: planned

## 목표와 범위

[북극성](../../../verification/north-star-playbook.html)의 L3 설계 이해, L4 대화 없는 인계와 실제 피드백에 따른
문서 갱신을 개선한다. 0033 문서 검토에서 핵심 설계는 충분했으므로 기존 안내·표현을 보완한다.
완벽한 제어가 아니라 대체로 잘 따르는 수준을 목표로 한다. 새 검사기·승인 단계·상태 장부는 만들지 않는다.
0033 제품 구현의 잔여 전용 시험·PR3 수락·D7·최종 인도는 이번 범위에 포함하지 않는다.

## 소스 변경

- 두 판의 작성 안내에서 기존 M01 컴포넌트·배포·경합 시퀀스와 W01 사용자 흐름을 직접 연결한다.
- 계약이 문장으로 충분해도 여러 경계와 대표 흐름 이해에 도움이 되면 도식을 선택하도록 짧게 보완한다.
  F05 교육 패키지를 복제하거나 클래스 다이어그램·그림 개수를 일반 의무로 만들지 않는다.
- 기존 sdlc-feedback에 후속 시험·검토 결과가 남은 작업을 바꿀 때 현재 plan·인계를 갱신하고 실제 시험 판과
  기존 근거를 연결하도록 명시한다. 과거 기록·작성 주체를 보존하며 시험 통과와 수락·통합·완료를 구별한다.
- 기본형0.1.9·선택형0.1.5로 패키지·판별/루트 카탈로그·현행 설치 안내를 일치시킨다. 역사적 버전은 보존한다.

## 리뷰와 실행 순서

1. root가 변경한다. Astra/high가 북극성·문서 의미를, Sol/medium이 두 판의 차이·패키지·설치를 검토한다.
2. 0033 보존 제품 `3ae564a1e6b8d2d4706d74456de731c76b351e68`에서 별도 제품 저장소와
   `codex/0034-doc-r01`을 파생한다. 후보 소스·설치판·원본 입력·해시·브랜치를 기록한다.
3. 선택형 자산·스킬을 프로젝트 안에 설치하고 Codex CLI Astra/medium을 문서 작성자로 실행한다.
   root는 HUMAN 역할로 기존 설계의 동료 인계용 정리를 요청하고 실제 제출에 피드백한다.
   design-spec·plan·sdlc-feedback은 명시 사용한다. 자연적인 스킬 선택의 증거로 세지 않는다.
4. F05 기존 설계에 컴포넌트 그림과 변경 시퀀스 각 한 장을 추가한다. JSON CLI 독립성, 공통 서비스/저장소,
   버전 검사·no-op·커밋·응답 순서를 기존 이름·계약에서 도출한다. ON일 때 `/requests/`는
   `404 route_not_found`, `/requests/%20`은 `400 invalid_input`임을 명료하게 예시한다.
   후속 E18의 동일26파일·77시험·216관찰을 현재 plan·결정 기록에 연결하고 남은 작업을 구분한다.
5. 앞선 대화·정답표 없이 개정 문서·선언 참조·기존 baseline만 주는 새 Sol/high 독자를 실행한다.
   구조·변경 순서·오류 판정·현재 완료 범위·다음 작업을 설명하게 한다. 새 제품 구현을 역으로 읽히지 않는다.
6. root가 판정한다. 기본 한 회, 중요한 누락이면 최소 수정 후 새 브랜치에서 한 회만 추가한다.
   제품 실험의 Codex CLI 호출은 첫 실행부터 합계30분·최대6호출이며 호출당 최대480초다.
   준비/제작용 리뷰와 실제 제품 실험 시간을 구분한다. 시간 초과나 미완료를 통과로 바꾸지 않는다.

## 통과 조건

- 도식·문장·OpenAPI·DDL의 이름과 계약이 일치한다. 새 제품 동작·미확인 결정을 추가하지 않는다.
- 새 독자가 버전 검사 우선, no-op 경합, 커밋 후 응답 손실, 기본 OFF, 두 경계 URL과
  PR3의 실제 남은 작업을 문서로 정확히 설명한다.
- E18을 지금 받은 사실과 개발자가 당시 받지 못했던 사실을 구분한다. 확보한 결과를 다시 기다리지 않고
  전용 경합·실패 시험과 PR3 수락이 남았음을 이해한다.
- 양 판의 기존 test-first/검증 방식 선택 차이를 유지하고 F01에 불필요한 도식을 요구하지 않는다.
- `make check`, 패키지 strict 검증, 버전 일치, 선택형 Codex patch와 설치 해시를 확인한다.
  F05 기존 경계 URL 시험을 실행하고 두 Mermaid 도식을 기존 렌더 방식으로 시각 확인한다.

사소한 표현·스타일 차이는 반복 사유가 아니다. 고정 가이드라인 전체의 반복 채점은 생략하되
변경에 영향받는 작성·검증 전략·문서 갱신·상태·설치의 회귀를 함께 본다.

## 보존과 반영

계획·이유·원본 입력·프롬프트·응답·리뷰·명령 결과·한계·Git 판을 0034 기록에 남긴다.
원0033 커밋·평가 입력을 수정하지 않는다. 제품은 별도 브랜치로 보존하고 제작용 개선은 main에 반영한다.
북극성 주석에는 문서 표현과 후속 근거 인계를 확인한 범위만 추가하며 기존 실패·부분 판정을 유지한다.
이번 결과를 전체 SDLC·D7·두 판의 실제 제품 개발 통과로 확대하지 않는다.
