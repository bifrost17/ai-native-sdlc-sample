## 왜 하나도 채택하지 않았나
「이미 있고 사람들이 쓰는 스킬을 찾는 것」이 첫 번째 목표였고, 18건을 열어 봤지만
**그대로 넣어서 나아지는 파일이 없었다.** 형식 문제가 아니다 — 18건 모두 Agent Skill 형식
(frontmatter `name`+`description`)을 충족한다. 갈린 것은 내용이고, 이유는 셋으로 모인다.

1. **보존 기간이 정면으로 충돌한다.** C6 은 3년인데, **18건 중 3년을 말하는 파일이 하나도 없다.**
   대신 6년(HIPAA 계열 2건) · 12~24개월 · 1년 · 6개월 · 2년 · 26개월이 각각 「법적 요구」라는 단정과 함께
   들어온다. 게다가 GDPR 계열 4건은 삭제권·TTL·익명화를 규범으로 밀어, 3년 보존해야 할 이력에
   삭제 경로를 붙이게 만든다. 섞을수록 C6 의 숫자가 흐려지는 구조다.
2. **거래성 통지에서 결론이 반대로 난다.** 이메일/SMS 스킬은 사실상 전부 마케팅 스킬이다.
   `email-compliance`·`sms` 는 「거래성 메시지는 별도 동의가 필요 없다」고 명시적으로 가르치는데,
   청구 상태 통지가 정확히 그 범주라 **C4 가 막으려는 실패를 스킬이 권하게 된다.**
   4건은 모든 메시지에 구독 해지/STOP 을, 2건은 본문 개인화·미리보기를 요구해 C5 를 깬다.
3. **C7 을 덮는 스킬이 세상에 없다.** 「제3자가 고객 **대신** 조회한다」는 자리가 공개 생태계에 없다.
   가장 가까운 둘도 대상이 정보주체 **본인**(DSAR)이지 대리인이 아니고, `gdpr-compliant` 는 오히려
   소유자 불일치를 403 으로 막아 **대리 조회 경로 자체를 부정한다** — 이 서비스의 정상 경로인데도.

여기에 한국 사정이 겹친다. **18건 중 한국을 언급한 파일은 0건**이고, PII 정규식은 전부 미국 포맷
(SSN · 5자리 zip · `phone_us`)이라 **주민등록번호·한국 연락처·계좌번호를 하나도 잡지 못하면서**
「스크러빙 완료」라는 거짓 안전감을 준다. 별 수가 높은 것이 좋은 후보도 아니었다 —
상위 3개 레포(★255145 · ★93214 · ★49240)는 모두 기각이고, 값어치 있던 도너 둘은 ★11 과 ★146 이다.

**그래서 설계했다.** 다만 좋은 점은 가져왔다 — 어디서 무엇을 가져왔고 왜 그대로 쓰지 않았는지는
각 스킬의 `PROVENANCE.md` 에 후보별로 적었다. 보류 4건(`pii-scrubber` · `audit-logging` ·
`consent-record-keeping` · `data-privacy-compliance`)은 **도너로만** 보관한다.

## 왜 하나가 아니라 둘인가
정책이 다루는 자리가 둘이고 어휘가 다르다 — **데이터·로그·이력**(spec·엔드포인트·쿼리·로깅)과
**고객에게 보내는 메시지**(문구·채널·동의). 하나로 묶으면 통지 카피를 쓰는 과제에서 응답 필드 규칙이
같이 떠서 소음이 되고, 반대로 트리거 문장이 넓어져 어느 쪽도 정확히 걸리지 않을 위험이 있다.
나눈 대신 **경계를 본문에 못박았다** — C6 의 문면은 data 쪽에만 두고 notice 쪽은 가리키기만 한다.
셋 이상으로 더 쪼개지 않은 것은, C1~C3·C6~C7 이 같은 과제(엔드포인트 하나를 만드는 일)에서
함께 필요하기 때문이다.

## 어떻게 찾았나
웹 검색 17 질의(`claude skill PII redaction SKILL.md`, `agent skills privacy compliance`,
`SKILL.md consent notification email SMS`, `claude code skill audit trail "who what when" retention`,
`SKILL.md "data minimization" API response allowlist fields` 등) + `gh search code --filename SKILL.md`
(`PII` · `GDPR` 축) + 후보 레포 직접 열람. 18건 전부 파일을 열어서 판정했고, 사본과 메타데이터
(라이선스·blob sha·갱신일·별/포크)는 `raw/` 에 원문 그대로 있다.

정독은 셋으로 나눠(PII 축 6건 · 동의·통지 축 6건 · 감사·접근 축 5+1건) 조항별 **축자 인용**을 받은 뒤
판정은 내가 했다. 인용이 붙지 않은 「덮음/부분」은 「—」로 내렸다.

## 남는 구멍
- **플러그인 배치로는 시험하지 않았다.** 6/6 과 집합 1회는 모두 `.claude/skills/` 직접 배치다.
  S8 이 실측한 접두(`/intent-sdlc-skills:<name>`)·이름 충돌 규칙은 반영했지만,
  **플러그인으로 로드했을 때도 같은 결과인지는 확인 못 함.**
- **스킬은 권고적 통제다**(L6: "A skill is a control, though an advisory one"). C1·C3·C4 는
  어기면 되돌릴 수 없는 조항인데(내보낸 값·보낸 문자는 회수가 안 된다) **뒤를 받치는 결정적 장치가 없다.**
  플레이북은 훅이나 PR 리뷰 패스를 그 자리에 둔다. 이 레인은 스킬만 만들었다 — 훅·리뷰 패스는
  다른 레인(S7 · S8)과 조직의 몫이고, 그 전까지 C1·C3·C4 는 「드물게」 어겨질 뿐 「거의 불가능하게」는 아니다.
- **트리거 편차를 재지 않았다.** 문구마다 1회씩이고, 같은 문구를 반복했을 때의 흔들림은 확인 못 함.
- **정본이 서명 전이다.** v0 draft 라 조항 문면이 바뀔 수 있고, 바뀌면 두 스킬의 인용 블록과
  `coverage.md` 를 함께 고쳐야 한다.
- **한국 식별자 포맷을 스킬이 직접 주지 않는다.** 주민등록번호·계좌번호의 마스킹 자릿수는
  「뒤 4자리 등」이라는 정본의 예시를 그대로 옮겼을 뿐, 형식별 규칙표를 만들지 않았다 —
  그건 정책이 정할 일이지 스킬이 지어낼 것이 아니다(아래 질문 1).

## 정책 오너에게 묻는다
스킬이 답을 지어내지 않고 **정본에 없어서 비워 둔** 자리들이다. 답이 오면 해당 조항과 두 스킬을 함께 고친다.

1. **C1 — 마스킹 자릿수를 식별자별로 고정하는가?** 정본은 "마스킹(뒤 4자리 등)"이라 예시만 든다.
   주민등록번호는 뒤 4자리를 남기면 생년월일·성별이 이미 앞자리에 있어 사실상 식별되는데,
   앞자리도 가려야 하는가? 계좌번호·연락처는 각각 몇 자리인가?
2. **C1 × C4 — 발송에 쓰는 연락처는 어디까지 「싣는 것」인가?** 통지를 보내려면 이메일·전화번호가
   발송 봉투에 쓰인다. 이 spec 은 「봉투에만 쓰고 본문·이력·로그에는 마스킹본조차 넣지 않는다」로
   기본값을 잡았는데(집합 시험 산출물 참조), 포털 화면에 "어디로 보냈는지"를 마스킹해 보여 주는 것은
   허용인가 금지인가?
3. **C5 — 지급 예정 「금액 자체」는 실을 수 있는가?** 정본은 "금액 산정 **근거**"를 뺐지만 금액 자체는
   말하지 않는다. 두 스킬의 기본값은 「애매하면 덜 싣는 쪽」이라 **미포함**이다.
   (시험용 intent 0011 의 열린 질문과 같은 것이고, 실제 과제에서 모델이 그대로 오너에게 넘겼다.)
4. **C5 — 보류·부지급 사유를 「화면」에는 보여도 되는가?** C5 는 통지에만 걸린다. 상담 콜의 큰 몫이
   보류 문의라면 사유 없는 "보류" 한 줄은 다시 전화를 부른다. 포털 화면의 기준이 필요하다.
5. **C6 — 3년의 기산점은 언제인가?** 이벤트 발생 시점인가, 청구 종결 시점인가.
   (후보 스킬들의 "3년"은 관계 종료 후 기산이라 우리와 다르다 — `coverage.md` 「가짜 친구」 참조.)
6. **C6 × 파기 요구 — 어느 쪽이 이기는가?** 고객이 개인정보 파기를 요구했을 때 3년 보존 의무가
   우선하는가? 정본에 예외 문장이 없다. **이 질문에 답이 없으면 스킬은 3년 보존을 그대로 지시하고,
   외부 GDPR 계열 스킬이 함께 로드되면 삭제와 보존이 부딪힌다**(후보 4건이 실제로 삭제를 지시한다).
7. **C7 — 「본인확인 기록」은 무엇이 자격을 갖추며 누가 발급하는가?** ARS·콜백·신분증 중 무엇인지,
   기록 ID 를 어느 시스템이 내주는지가 정해지지 않았다. 계약(기록이 있을 때만 조회, ID 병기)은
   C7 이 이미 고정하므로 구현은 이 답을 기다리지 않는다 — 발급처 하나만 열려 있다.
8. **C2 — 「근거 조항」은 무엇을 가리키는가?** 이 정책의 조항 ID(C1~C7)인가, 법령 조문인가,
   아니면 요구사항 번호인가. 외부 스킬을 함께 쓰면 GDPR 조문으로 오도될 여지가 있다.
