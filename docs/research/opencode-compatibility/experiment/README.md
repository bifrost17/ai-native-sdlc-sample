# OpenCode 템플릿 실험 설계

2026-09-12 · Status: proposed. **설계만 작성했다. 설치·준비 probe·제품 실험은 시작하지 않았다.**
이 문서는 HUMAN 운영용이며 진행 중인 AGENT checkout에 전달하지 않는다.

## 결정

**스킬을 최대한 제공하는 혼합 조건 A로 작은 개발건 전체 1회**를 진행한다.
OpenCode용 스킬 14개와 참고 파일 2개를 제공하고, 해당 업무에 필요한 자료를 에이전트가 선택하게 한다.
호환성 문제나 중요한 과정 실패가 남을 때만 직전 스냅샷에서 해당 구간을 부분 재시험한다.
파일 참조 조건 B는 설치/호출 경로의 대안이다. 두 조건의 전체 개발을 처음부터 두 번 돌리지 않는다.

목표는 [북극성](../../../verification/north-star-playbook.html)의 주요 개발 흐름이 사람과 함께
대체로 잘 동작하는지 확인하는 것이다. 모든 스킬 호출, 모든 UML, 모든 문단 재평가를 요구하지 않는다.
[스킬 제공 설계](skill-delivery.md), [평가·기록 설계](assessment.md)를 함께 읽는다.

## 개발건과 전달 자료

기존 Python 표준 라이브러리 CLI에 담당자별 조회와 상태 요약을 추가한다.
두 기능을 하나의 공개 단위로 취급하되 작은 두 PR 범위로 순차 개발한다.
첫 요약 구현이 실제로 나온 뒤 JSON 출력 요구를 추가한다.

AGENT에게 주는 제품 초기 입력은 다음 네 파일과 채택한 사용 템플릿·팀 자료다.

| 원본 | 제품 위치 |
|---|---|
| `datasets/v1/baseline/tracker.py` | `tracker.py` |
| `datasets/v1/baseline/test_tracker.py` | `tests/test_tracker.py` |
| `datasets/v6/F04-release-json/requests.json` | `requests.json` |
| `datasets/v6/F04-release-json/public.json` | `case.json` |

위 원본 경로는 `docs/experiments/` 기준이다. v1/v6 manifest의 해시로 복사 원본을 확인한다.
사용 설명은 기존 명령만 설명한 `USAGE.md`로 준비한다.
프로젝트 지침과 정책에는 실제 시험 명령 `python3 -m unittest discover -s tests -v`,
Python 표준 라이브러리, 로컬 합성 데이터, 별도 build/lint 없음과 실제 판단 주체만 채운다.
maker의 `make check`를 제품 시험 명령으로 복사하지 않는다.

`human.json`, oracle, 이전 실행 결과·대화, 이 설계와 평가표는 전달하지 않는다.
사용판에 원래 들어 있는 양식과 교육 예시는 제공하되, 완성 예시를 이번 제품의 intent/spec/plan으로
복사해 시작하지 않는다. 교육 예시가 있다는 사실은 기록하고 무예시 실험으로 표현하지 않는다.
출처 확인용 manifest는 허용하지만 maker 전체 연구에 연결해 답을 찾게 하지 않는다.

이 사용판의 작성 예시에는 F04와 같은 hana/R-101/R-103, 정확 일치·완료 포함·빈 결과 계약이 있다.
따라서 **예시를 포함한 실사용 조건**이며 D1을 완전 무힌트로 발굴한 실험이 아니다.
또 `plan/examples/two-pr-spec.md`는 목록부터 공개하고 두 줄로 요약하는 다른 업무 결정이다.
어떤 예시를 읽었는지 기록하고, 현재 HUMAN의 공동 공개·세 줄 요약 계약을 우선 적용하는지 본다.
설계 시 사용판 교육 경로에서 `--json`은 발견하지 못했다. 실행 준비에서 다시 확인해
미래 D7이 제품 자료나 온보딩에 들어가지 않도록 한다. 실제 사용판 예시를 몰래 제거하지 않는다.

## 브랜치와 기록의 분리

실행 승인을 받은 뒤 아래 구조를 만든다. **이름은 계획이며 아직 생성하지 않았다.**

```text
보존된 use-template-0024-r2 @ d4d2153
  └─ 별도 얕은 제품 clone: main → seed + 선택 스킬/설정 커밋
       ├─ codex/oc-f04-a-owner
       │    최초 intent → spec → plan 커밋/수락 → PR1 → main merge M1
       └─ M1에서 codex/oc-f04-a-summary
            PR2 첫 요약 → JSON 요구 변경 → 검토 → main merge M2

HUMAN 보존: codex/experiment-<실행일>-oc-f04-a-r01
필요할 때만: codex/experiment-<실행일>-oc-f04-b-partial-r01
```

제품 통합은 로컬 main이며 maker main과 다르다. 단계마다 별도 PR을 만들지 않는다.
문서 초기 작성은 각각 커밋·수락하되 첫 기능 PR 범위에 함께 보존할 수 있다.
같은 CLI와 담당자 선택 계약을 공유하므로 PR1→PR2 순차 진행이 적합하다.
순차 개발을 병렬 개발 검증으로 세지 않는다.

기본은 **로컬 PR 범위 리뷰와 merge commit**이다. GitHub PR 객체·댓글·push·CI는 이번 범위에 없다.
실제 hosted PR이 없는 `pr-loop`의 외부 업무는 미관측이다.
전체 완료 뒤 제품 HEAD, 두 작업 branch, 수락 SHA, merge SHA, 공개 대화·출력을 HUMAN 기록 refs에 보존한다.
제품 이력을 maker main으로 합치지 않는다. maker에는 설계와 후속 결과 색인만 둔다.

AGENT clone은 해당 use tree의 shallow 경계 뒤에서 새 이력을 쌓는다.
maker 부모·다른 ref·비공개 파일이 보이지 않는지 실행 준비 때 확인한다.
보존된 원본 전체 이력은 HUMAN 쪽에 유지한다.
단순 worktree·별도 디렉터리를 OS 보안 격리라고 부르지 않는다.
HUMAN 비공개 자료는 AGENT 작업 범위 밖에 두고, 유출되면 영향 구간을 오염으로 표시한다.

## 대화와 단계 운영

Codex root는 `HUMAN (simulated)`, OpenCode는 제품 문서·코드·시험을 작성하는 AGENT다.
HUMAN은 초기 입력을 준비하고 질문에 답하며 결과를 검토한다. 제품 정답 코드나 완성 문서는 대신 쓰지 않는다.
고정 대본·자동 후속 응답기는 만들지 않는다.

| 구간 | HUMAN과 AGENT의 행동 | 관측 지점 |
|---|---|---|
| 실행 전 준비 | 선택 자료·설정·실제 스킬 목록·모델을 확인. 공개 카드와 정책을 준비 | 본문 파싱과 실제 모델 사용은 구분 |
| 작성 세션 S1 | 공개 문제 제기 → 실제 질문에 사실/이유 답변 → intent, spec, plan을 각각 읽고 수락 | 없는 정책 창작, 불필요한 재승인, 구체 계약·PR/시험 계획 |
| 새 구현 세션 S2 | 작성 대화를 넘기지 않고 수락 문서·필수 연결 설계·현재 코드·수락 SHA만 인계 | 문서만으로 이어받는 정도. 부족하면 질문을 허용하고 공백 기록 |
| PR1 | 담당자 조회·개발 중 공개 제어를 선행 시험부터 구현, 검토하고 M1 통합 | 의미 있는 RED→GREEN, 기존 명령, 일반 OFF·개발 시험 가능 |
| PR2 첫 구현 | M1에서 요약 개발. 요약 출력이 나오면 마무리 전 업무 리뷰 | 최초 코드·시험 결과를 실제로 본 시점과 SHA/dirty diff 보존 |
| 업무 변경 D7 | 위 시점 뒤 내부 자동화용 JSON 요구를 처음 공개 | 영향 문서·계획·시험·커밋을 별도 상기 없이 갱신하는지 |
| 완료·인도 | AGENT 독립 검토와 HUMAN 리뷰, 보완 후 M2 통합·fresh directory 실행 | 전체 회귀, 같은 소스 OFF→ON→OFF, 다음 작업 인계 |

기본 요청은 공개 카드 내용과 “프로젝트 지침과 제공된 팀 자료 중 관련 내용을 활용해 진행한다”는
통상 온보딩이다. 설치/참고 자료의 위치는 알리지만 전문을 첫 프롬프트에 붙이지 않는다.
매 단계 특정 스킬·문서 갱신·누락 위치를 지시하지 않는다.
자료 위치를 알려 준 조건이므로 완전 무힌트 실험으로 표현하지 않는다.

D1–D6은 `human.json`의 공개 조건에 따라 실제 질문에 답하거나 잘못된 가정을 리뷰하며 구현 전에 합의한다.
D7은 첫 요약 코드와 시험이 나온 **뒤** “내부 자동화도 읽어야 하니 summary --json이 필요하다”는
업무 변화와 정확한 계약을 전달한다. 파일명·스킬명·문서 갱신 지시는 덧붙이지 않는다.
D7이 사전에 노출됐거나 처음부터 JSON까지 구현됐다면 ‘구현 중 변경’은 미관측으로 남긴다.
로그를 되돌려 RED나 변경 시점을 재연출하지 않는다.

수락은 실제 읽은 문서 SHA·판단 이유로 남긴다. 구현 중 개정 spec을 먼저 커밋해 수락한 경우도 허용한다.
plan은 구현 전에 갱신하고 해당 구현·시험과 같은 관련 커밋에 포함하는 현재 Git 정책을 평가한다.
중요한 intent 제약이나 연결 설계가 낡았는지도 본다. 영향 없는 문서까지 수정할 필요는 없다.

S1 내부와 S2 내부는 각각 같은 OpenCode session ID로 대화를 이어간다.
탐색·계획 논의는 OpenCode의 plan agent를 우선 사용한다. 문서 작성·커밋이 필요한 시점에는
이미 허용된 문서 범위로 전환/권한을 맞추고, 구현 시작 전까지 제품 코드·시험을 바꾸지 않는다.
실제 사용 mode와 전환을 기록하며 Claude의 plan mode 제약과 같다고 가정하지 않는다.
지원되는 `run --session <id>`와 JSON 출력 방식은 실행 준비에서 재확인한다.
S1→S2만 의도적인 새 문맥 인계다. 복구·모델 변경·압축은 이유와 전달 내용을 기록한다.
‘최근 세션’에 암묵적으로 이어 붙이지 않고 실제 ID와 cwd를 고정한다.
이는 [공식 CLI의 세션 이어가기](https://opencode.ai/docs/cli/)에 근거한 계획이며 이번에는 CLI를 호출하지 않았다.

독립 검증자는 새 문맥에서 현재 공개 합의·spec/plan·diff·시험을 보고 결과만 돌려준다.
AGENT가 호출하고 기다리는 흐름을 관측한다. 자기 검토를 독립 검토로 세지 않는다.
native 위임이 불가능하면 HUMAN이 별도 OpenCode 리뷰 세션으로 전달할 수 있으나,
수동 독립 검토로 표시하고 native 호출 성공을 주장하지 않는다.

## 예산과 재시험

이전 0024는 보완·재시험을 포함해 개발 호출 약 76.6분/14 HUMAN 턴이었다.
이번 제안은 **전체 1회, 60분/12턴에서 현황 점검, 준비·복구·부분 재시험 포함 90분 또는 16턴 중 먼저 도달하면 중단**이다.
한 번의 질문이나 짧은 답변을 토큰 절약 때문에 생략하거나, 시간 제한 때문에 완료로 판정하지 않는다.
개별 CLI 응답이 10분을 넘으면 진행·무한 반복 여부를 확인하고 필요한 경우 해당 실행만 중단한다.

개발 모델은 이미 연결된 제공자 중 Sonnet급 역량과 적정 추론을 기본으로 한다.
중요한 설계·합의 대조와 독립 검토에는 더 높은 역량/추론을 배치하되, 매 턴 최고 모델을 쓰지 않는다.
실제 provider/model ID·variant 지원은 실행 전 확정한다. 지원하지 않는 이름을 추정해 넣지 않는다.
비용은 실제 사용량/가격 근거가 있을 때 기록하고, 없으면 unknown이다.
이번 설계는 유료 계정 신규 연결이나 비용 자동 충전 권한을 만들지 않는다.

재시험은 다음 순서로 제한한다.

1. 파일 부재·오류 설정 등 시작 전 준비 실패는 수정하고 같은 조건의 새 제품 세션을 시작한다.
   실패·수정 내역을 남기며 이를 제품 행동 실패나 성공으로 세지 않는다.
2. 실행 중 중요한 누락을 발견하면 먼저 원 결과와 개입 시점을 보존하고 정상 HUMAN 리뷰로 복구한다.
   최초 자발적 누락은 그대로 남긴다.
3. 원인 확인이 필요한 경우에만 해당 이벤트 직전 스냅샷에서 새 세션으로 **부분 재시험 1회**를 한다.
   native 경로 문제라면 B로, 지침 문제라면 작은 수정의 새 판으로 고정한다.
   모델과 전달 방식 등을 함께 바꾸면 원인 하나의 효과로 해석하지 않는다.
4. 관련 없는 실패나 표현 정정만으로 전체를 다시 실행하지 않는다.
   같은 차단이 두 번 반복돼 진전이 없거나 예산에 도달하면 실패/미관측/예산 중단으로 마감한다.

B에 A의 이후 발견·정답·보완 내용을 몰래 인계하지 않는다.
동일한 직전 코드·문서·공개 합의와 해당 이벤트 입력을 사용한다.
재시험으로 이어받은 뒤 나머지 개발을 완료해도 전체 결과는 조건 전환을 포함한 실행으로 기록한다.

## 산출물과 현재 상태

후속 실행 때 설치 원본·변환 내역·설치/갱신/제거 안내, 노출 목록, 환경 판,
공개 대화·도구 결과·Git 이력, 평가표와 비용/시간을 보존한다.
