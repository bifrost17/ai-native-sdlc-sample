# 독립 설계 리뷰와 반영

2026-09-12. reviewer: `opencode_experiment_review`, gpt-6-astra/xhigh.
작업 난도에 맞춰 설계·실험 타당성을 독립 검토했다. 문서·Git 조회만 했으며
스킬 설치, OpenCode 호출, 실험 branch 생성, 제품 구현은 하지 않았다.

## 1차 검토

대상은 기존 실험 운영·페르소나·F04/v6·0024 결과·OpenCode 호환성 검토와 부모가 제안한
native 14개/파일 2개·전체 1회/필요한 부분 재시험 구조다.

1. 최소 전체 흐름은 작성과 수락, 새 구현 세션 인계, PR1/PR2 순차 통합,
   PR2 첫 코드·시험 뒤 JSON 공개, 독립 검토와 fresh-directory 인도를 유지해야 한다.
2. 제공·발견, native 호출, 파일 본문 읽기, 산출물 적용, 자연 이벤트 선택, 지적 후 복구를 나눈다.
   A의 성공한 직접 Read도 적용 증거다. B는 직전 동일 스냅샷에서 새 세션으로 시작한다.
3. 사용판 예시에 F04와 같은 행·담당자·정확 일치·완료 포함·빈 결과가 있다.
   두 PR 예시는 목록 우선 공개와 두 줄 요약으로 이번 업무 결정과 다르다.
   예시 포함 실사용 조건임을 명시하고 현재 합의의 우선 적용과 실제 읽기를 관측한다.
   검색한 예시에서는 JSON 후속 계약을 찾지 못했다.
4. HUMAN의 원본·실패·재시험 이력 보존과 AGENT의 maker 이력 미노출을 구분한다.
   v6의 frozen manifest를 덮어쓰지 않고 d4d2153 기준 변경을 실행 기록에 남긴다.
5. 플랫폼 변경으로 지침 전달·권한·hook·검증자 실행은 새 관측 대상이다.
   문구가 같아도 과거 실행 성공을 자동 승계하지 않는다. 운영·UI 등은 미관측이다.
6. Codex는 HUMAN이며 정답을 대신 구현하지 않는다.
   native 검증이 불가능하면 별도 OpenCode 리뷰 세션으로 수동 독립 검토할 수 있지만
   자기 검토나 자동 위임 성공으로 바꾸어 기록하지 않는다.
7. 90분/16 HUMAN 턴 및 부분 재시험 최대 1회를 A+B 전체에 적용한다.
   과거 Claude 비용을 이번 예상 비용으로 사용하지 않는다.

부모는 위 내용을 설계 본문에 반영했다. 실제 use-template-0024-r2의 해당 예시를
Git으로 조회해 D1 중첩과 두 줄 요약/목록 우선 공개를 대조했다.
`examples/`와 `docs/sdlc-authoring/`에서 `--json` 검색 결과는 없었다.
이것은 자료 검토이며 제품 실험 결과가 아니다.

## 2차 문서 검토

대상: [실험 설계](README.md), [스킬 전달](skill-delivery.md), [평가·기록](assessment.md).

검토자는 합의한 방향이 반영됐다고 판단했고 중요한 수정 한 건을 요청했다.

> “PR마다 노출 코드를 고침”은 정상적인 PR2 공개 제어 구현까지 실패로 읽힙니다.
> “완성된 같은 HEAD의 OFF→ON→OFF 전환에 소스 수정이 필요함”으로 좁히면 의도와 맞습니다.

부모가 해당 평가 문구를 수정했다. 기능을 구현하면서 공개 제어 코드를 추가하는 정상 작업과
완성된 기능의 켜기/끄기에 소스 수정이 필요한 문제를 구분했다.

검토자가 확인한 실행 전 미정:

- 실제 OpenCode 판·provider/model/variant, 세션 재개·출력 수집 인자.
- 최종 어댑터·동반 자원·검증자 권한과 판.
- 전역 노출 및 B의 native 중복 제거 가능 여부.
- 실행일·준비 시작점·seed/설정 커밋·실제 기록 위치.

이는 실행 전 준비에서 확정할 값이다. 설계에서 확인하지 않은 설치·실행 성공을 선반영하지 않는다.
교육 예시 한계와 위 문구 수정 외에 다시 설계할 중요한 누락은 없다는 리뷰를 받았다.
