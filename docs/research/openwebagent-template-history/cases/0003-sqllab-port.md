# 0003 SQL Lab 이식 — 원본 대조와 늦은 제품 마운트의 긴장

판정: **중요 사건을 중심으로 한 심층 검토 완료, 일부 원본 실행 증거 제한**. 수집한 `bifrost17/openwebagent` bare Git `main@a08295f2f7f492efd3ef4787c4ed3d1a1d8f118e`, 문서의 도입 커밋과 변경 이력, PR API 및 첫 부모 머지를 대조했다. 원본 Superset `e7c42dd`의 모든 파일·캡처·시험 로그를 이 조사에서 재실행/전수 대조하지 않았고, 사용자의 대화 원문과 작업 OS·모델 실행 로그도 미확인이다.

H1은 **부분 지지**: 실제 선행 결정 Q3와 충돌한 링킹 설계, 누락된 원본 시험·시각/실행 의미는 설계/검증 결함이다. 다만 137개 결정 중 뒤의 신규 기능·정책 변경을 초기 실패로 합산하지 않는다. H2는 **지지**: 참고 캡처·HTML 목업이 있어도 실제 다크/라이트·좁은 폭·빈 상태가 #327/#328에서 깨졌다. 심미성 최종 수락은 사람 원본 평가 없이는 미확인. H3는 **강한 지지**: 중간 PR의 백엔드/부품은 있었지만 전 사용자 실행 흐름이 H까지 없고 Run·권한·API/CORS 결합이 막혔다. H4는 **부분 지지**: 원본 시험·AC·계획 검증법은 구체적이었으나 장부 추출기 자체가 빠뜨린 항목과 늦은 실제 브라우저 검증이 큰 공백이었다.

현재 0.1.8 정본은 선행 공유 계약, 최신 결합판 검증, UI 실제 관찰, 독립 기대를 이미 지시한다([기준 비교](../baseline.md)). 이 사례에서 남는 후보는 **대규모 이식의 첫 공개 전 대표 수직 흐름을 어디서 최소 비용으로 실제 마운트해 볼지**에 관한 얇은 판단 예시이며, 전 모듈 선행 확정이나 새 형식 gate를 근거 없이 강제하지 않는다. 원인 귀속은 템플릿보다 프로젝트의 원본 이식/출시 분할, 에이전트의 코드·계약 오독, 검증 계기/환경의 한계가 우선이다. GitHub formal review API가 비었다고 기록된 새 문맥 검토가 없었다고 판단하지 않는다.
