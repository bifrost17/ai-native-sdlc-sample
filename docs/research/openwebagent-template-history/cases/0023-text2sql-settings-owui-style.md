여섯 축: **의도 보존**은 OWUI 입력·버튼·탭과 저장 피드백에 대응하지만 FR11·FR17–20은 측정/사용자 결정으로 범위가 늘었다. **설계 충실성**은 원본 OWUI 클래스 대조 가드와 화면 코드를 통해 정적으로 확인되며 픽셀 동일성은 미판정이다. **계획 실행 가능성**은 구체적인 T01–T09·AC와 스텁 사용성 절차가 높지만 첫 문서의 사전성은 불명이다. **PR 분할**은 0025와 공통 파일·프레임 연동 때문에 한 PR이 합리적이나 검토 집계는 공통 1건이다. **변경 피드백**은 첫 AFTER 악화를 계량해 FR13으로 되돌리고 리뷰 발견을 고쳤다. **검증·보고**는 169파일 1925시험, 전체 649파일 중 기존 9실패, 브라우저 전후 지표를 PR/plan이 보고한다. 이번 조사에서 그 명령·rc를 재실행하지 않았다. 정적 문자열·SSR만으로 클릭 동작 전체를 증명하지 않는다고 PR도 제한한다.

사용자 가설: H1(설계 부족→변경)은 **부분 지지**다. 초기 시각 설계가 열 밀도·실제 스크롤을 놓쳤으나 FR12 측정이 바로 교정했다. H2(UI HTML 대 실제)는 **정적/실브라우저 분리 지지**다. 캡처와 `isTrusted` 클릭·요청 단언을 갖추었지만 API는 스텁이다. H3(늦은 모듈 통합)은 **반증 쪽**이다. 0025와 합친 공통 PR이고 저장 동작의 새로운 문제는 측정에서 0024로 분리되었다. H4(검증 조기 식별 실패)는 **부분 반증**이다. FR12가 측정을 예정했으나 첫 화면만으로는 회귀를 놓쳤다. 원인 분류는 제품 UI 설계·측정 단계; 현행 0.1.8 plan 양식의 독립 기대·실행 기록 요구가 이미 있으므로 단독 템플릿 결함 후보로 올리지 않는다.

근거 부족: 당시 대화 원문·검토 응답·모델/OS 실행 정보·Playwright 프로세스 출력은 이 수집에 없다. Sonnet은 문서의 검토자 표기이지 브랜치 이름의 추론이 아니다. PR의 `reviews`·`checks` API 빈 목록은 외부 게이트 부재 증거가 아니다.
