여섯 축: **의도 보존**은 데이터 손실 방지·직접 편집으로 이어졌고 FR01의 초기 “불러온 값 보내기”는 검토 뒤 올바른 생략으로 수정됐다. **설계 충실성**은 현재 `tableDetail.svelte.ts:467-485`의 미수정 키 생략, `models/text2sql.py:930-988`의 생략=변경 없음, `SchemaKnowledgePane.svelte:370-395,434-470`의 편집·판 처리로 정적 확인된다. **계획 실행 가능성**은 T01/T02/T03 구분·독립 기대가 명확하나 첫 문서 선행은 불명이다. **PR 경계**는 공유 화면 0023/25 선행 머지를 필요로 했고 실제 병합·후속 리뷰에서 접점이 드러났다. **변경 피드백**은 검토가 낡은 값 전송을 바로잡고 리뷰가 캐시·늦은 응답을 보완했다. **검증·보고**는 RED 근거 중 `SchemaKnowledgePane.save` 첫 실행의 잘못된 `calls('post')` 필터 때문에 일부 실패 원인이 혼재했다고 plan이 명시한다. 이후 구현 상태 10 통과와 FR08의 구현 뒤 임시 되돌림 3실패를 구별해야 하며 이를 모두 진짜 선행 RED로 세지 않는다.

사용자 가설: H1은 **지지**(초기 “불러온 값” 설계가 저장 경쟁에서 의도와 어긋나 수정), H2는 **부분 지지**(측정은 실제 요청 HTML/UI를 봤지만 백엔드는 스텁; 후속 저장소 시험에서 효과 재현), H3는 **지지**(두 화면이 같은 저장소와 캐시를 공유한다는 통합면을 늦게 연결했고 PR 리뷰가 캐시를 찾음), H4는 **부분 지지**(TDD·전체 스위트 계획은 있었으나 UI 실제 서버/DB 경로는 미검증). 현재판에 남는 일반 원인을 템플릿 탓으로 단정하지 않는다. 0.1.8·WIP 양식은 검증 선택·독립 기대·실제 한계 기록을 이미 요구한다.
