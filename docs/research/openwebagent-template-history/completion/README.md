리뷰자는 실제 문서와 필수 참조를 읽고 모순·중요 누락·과도한 강제·인계/검증 오인을 찾는다.
root는 발견의 근거를 판단하고 관련 source만 최소 수정한다. 지적 없음이나 취향 차이만으로 규칙을
추가하지 않는다. 중요한 범위가 바뀌면 그 범위를 재검토한다. 적대적 리뷰 자체는 사람의 수락이 아니다.

단위별 리뷰 전문·발견 처리·대상판은 이 폴더에, 명령 전체 출력·해시·스냅샷은
`.local/research/openwebagent-template-history/20261003/completion/`에 보존한다.
설계/검토 source가 사용할 스킬은 배포판의 예시 기준이며 제작용 개인 설치를 일괄 업데이트하지 않는다.
개발 실험은 보완 이후 실제 사례를 기반으로 별도 지시 후 진행한다. 기존 중단 기록을 통과로 바꾸지 않는다.

## 이번 실행의 사용자 원문

> 개발 실험은 실제 사례 바탕으로 할거야. 일단 보완 작업을 끝까지 완료하고 하자. 한번에 다하지 말고 나눠서 각각 진행후 적대적 리뷰 붙여서 검증 받는 식으로 하자.

## U1 처리

root는 기대 근거와 미확인 검증 입력의 인계를 AC 안내에 명시하고, 중요한 AC의 검증 접근을 UI 설명과
구분했다. F01의 좁은 출력/보존 시험으로 충분한 경우를 함께 설명했다. Astra/high는 기존 후보와 실제
수정·관련 입력/정본을 대조해 중요한 지적을 찾지 못했다. root도 추가 규칙이 필요하지 않다고 판단했다.
해당 2개 문서의 상대링크12개와 diff 공백 확인은 통과했다. 제품 효과는 미입증이다.

## U2 처리

실제 컴포넌트 탐색의 범위, 사람의 시각 피드백, 공개/데이터 정책과 제품 편입 조건을 보완했다.
기존 정적 예시의 비연결 제한이 모든 UI 작업의 금지로 읽히지 않게 설명했다. Astra/high는 여덟 반례를
대조해 중요한 지적을 찾지 못했고 U1 검증 절이 그대로임을 확인했다. root는 해당 범위의 정리를 완료했다.
실제 화면 구현·시각 수락·제품 효과는 검증하지 않았다.

## U3 처리

첫 실제 연결과 독립된 준비 작업을 구분하는 설정 저장 예시를 보완했다. Astra/high는 첫 통합 지연,
미래 계약 고정, 병렬·배포 조건, 가상 검증 오인과 M01의 의존성을 대조했고 필수 수정 사항은 찾지 못했다.
root는 오류 계약을 spec에서 먼저 확인한다는 기존 문맥과 작은 인도로 구현·검증을 확장하는 설명을 함께
확인했다. source 범위를 완료하며 실제 통합 시점이나 제품 결과의 개선을 주장하지 않는다.

## U4 처리

기존 제품의 실제 색인·경로를 사용하는 안내와 코드 결함/의도된 계약 개정의 구분을 보완했다.
Astra/high는 Git 정책의 인계·머지 지시가 여전히 changes 표를 지정하는 충돌(P2)을 발견했다.
root가 실제 채택한 색인, 없으면 현재 plan·기존 실행 기록을 갱신하도록 맞췄고 재검토에서 해결됐다.
최초 지적과 수정판을 전문에 함께 보존했다. 강제 경로 이사·두 번째 색인·새 검사기는 추가하지 않았다.
