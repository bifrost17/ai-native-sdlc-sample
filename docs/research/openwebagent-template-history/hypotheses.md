# 사용자 기억에서 시작하는 조사 가설

사용자가 실행 중 직접 제시했다. 아래는 아직 사실로 판정하지 않은 조사 입력이다.

| ID | 기억·제안 | 사건에서 확인할 것 | 반증·경계 |
|---|---|---|---|
| H1 | 설계 부족으로 변경이 잦고 계획대로 구현되지 않았다 | 최초의 중요한 미결·계약과 뒤 변경/재작업의 관계, 변경 때 spec/plan 갱신 | 새 요구나 정당한 탐색은 초기 설계 결함과 구분 |
| H2 | HTML 시안이 있어도 실제 UI의 심미성·기존 UI 통일성이 부족했다; 설계 중 실제 UI를 구현하면 좋겠다 | 실제 기준 화면·컴포넌트·상태/사용 흐름·반응형·사람 디자인 판단과 시안/구현의 차이 | 임시 시안의 성공을 제품 UI 수락으로 바꾸지 않음; 모든 화면 완성은 요구하지 않음 |
| H3 | 모듈별 구현 뒤 통합이 잘 동작하지 않았다; 전체 인터페이스·시퀀스부터 정하면 좋겠다 | 공유 계약·실패/수명/권한·대표 흐름을 언제 연결해 검증했는지 | 모든 내부 구현을 미리 확정하거나 병렬 수행을 금지하지 않음 |
| H4 | 설계 때 검증 방법을 특정하지 않아 최종 누락/버그가 생겼다 | AC의 독립 기대·방법·입력/환경·관측 지점·한계, plan과 실제 실행 연결 | 명령 이름·테스트 수·스크린샷 존재만으로 충분성 판정하지 않음 |

각 사례에서 적용되는 가설과 지지·반증·근거 부족을 기록한다. 사용자 기억이나 원전의 권고만으로
템플릿 원인을 확정하지 않는다. 중요한 현행 잔여 문제만 기존 지침의 작은 개선으로 연결한다.
