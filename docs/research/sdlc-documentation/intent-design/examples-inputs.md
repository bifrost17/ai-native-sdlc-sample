# Intent 예시의 입력과 출처

아래는 양식 설계를 위해 Codex root가 작성한 합성 사례다. 실제 사내 사건이나 에이전트 실행
결과가 아니다. 예시에는 아래에서 공개한 입력만 사용하며, 별도의 human.json 결정은 미리 채우지 않는다.
이 문서는 설계 리뷰 자료이고 사용하는 프로젝트에 복사해야 하는 양식의 일부가 아니다.

## F01 — 작은 기능 요청

출처: [기존 F01 공개 카드](../../../experiments/datasets/v1/F01/public.json).
작성자는 실험 요청자라는 합성 역할로 표시한다.

요청: 작은 팀이 로컬 CLI로 업무 요청을 본다. 목록이 섞여 있어 담당자의 요청을 눈으로 고르고 있다.
담당자 ID로 목록을 좁혀 보고 싶다. 기존 list/show/complete와 JSON 필드는 유지하고, 조회로 파일을
바꾸지 않는다. Python 3.9 이상 표준 라이브러리만 사용하며 외부 서비스·계정·네트워크가 없다.
업무 코드는 2~4파일 이내이며 시험·문서는 별도다. 목록은 파일 순서이고 담당자 없음은 null이다.
완료 포함 여부·미배정 선택·구체적 옵션은 아직 대화로 답하지 않았다.

## B01 — 복사한 ID로 조회 실패

출처: [기존 B01 공개 카드](../../../experiments/datasets/v1/B01/public.json).
작성자는 실험 요청자라는 합성 역할로 표시한다.

요청: 메시지에서 복사한 ID로 조회하면 있는 요청도 없다고 나온다. 앞뒤 ASCII 공백 없이 입력하면 된다.
확인된 예: `python3 tracker.py --data requests.json show R-202`는 성공하고 같은 ID 양끝에
ASCII 공백이 있으면 rc=1이다. 기존 list/show/complete가 있으며 저장 ID는 대문자 R-와 숫자 세 자리다.
저장된 ID와 데이터 행을 재작성하지 않는다. 기존 시험은 현재 baseline에서 통과하며 수정·삭제하지
않고 재현/회귀 시험을 먼저 추가한다. Python 3.9 이상 표준 라이브러리만 사용하고 외부 연결은 없다.
업무 코드는 2~4파일 이내다. 다른 공백 문자·완료 명령 적용은 아직 답하지 않았다.

## I03 — 작성자와 재현 정보가 없는 요청

이번 양식 설계용 합성 입력이며 실제 티켓이 아니다.

출처: 팀 요청함. 작성자 이름·팀·답변 담당자·접수 시각은 제공되지 않았다.
원문: “검색 결과를 기다리다가 업무 흐름이 끊겨요. 캐시가 없어서 그런 것 같은데 Redis 캐시를
넣으면 좋겠어요.” 요청자는 현재 세션에 없다.
추가로 알려진 지연 수치·검색 예시·재현 명령·기술 구조·확정 제약·해결책 승인·로그·SHA는 없다.
Redis는 제안이며 필수 선택으로 합의되지 않았다. 원인도 확인되지 않았다.
