# 발견으로 계획을 바꿀 때

F02의 PR2 시작 시 기존 계획이 tests/test_tracker.py에 요약 시험을 추가한다고 가정한다.
실제 읽기에서 그 파일은 기존 명령 회귀의 기준이며, 독립 test_summary.py가 더 읽기 쉽다고 판단했다.
동작·계약은 그대로이므로 Files와 PR2/Proof의 경로·이유를 바꾸고 요약 구현과 같은 커밋에 담는다.
spec·intent를 형식적으로 다시 쓰거나 helper/시험 배치 변경을 새 요구 승인으로 취급하지 않는다.
PR1이 끝났다는 이유로 plan 전체를 완료로 표시하지 않는다.

반대로 요약에서 미배정을 별도 선택하거나 출력 JSON을 요구하면 spec의 동작·AC가 달라진다.
그 결정을 사람이 수락한 판을 먼저 커밋/기록한 뒤 plan의 Upstream·작업·Proof를 맞춘다. 문제/목표가
같으면 intent는 유지한다. 변경된 계획·이유는 관련 구현과 같은 커밋에 들어간다.

M01에서 API 밖 소비자를 새로 발견한 사례는 이미 spec-design에서 결정 변경으로 다뤘다.
계획에서 임의로 영구 JSON 미러를 추가해 해결하지 않는다. 관련 spec 질문/선택을 먼저 맞추고
그 결과에 따라 PR 순서·보고서 파일·전환 전 검증을 갱신한다. 이미 완료한 다른 PR과 앞으로의
미완료 범위를 함께 읽을 수 있게 유지한다.

이 문서는 가상 변경 대조다. 실제 F02 실험의 발언·변경·커밋 관측과는 별도로 기록한다.
