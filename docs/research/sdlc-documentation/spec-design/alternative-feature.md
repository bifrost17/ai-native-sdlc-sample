# B 후보: 담당자 조건으로 요청 목록 좁히기

이는 채택하지 않은 정보 배치의 완성 예시다. 입력은 [F01](../../../../.claude/skills/design-spec/examples/feature/context.md)과
동일하며 실제 승인·구현 문서가 아니다. 비교에 무관한 공통 메타데이터는 생략했다.

기존 목록 사용을 유지하면서 `list --owner <ID>`로 한 담당자의 요청을 조회한다.
완료 여부와 순서를 바꾸지 않으며 별도 사람 결정이 필요한 우려는 현재 없다.

## Capabilities and acceptance

### 담당자별 조회
- R1. `list --owner <ID>`는 담당자 문자열이 정확히 일치하는 행을 기존 순서로 출력한다.
  완료 건을 포함하며 null 담당자는 문자열과 일치하지 않는다.
- R3. 조회는 파일을 바꾸지 않는다. 일치하는 행이 없으면 빈 stdout과 rc=0이다.
- AC1 → R1,R3: 새 F01 데이터에서 hana는 R-101, R-103 순서이며 파일 바이트가 같다.
- AC2 → R1,R3: nobody, HANA, `-`는 각각 빈 결과·rc=0이고 파일은 같다.

### 기존 사용의 보존
- R2. 옵션 없는 list, show/complete, 출력 열과 JSON 필드를 유지한다.
- AC3 → R2,R3: 옵션 없는 list는 네 행을 원래 순서·열로 출력한다. 기존 show/complete와
  I/O 오류 동작을 기존 검증으로 확인한다. 시험의 파일명·명령은 plan에서 정한다.

## Design
argparse의 list에 선택 인자를 더하고 JSON 읽기 뒤 순서를 유지하는 필터를 적용한다.
기존 display를 재사용하고 show/complete의 ID 조회에는 개입하지 않는다. 기존 순회에서
필터링하면 충분하며 새 인덱스·DB·캐시를 정당화할 규모나 성능 문제가 입력에 없다.
비교에서 대소문자 변환·부분 일치는 하지 않는다. 내부 함수 이름은 구현자가 정한다.

## Constraints and scope
기존 명령·필드·조회 무변경은 R2,R3에 보존한다. 업무 코드는 2~4파일이고 시험·문서는 별도다.
미배정 전용 조회·복수 담당자·부분 일치·정렬·새 저장소는 범위 밖이다.

## Open questions
- Q1 answered: 요청자의 완료 포함·원래 순서 답변을 R1에 반영했다.
- Q2 answered: 정확 일치·null 제외·없는 담당자는 빈 결과다. R1,R3과 AC2에 반영했다.
- Q3 answered: `list --owner <ID>`와 기존 list 유지다. R1,R2에 반영했다.
새로운 중요한 미결 질문은 없다.
