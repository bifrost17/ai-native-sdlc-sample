# R1 이후 root가 수정한 범위

R1 보존 커밋은 maker 4f52028, adopter 3e2f693이다. 양쪽의 실패 후보와 검토 기록을 유지한다.
Astra는 복구 뒤 구버전 쓰기 유실 재발을 차단 사유로 FAIL, Fable은 PASS와 비차단 보완 의견을 냈다.
root는 구체적인 회귀 경로를 근거로 Astra 지적을 수용했다. 다수결로 통과시키지 않았다.

- M01 context/spec 양쪽: 최신 복구 데이터만 확보하고 결함 있는 구버전 writer를 재개하지 않도록
  합성 운영 결정을 명시했다. R4·AC4·Design·Q2에 쓰기 경로의 R1 보존과 미충족 시 중지 유지,
  쓰기 여부 미확인 시 보수적 복구 경로, 사본의 구버전 완료 시험을 함께 반영했다.
  입력에 없는 기존 백업 체계는 사실처럼 표현하지 않는다. 다른 writer는 있는 경우만 중지한다.
- 양쪽 design-depth: 이행 후 데이터뿐 아니라 재개 후 중요 불변 조건도 보존하도록 기존 행을 보완했다.
  새로운 표제·검사기·승인 관문을 추가하지 않았다.
- F01 spec 양쪽: 실제 baseline 세 시험에는 I/O 오류 시험이 없으므로 그 경로까지 기존 시험으로
  확인한다고 쓰지 않게 했다. 실제 Sonnet 초안에서도 예시의 이 표현이 이어져 root가 발견·수정 요청했다.
  필요한 추가 검증의 선택과 실행은 plan에 남긴다. 제품 계약과 합성 입력은 그대로다.
- 기존 eval 03 양성/음성 fixture: AC를 Requirements 다음으로 이동했다. 질문 누락 실패와
  assertion 내용은 유지했다. 제약 restate와 참조 허용의 비차단 표현 차이는 이번에 기준 변경으로 확대하지 않는다.
- maker CLAUDE.md와 /spec 연결 설명: 양식이 항상 스킬 안에 복제돼 있다는 옛 설명과,
  허용된 초안 예외를 생략한 문장을 현재 지침에 맞췄다. 원래 L3 프롬프트는 그대로다.
- adopter 선택 지침: intent의 해결 제안과 실제 설계 선택 구분, 요청·자료 판의 기존 기록 보존을
  짧게 추가했다. References applied와 disable-model-invocation: true는 유지한다.

소스 예시는 root가 쓴 합성 자료다. 실제 Sonnet 대화에서 나온 문서는 별도 실험 브랜치에 있다.
추가 합성 결정은 회사 정책이나 실제 사용자 답이라고 인용하지 않는다.

R2는 위 수정과 기존 31개 파일, 새로 명시한 maker CLAUDE.md·/spec 명령 두 개를 함께 검토한다.
두 리뷰어는 자신의 R1 맥락을 재사용하되 실제 수정 파일을 다시 읽고 같은 R2 후보를 판단한다.
