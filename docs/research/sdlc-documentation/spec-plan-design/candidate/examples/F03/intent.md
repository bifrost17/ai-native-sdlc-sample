# Intent: 담당자별 요청 목록과 진행 현황을 함께 제공
Author: 합성 업무 오너 F03. Status: draft.

## Problem
동료들이 담당 건을 찾은 뒤 전체·미완료·완료 수를 따로 세고 있다.
## Proposed outcome
담당자 목록과 집계를 한 기능으로 사용하고 싶다. 두 PR로 개발하되 전체가 준비될 때 공개한다.
## Affected users and systems
요청 CLI 목록·집계 사용자와 개발 시험 프로세스.
## Constraints
기존 명령·데이터 형식·원순서와 읽기 전용 조회를 유지한다.
일반 사용자는 미완성 기능을 보지 않으며 개발자는 준비된 부분을 시험할 수 있어야 한다.
## Open questions
- Q1 정확 일치와 null, 집계 출력 순서는?
- Q2 일반/시험 공개는 어떻게 분리하는가?
- Q3 공개·중단·제어 제거는 언제 누가 하는가?

답은 [context](context.md)의 고정 입력/역사 계약에 있다. 실제 공개 결정은 이 작성 예시에서 미실행이다.
