# M01 설계 정본: 전환·복구 조건
[spec 진입점](../spec.md). 담당은 합성 운영 담당. 실제 명령/경로/권한은 Q4, 실행 순서는 plan이 구체화한다.

전환 전제는 보고서 API 전환과 SQLite 저장/이행 도구의 통합 검증, 그리고 실제 환경 사본 리허설이다.
API·보고서·모든 writer를 중지하고 확인한 상태에서 원 JSON을 보존한다. 새 DB에 import 후 값·순서
전체를 비교하고 설정을 sqlite로 바꾼다. 재개 판단 전 사본에서 권한·완료·재조회·보고서·복구를 확인한다.
코드 머지는 데이터 이행이나 운영 공개의 성공이 아니다.

| 시점/문제 | 보존/대응 | 재개 조건 |
|---|---|---|
| import 실패·중단 | 원본 유지, 실패 target 사용 금지, 원인 해결 후 새 target에 재실행 | 유효성·대조·리허설 성공 |
| 전환 후 쓰기 전임이 확실 | 원본을 복구 입력으로 사용 가능, 새 DB도 보존 | R1이 검증된 안전한 저장 경로 |
| 전환 후 쓰기 있음 또는 불명 | 서비스 중지, 최신 DB를 새 JSON으로 export·대조, 모든 원본 보존 | 최신 데이터와 동시 완료 보존이 검증된 저장 경로 |
| export·대조·안전 경로 검증 실패 | 중지 유지, DB/원본/부분·정상 복구 자료를 구별해 보존 | 원인 해소 후 필요한 검증 재수행 |

기본 복구는 최신 데이터가 있는 SQLite 경로를 복구하는 것이다. JSON export는 최신 데이터를
보존하고 구버전 호환을 사본에서 확인하는 수단이며, 알려진 동시 쓰기 유실이 있는 구 JSON writer를
다시 서비스한다는 허가가 아니다. Git revert만으로 데이터/동시성 문제는 해결되지 않는다.
구버전 list/complete 호환은 복구 JSON의 사본에서만 확인하고 정상 export 원본은 보존한다.
Q4 미해소, unknown writer, 검증 불일치가 있으면 운영 전환/재개를 멈추고 운영 담당에게 전달한다.
