정정 감사합니다. plan.md의 해당 문단을 다시 보면 "최신 main과 결합한 판"과 "통합 main"은 서로 다른 시점의 서로 다른 판이며, 확인 횟수를 고정하는 것이 아니라 PR마다 반복되는 두 개의 별개 확인입니다.

## PR1

- **기준**: 새 branch 시작 시점에 기존 `test_tracker.py`(P0)가 통과하는 것을 기준점으로 확인.
- **구현 중**: branch 위에서 `test_owner.py`(AC1) RED→GREEN, `test_release_control.py`(P2, OFF 거부·설정값)를 확인. 아직 main과 무관한 branch 로컬 판.
- **머지 전(결합판)**: 리팩터링 후 전체 시험(P0–P2)을 branch에서 재확인하고, "최신 main과 결합한 판"—즉 PR1 branch를 그 시점의 최신 main과 합친 판—에서 같은 시험을 확인. 이는 PR1 개발 중 main이 움직였을 가능성에 대비한, 머지 이전의 사전 확인.
- **머지 후(통합 main)**: PR1이 실제로 main에 머지된 뒤, 그 통합 main 자체에서 P0–P2를 다시 확인. 결합판과 통합 main은 코드 이력상 다른 커밋이므로 별개 확인이 필요.

## PR2

- **기준**: PR1이 반영된 최신 main에서 새 branch를 시작하며, 그 시점 P0–P2가 유지되는지 기준 확인.
- **구현 중**: `test_summary.py`(P3) RED→GREEN, PR1의 목록·OFF 거부 시험(P1/P2)이 회귀로 유지되는지 확인.
- **머지 전(결합판)**: 리팩터링 후 전체 시험(P0–P3)을 branch에서, 그리고 그 시점 최신 main과 결합한 판에서 확인.
- **머지 후(통합 main)**: PR2가 머지된 실제 main에서 P0–P3 전체를 다시 확인. 이 판이 일반 OFF/TEST ON에서 목록+집계 전체가 가능한 상태.

## 공개 전

Proof P4는 "PR2 결합/통합 main **동일 판**의 사본에서 OFF→ON→OFF + P0–3"이라고 명시합니다. 즉 공개 전 단계는 새 코드 판을 또 만들지 않고, PR2 머지 후 통합 main 확인에서 이미 확보한 유효한 판·근거(P0–P3 GREEN)를 그대로 재사용합니다. 여기에 추가되는 것은 그 동일 판의 사본에서 실행하는 **토글 리허설**(설정만으로 OFF→ON→OFF 전환)이라는 새로운 관측뿐입니다. 공개 담당은 이 재사용된 근거 + 리허설 결과 + 완료 범위를 보고 실제 일반 공개 여부를 결정하며, 그 뒤 같은 완성 코드로 실제 일반 환경에서 새 프로세스를 실행해 설정 ON/OFF를 관측하는 것은 코드 판을 바꾸는 작업이 아니라 별도의 설정 변경·관측 행위입니다.
