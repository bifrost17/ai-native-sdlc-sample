# 추가 사용자 조건: spec은 한 파일로 제한하지 않는다

2026-09-11, 독립 제안 수집 중 사용자 확인: “spec.md 를 꼭 하나의 파일로 구성하려고 생각한건 아니지?”

spec.md는 설계의 진입점이다. 작은 변경은 단일 파일, 큰 변경은 연결된 문서 집합으로 구성한다.
여섯 정보 역할은 유지하되 Design 본문 전체를 한 파일에 강제하지 않는다. spec.md에 정본 설계 문서의
목록·역할·필수 읽기 범위를 명시하고, 각 결정은 한 위치에서 관리한다. 참조만 있고 실제 내용이 없거나
어느 문서가 현행인지 알 수 없는 상태는 인계 가능한 spec이 아니다.

클래스·API·데이터 모델·시퀀스·배포 등 중요한 설계는 연결된 spec 문서 집합에 속한다. 파일을 나누기
위해 plan으로 옮기지 않는다. plan은 필요한 설계 문서/절을 참조하며 실제 구현·시험·통합을 계획한다.
관련 구현 변경 시 영향받는 설계 문서와 plan을 같은 커밋에서 갱신한다. 참조된 정본도 리뷰 범위다.

설계 패키지 적용: F01은 단일 spec 예시, M01은 spec.md + design/ 상세 문서의 연결 예시로 만든다.
독립 제안 원본은 고치지 않고 추가 조건으로 보존한다. 후속 후보 리뷰에는 이 조건을 모두 제공한다.
