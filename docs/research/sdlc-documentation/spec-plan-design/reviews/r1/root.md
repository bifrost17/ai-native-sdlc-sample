# root의 후보 검토 메모

r1 2634f07. 이 메모는 Astra 리뷰 수신 뒤 작성했으므로 독립 리뷰로 세지 않는다.
후보는 두 모델의 같은 판 검토가 끝날 때까지 고정한다.

- A1 수용 예정: 활성화 전달표에 change-walkthrough와 예시 입력의 위치/상대 링크 조정 범위를 추가한다.
  설치 초안의 빠뜨릴 여지를 줄이는 수정이며 새로운 설치 프로그램은 만들지 않는다.
- R1 보완 예정: F03 P4의 동일 코드 OFF→ON→OFF 검증은 일반 공개 전 개발 프로세스/사본의 리허설도
  가능함을 분명히 하고, 실제 일반 환경 전환은 그 뒤 오너 결정/운영 기록으로 구별한다.
  공개 전에 실제 공개 관측을 먼저 요구하는 순환으로 읽히지 않게 한다.
- R2 보완 예정: M01 sqlite 선택 시 기존의 검증된 DB만 열고 새 빈 DB를 조용히 만들지 않으며
  user_version/필수 스키마의 시작 전 검증을 명시한다. 실제 구현/시작 단계에는 관련 시험을 plan에 연결한다.
  이미 정한 “사용 불가 DB 시작 실패·fallback 없음”의 구체화다.
- R3 표현 수정 예정: M01 클래스 그림에서 owner_or_null이라는 설명용 가짜 필드 대신 실제 owner와
  Optional[str] 타입을 쓴다. 그림과 실제 계약의 이름을 맞춘다. Request는 dict 표현이라는 설명을 유지한다.
- R4 시각 수정 예정: F03 cleanup 노드 라벨을 더 짧게 해서 자동 한글 낱자 분리를 없앤다.
- R5 인계 근거 보완: F03 context가 과거 spec/plan을 필수 읽기처럼 연결해 현행 정본과 함께
  읽혔다. 실제 trace의 turn 1에 두 역사 파일 Read가 있고 turn 2에는 재독 없이 과거 R6를 인용했다.
  역사 자료는 출처로 보존하되 필수 인계에서 빼고 현행 spec/plan을 정본으로 명시한다.
  규칙을 추가하기보다 불필요하게 섞인 입력을 줄이고 새 Sonnet 문맥으로 재점검한다.

F03 새 세션의 순서/출처 오독은 handoff/record.md에 보존한다. 같은 규칙이 이미 plan/skill에
있으므로 개별 실수마다 새 gate/ledger/체크리스트를 추가하지 않는다.
