첫 응답을 읽었다. 현재는 합성 입력을 전제로 한 문서 인계이며 실제 제품 정책/경로 확인은 실행 때 해야 할 일이다. 먼저 candidate/guidance/execution-blocks.md의 같은 커밋 갱신 절, W01 plan의 Current change와 PR-A 기준, 링크된 docs/GIT-WORKFLOW.md와 docs/RELEASE-CONTROL.md를 실제 Read로 확인해줘. 그 근거로 오래된 Upstream+Current change를 즉시 결함으로 본 판단을 다시 설명하고, 처음 작업의 기준 확인부터 머지 전 결합/머지 후 확인까지 빠짐없이 정리해줘.

후속 개발 요청도 있다. PR-A가 main에 합쳐졌고 u1의 API 조회만 성공한 상황이라고 하자. 아직 PR-B는 시작하지 않았다. 직원이 '목록을 보는 중에도 새로고침 버튼으로 다시 읽고 싶다. 자동 polling은 원하지 않고 API의 본인 조회 계약은 그대로다'라고 요청했다. 이 요청을 수용할 적절한 기본 UI 동작을 제안하고, 어느 spec 결정/AC와 plan 파일·첫 시험을 수정해야 하는지, 무엇은 그대로 둘지 설명해줘. 현재 u1/u2에게 가능한 동작과 일반 공개/cleanup 판단도 함께 알려줘. 제품 코드나 후보 파일은 수정하지 않는다. 실제 완료/수락이 아니라 이 가정에서의 인계 답변이다.
