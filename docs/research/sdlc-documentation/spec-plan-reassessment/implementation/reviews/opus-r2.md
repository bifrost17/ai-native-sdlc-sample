## 1. W01 AC1–7 / AC8 분리 — 수정이 **필요했고**, 올바르다

이전 판의 "완성 코드의 **전체 AC**와 OFF 복귀 근거를 확인해 공개를 결정"은 실제로 순환이었다. AC8(spec L33)의 조건 자체가 "공개 후 조건을 충족해 **제어 제거한 판**"이고, 그 판은 spec L137·plan L103의 전제(공개 → 안정화/중단 관측 → 구버전 의존 해소 → 오너 정리 요청)를 거쳐야만 존재한다. 즉 공개 게이트가 공개 이후에만 생기는 증거를 요구하고 있었다. 문서 결함이 맞고, 최소 수정으로 해소됐다.

현재 순환이 해소됐는지 독립 확인:
- 공개 게이트(spec L134) = AC1–7 + OFF 복귀 근거. AC1–6은 완성 판의 focused/e2e 시험(plan P-A/P-B/P-C, L119–121), AC7은 "같은 완성 판의 격리 사본 리허설"(spec L135 ↔ plan L95 "격리한 설정 사본으로 … 같은 완성 판에서 리허설")로 **공개 전에 관측 가능**하다.
- AC7이 실환경 ON을 전제하지 않는 점도 plan P-R(L123) "로컬 리허설과 운영 관측은 별개"로 분리돼, 공개가 자기 자신을 선행 조건으로 삼지 않는다.
- cleanup 게이트(spec L137, plan L103) → AC8 검증(spec L135, plan L104–105, Proof P-F L124). 어느 단계도 후행 단계의 증거를 요구하지 않는다. **순환 해소 확인.**
- 인도 지도(plan L32–33)도 "공개/중단 ← B 전체 흐름/회귀와 Q4 확정", "cleanup ← 위 관측 후 오너 정리 요청"으로 같은 순서를 유지한다.

이 형태는 F03의 선례(AC1–6 공개 전, AC7 cleanup 판, spec L59–60)와도 일치해 두 예시의 공개 단계 의미가 이제 같은 규칙을 따른다.
