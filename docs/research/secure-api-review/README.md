# secure-api-review (S5) — 요약

**과제**: `policies/api-security.md` 의 S1–S4 는 플레이북 예시 스킬(기준선)이 이미 덮는다. 그 밖의 **S5(상류 호출 예산) · S6(열거 방지) · S7(세션 계약) · S8(비밀값)** 을 덮는 스킬을 구해 오고, 남으면 설계한다.

## 결론

| 무엇 | 어느 스킬 | 덮는 조항 |
|---|---|---|
| **기준선 그대로 채택** | `skills/secure-api-review/` — 템플릿 `@016705e` 사본, 한 글자도 안 고침 | S1 · S2 · S3 · S4 |
| **채택** | `skills/secrets-scan/` — OWASP secure-agent-playbook `@79fea6b`(v0.2.7), CC-BY-4.0, 원문 유지 | S8 |
| **설계** | `skills/claims-api-security/` — 정책 원문을 조항 ID 와 함께 옮김 | S5 · S6 · S7 · S8 |
| **기각** | 27건 | — |
| **보류** | 2건(OWASP API Security Top 10 2023 · OWASP CheatSheetSeries — 스킬이 아니라 참고 산문) | — |

여덟 조항이 모두 덮인다 — `coverage.md`. 후보 30건의 판정과 근거는 `candidates.md`, 트리거 시험 18건은 `trigger-tests.md`, 명령·사본 원문은 `raw/`.

## 어쩌다 「거의 다 설계」가 됐나

찾기를 게을리해서가 아니다. 여섯 갈래(GitHub 코드·레포 검색, 알려진 모음, 웹 검색, 스킬 아닌 원문, 마켓플레이스·레지스트리)로 훑고 **30건을 열어 읽은 뒤 후보마다 반박 담당을 따로 붙여** 등급을 내리게 했다. S5–S8 중 하나라도 「덮음」으로 살아남은 것은 **secrets-scan(S8) 하나**다.

이유는 조항의 성질에 있다:
- **S5** 세상의 rate-limit 스킬은 전부 인입 통제(자기 엔드포인트에 429)다. S5 는 상류 claims-core 예산이고, 산출물이 코드가 아니라 **spec 에 적는 캐시 정책과 호출 수 계산**이다.
- **S6** IDOR/BOLA 스킬은 흔하지만 하나같이 권한 없음에 **403 을 돌려주는 예시**를 든다 — 정책이 금지하는 열거 오라클 그 자체다. 「같은 지연」까지 말한 스킬은 없었다.
- **S7** 역할마다 세션 키 이름이 다르고 핸들러가 자기 것만 읽는다는 계약은 이 조직의 것이다. 남들은 RBAC 나 쿠키 위생을 말한다.
- **S8** 만 세상과 겹쳤다 — 그래서 하나를 채택했다.

거의 모든 기각의 뿌리는 둘이다: (1) 앱에서 게이트웨이 JWT 를 다시 검증하라 — 기준선 org note 가 「다시 지적하지 말 것」이라 못박은 자리, (2) 권한 없음에 403 — S6 위반. 목록은 `coverage.md` 「모순」.

## 남는 구멍

1. **강제층이 없다.** 스킬은 권고적 통제다(플레이북 L6 503). S8 뒤에는 템플릿의 `no-secrets` 훅이 있지만 S5·S6·S7 뒤에는 아무것도 없다.
2. **트리거는 결정적이지 않다.** 같은 문구가 어떤 판에서는 스킬을 띄우고 어떤 판에서는 안 띄웠다(`trigger-tests.md` 54 대 62). 채택분 `secrets-scan` 은 **검토** 문구에서만 뜬다 — 자격증명을 담는 설정 파일을 **새로 쓸 때**는 안 떴다(62). 그 자리는 설계분 S8 절이 메웠다.
3. **S5 를 닫으려면 수치가 더 필요하다.** spec 시험(63)에서 세션이 캐시 정책과 호출 수는 적었지만 rps 환산의 입력값(예상 요청률)이 없어 「닫히지 않음」으로 남겼다. 스킬이 시킨 대로 한 결과다 — 그 숫자는 정책·제품 쪽에서 와야 한다.
4. **설계분에는 오너 서명이 없다.** 플레이북은 정책 스킬에 오너 서명을 요구한다(L6 57행). 이 PR 은 머지하지 않는다.

## 정책 오너에게 묻는다

1. **S5·S6·S7 뒤에 결정적 통제를 둘 것인가?** 스킬만으로는 「위반이 드물어질」 뿐이다(L6 503-504). 훅으로 막을지, PR 리뷰 패스로 다시 볼지, 아니면 권고로 둘지는 정책의 결정이다. 이 레인은 훅을 만들지 않았다.
2. **S6 의 「같은 지연」을 어디까지 요구하는가?** 「같은 코드 경로를 타라」(설계 가능·검토 가능)까지인가, 상수 시간 보장(측정과 시험이 필요)까지인가. 스킬은 앞쪽으로 적었다 — `skills/claims-api-security/SKILL.md` S6.
3. **채택분 `secrets-scan` 의 play 89–92행** 「Is it active? … Check if the key format is currently valid for the service」는 발견한 자격증명을 실제 서비스에 대 보라는 뜻으로 읽힌다. spec 을 쓰는 세션이 할 일이 아니라고 보지만, 원문을 고치지 않는 원칙 때문에 그대로 두었다. 잘라낼지, 조직 주석을 덧댈지 결정이 필요하다.
4. **OWASP 원문을 정책의 근거로 달 것인가?** OWASP API Security Top 10 2023 과 CheatSheetSeries 는 CC-BY-SA-4.0 이다. 문장을 옮기면 같은 라이선스와 저작자 표시가 정책·스킬에 따라붙는다. 지금은 착상만 가져오고 옮기지 않았다.
5. **S7 의 세션 키 이름 세 개**(customer · adjuster · agent)가 실제로 무엇인지 이 레포에는 없다. 스킬은 「자기 역할의 키만 읽는다」는 규칙만 적는다. 키 이름을 정책에 박을지, 세션 계약 문서로 뺄지.
6. **S5 의 50 rps 는 서비스 전체 합인가, 경로별인가?** 스킬은 「모든 경로가 나눠 쓰는 예산」으로 읽고 적었다. 다르면 고쳐야 한다.

## 확인 못 한 것

- 적대 검토 로그 하나(`raw/78`, sickn33/api-rate-limit-handler)는 판정 블록 전에 세션 한도로 끊겼다. 그 후보는 정독 판정(기각)을 그대로 뒀다.
- 발굴에서 이름만 본 것이 수백 건이다. 열지 않은 것은 `candidates.md` 에 넣지 않았다 — 열어 본 30건만 있다.
- 대화형(비헤드리스) 세션에서 스킬이 뜨는지는 시험하지 않았다. 헤드리스 `claude -p … --output-format stream-json` 의 도구 호출 기록으로만 판정했다.
- `skills.sh` 설치 수는 그 레지스트리가 보고한 값을 그대로 적었다 — 독립 검증은 못 했다.
- 이 스킬 집합을 템플릿 레포에 실제로 꽂고 `/spec` 명령을 돌려 보지는 않았다(그 자리는 S6 레인).
