     1	# Play: Secrets Scan
     2	
     3	Detect hardcoded credentials, API keys, tokens, and other secrets in source code and configuration files.
     4	
     5	## Trigger Conditions
     6	
     7	Use this skill when:
     8	- Reviewing code for leaked secrets before commit or merge
     9	- Auditing a repository for historical secret exposure
    10	- A user asks to check for hardcoded credentials
    11	- Setting up pre-commit hooks for secret detection
    12	
    13	## Inputs
    14	
    15	- Repository or directory to scan
    16	- (Optional) List of known-safe patterns to ignore (e.g., test fixtures, example placeholders)
    17	- (Optional) Whether to scan git history or just current files
    18	
    19	## Procedure
    20	
    21	### 1. Run Automated Scanner
    22	
    23	Use available tools in order of preference:
    24	
    25	1. **trufflehog** (recommended — scans current files + git history):
    26	   ```bash
    27	   trufflehog filesystem --directory=<path> --json
    28	   trufflehog git file://<repo_path> --json  # includes git history
    29	   ```
    30	
    31	2. **gitleaks** (git-aware scanning):
    32	   ```bash
    33	   gitleaks detect --source=<path> --report-format=json --report-path=results.json
    34	   ```
    35	
    36	3. **detect-secrets** (Yelp's baseline-aware scanner):
    37	   ```bash
    38	   detect-secrets scan <path> --all-files
    39	   ```
    40	
    41	If no scanner is installed, proceed with manual analysis.
    42	
    43	### 2. Manual Pattern Analysis
    44	
    45	Search for these high-confidence patterns:
    46	
    47	#### API Keys & Tokens
    48	| Pattern | Service | Regex Hint |
    49	|---------|---------|-----------|
    50	| `AKIA[0-9A-Z]{16}` | AWS Access Key ID | Exact format |
    51	| `sk-[a-zA-Z0-9]{48}` | OpenAI API Key | Prefix match |
    52	| `sk-ant-[a-zA-Z0-9-]{80,}` | Anthropic API Key | Prefix match |
    53	| `ghp_[a-zA-Z0-9]{36}` | GitHub Personal Access Token | Prefix match |
    54	| `gho_`, `ghu_`, `ghs_`, `ghr_` | GitHub OAuth/App tokens | Prefix match |
    55	| `xoxb-`, `xoxp-`, `xoxs-` | Slack tokens | Prefix match |
    56	| `SG\.[a-zA-Z0-9_-]{22}\.[a-zA-Z0-9_-]{43}` | SendGrid API Key | Format match |
    57	| `sk_live_`, `pk_live_`, `rk_live_` | Stripe keys | Prefix match |
    58	
    59	#### Credentials in Config
    60	| Pattern | What to Look For |
    61	|---------|-----------------|
    62	| Connection strings | `://user:password@host` patterns |
    63	| Password assignments | `password = "..."`, `PASSWORD: ...`, `passwd`, `secret` |
    64	| Private keys | `-----BEGIN (RSA\|EC\|OPENSSH) PRIVATE KEY-----` |
    65	| Certificates | PEM-encoded certificates with private key material |
    66	| JWT secrets | `JWT_SECRET`, `TOKEN_SECRET` assignments |
    67	| Database credentials | `DB_PASSWORD`, `MONGO_URI`, `DATABASE_URL` with embedded credentials |
    68	
    69	#### High-Risk File Patterns
    70	Scan these files with extra scrutiny:
    71	- `.env`, `.env.*` files
    72	- `**/config/**`, `**/settings/**`
    73	- `docker-compose*.yml` (environment sections)
    74	- `*.tfvars`, `terraform.tfstate`
    75	- `kubeconfig`, `*.kubeconfig`
    76	- `credentials`, `credentials.json`, `service-account*.json`
    77	- `.npmrc`, `.pypirc`, `pip.conf` (registry tokens)
    78	- `**/ci/**`, `.github/workflows/**` (inline secrets)
    79	
    80	### 3. Contextual Analysis
    81	
    82	For each detected secret:
    83	
    84	1. **Is it real?** Filter out:
    85	   - Placeholder values (`CHANGE_ME`, `xxx`, `your-api-key-here`, `<token>`)
    86	   - Test fixtures with known dummy values
    87	   - Documentation examples
    88	   - Base64-encoded non-secret data that matches key patterns
    89	
    90	2. **Is it active?** If possible:
    91	   - Check if the key format is currently valid for the service
    92	   - Look for rotation evidence (was it replaced in a later commit?)
    93	   - Check `.gitignore` — is the file supposed to be excluded?
    94	
    95	3. **What's the blast radius?**
    96	   - What service does this credential access?
    97	   - What permissions does it grant?
    98	   - Is it a production or development credential?
    99	   - How long has it been exposed?
   100	
   101	### 4. Check Preventive Controls
   102	
   103	Verify that the project has:
   104	- [ ] `.gitignore` entries for sensitive files (`.env`, `*.key`, `*.pem`, tfstate, etc.)
   105	- [ ] Pre-commit hooks for secret scanning (trufflehog, gitleaks, detect-secrets)
   106	- [ ] CI pipeline secret scanning step
   107	- [ ] Documentation on how to manage secrets (env vars, vault, etc.)
   108	- [ ] `.gitleaks.toml` or equivalent allowlist config for known false positives
   109	
   110	## Output Format
   111	
   112	```markdown
   113	## Secrets Scan: [Repository/Directory]
   114	
   115	### Scan Summary
   116	- **Scanner used**: [tool or manual]
   117	- **Scope**: Current files | Git history | Both
   118	- **Files scanned**: [count]
   119	- **Secrets found**: [count by category]
   120	
   121	### Findings
   122	[Standard finding template for each secret, with type and blast radius]
   123	
   124	### Preventive Controls
   125	| Control | Status |
   126	|---------|--------|
   127	| .gitignore covers sensitive files | Present/Missing |
   128	| Pre-commit secret scanning | Present/Missing |
   129	| CI secret scanning | Present/Missing |
   130	
   131	### Immediate Actions Required
   132	[If active production secrets are found, list rotation steps]
   133	```
   134	
   135	## Important Notes
   136	
   137	- **Never include the actual secret value in findings.** Show a redacted version: `AKIA****EXAMPLE`
   138	- If active production secrets are found, flag this as requiring **immediate rotation** — the secret must be assumed compromised once it's been in version control
   139	- Historical secrets in git history remain accessible even after deletion from current files — git history rewriting or rotation is required
   140	
   141	## OWASP References
   142	
   143	- **A07:2021** — Identification and Authentication Failures
   144	- **CWE-798** — Use of Hard-coded Credentials
   145	- **CWE-312** — Cleartext Storage of Sensitive Information
   146	- OWASP Cheat Sheet: Secrets Management
   147	- OWASP WSTG-CONF-04: Review Old Backup and Unreferenced Files for Sensitive Information
