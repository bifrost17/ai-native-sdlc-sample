# TDD 스킬 조사와 spec·plan 책임 배치

2026-09-11 · 제작용 리서치. 활성 템플릿 변경이나 스킬 설치·실행 실험이 아니다.

**권고는 작은 자체 TDD 스킬이 반복 절차를 맡고, spec·plan에는 개발건별 구체적인 설계와 검증
계획을 남기는 것이다.** 정책에는 TDD 의무와 절차 연결을 짧게 둔다. 스킬만 설치하거나 문서마다
전체 절차를 복사하는 방식은 추천하지 않는다.

## 조사 결과의 적용 방향

- Matt·Kirjolab의 한 행동씩 진행하는 방식을 참고하되 실제 실패 확인과 REFACTOR를 보완한다.
- Superpowers의 예상 RED·최소 GREEN·테스트 품질 예시를 참고한다. 사전 구현 시 무조건 삭제·
  재시작이나 주변 오케스트레이션 전체를 기본 절차로 가져오지 않는다.
- Addy의 실제 저장소 검증 명령 사용, ECC의 계약/작업/검사 연결, Glebis의 테스트 약화 방지에서
  필요한 요소를 취한다. 고정 coverage 수치·별도 상태 원장·cycle마다 다중 에이전트를 기본화하지 않는다.
- spec은 테스트 가능성과 중요한 설계를 구체화한다. plan은 실제 테스트 경로·먼저 확인할 행동·
  PR 통합 검증을 명시한다. 기존 feature 예시의 구현→테스트 순서는 보강 대상이다.

북극성은 버그 수정의 test-first와 개발 중 피드백을 직접 제시한다. 새 기능까지 TDD를 필수화하는
것은 이번 사용자의 팀 정책 선택이다. 과거 조사와 북극성 원문을 이 선택에 맞춰 다시 쓰지 않는다.

## 원문 보존

`references/<후보>/source/<상류 경로>`에 선택 원문 40개를 보존했다. 6개 저장소의 MIT LICENSE와
Kirjolab 내부의 Matt 저작권 고지도 포함한다. 상당한 분량을 재사용할 때 해당 고지를 함께 유지해야 한다.
Kirjolab은 Matt 이전 판의 현지화 사례이므로 여섯 후보가 여섯 독립 방법론을 뜻하지 않는다.

원문은 고정된 default-branch 커밋의 스냅샷이며 stable release 순위나 인기도 추천 목록이 아니다.
파일 크기·필수 단계·호출 구조는 부담의 단서이고 실제 토큰·실행 시간 측정값은 아니다.
선택 아카이브는 완전한 설치 패키지가 아니며 보존된 스크립트는 실행하지 않았다.

조사 자료 40개의 SHA256·바이트를 다운로드 원문과 재대조했다. 기존 `make check`도 수행했다.
검사 결과와 자문은 이 설계대로 에이전트가 TDD를 수행했다는 증거가 아니다. 행동 실험은 후속 작업이다.
