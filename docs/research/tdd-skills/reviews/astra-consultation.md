# Astra 독립 자문 요약

2026-09-11 · gpt-6-astra / ultra. root가 자문 결과를 요약했다. 원문 축자가 아니다.
읽기만 수행했으며 설치·템플릿 수정·실행 실험의 통과 판정은 하지 않았다.

## 최초 독립 의견

TDD의 주 소유자는 작은 스킬이 적합하다. spec/plan에는 일반 절차를 중복 보관하지 않고 이번
개발건의 행동·계약·경계와 실제 테스트·파일·순서·통합 증거를 남겨야 한다. 팀의 의무는 항상
읽는 지침에서 짧게 선언한다. 스킬만으로 누락된 기능별 검증 계획을 대신할 수는 없다.

현재 feature plan 예시는 구현 후 테스트를 추가하도록 쓰여 있다. 스킬만 추가하면 상충하므로
보강 시 예시도 함께 수정해야 한다. bug-only test-first의 기존 지침과 새로운 팀 선택은 구분한다.
일반 기능에 fix 보호 모드를 켜면 새 테스트 작성이 차단되므로 그 모드를 확장해서는 안 된다.

spec은 테스트 가능하게 만들되 모든 내부 클래스를 먼저 확정할 필요는 없다. 공개 계약 중심은
모든 테스트를 E2E로 만들라는 뜻도 아니다. plan의 네 정보 역할을 유지하면서 행동별로 무엇을
먼저 확인할지 구체화하면 된다. 실제 실행 근거는 PR/실행 기록에 두고 plan에는 매 cycle 장부를
추가하지 않는 편이 좋다.

작업 브랜치 RED와 main GREEN은 양립한다. 하나의 PR에 RED 재현 커밋과 GREEN 수정을 담을 수 있다.
일반 기능에 테스트별 커밋이나 PR을 강제할 이유는 없다. 순수 리팩터링·이미 통과하는 테스트에
억지 RED를 만들지 않으며, 정당한 계약 변경의 테스트 수정과 기대값 약화를 구분해야 한다.

가장 강한 반론은 스킬이 실행 순서를 보장하지 못한다는 것이다. 긴 문서나 실행 가능한 명세도
이 문제를 자동 해결하지 못한다. 기존 실행 근거·PR 리뷰와 사람 판단을 유지하라는 의견이다.

## root 초안 후속 검토

대상: `responsibility-design.md`, `comparison.md`.

1. **스킬 누락 fallback이 불명확:** 기본 지침에 최소 test-first 규칙을 둔다고 했지만 실제 문장이
   없었다. root는 의도한 RED 실행→같은 기대를 유지한 최소 구현·재검증→필요한 정리·회귀 검증의
   제안 문구를 추가했다. 자료 누락과 실행 환경 부재도 구분했다.
2. **예시 축약으로 계약 누락:** 같은 AC 번호를 사용하면서 null/미배정 표시와 I/O 회귀를 생략해
   얇은 계획을 이유로 계약을 줄이는 예시처럼 읽혔다. root는 원 spec 전체의 발췌임을 명시하고,
   완료 포함·null 비일치·`-`·I/O 실패 검증을 다시 넣었다.

그 밖의 책임 분리와 실제 자료 참조에서는 실질적인 오류를 지적하지 않았다. 이 의견은 에이전트가
이 설계대로 행동했다는 증거가 아니며, root가 수정한 최종 문구를 별도 행동 실험한 것도 아니다.
