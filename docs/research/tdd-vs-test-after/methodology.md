# 조사 방법과 근거 해석

조사 기준일은 2026-09-12다. 공개 연구·개발 기록을 조사했으며 자체 에이전트 비교 실험이나 대상 저장소의 테스트를 실행하지 않았다. 공개 실험 결과의 재집계와 문서·출처 검증만 수행했다.

## 질문과 증거 축

질문은 에이전트 개발에서 테스트 작성 순서가 최종 정확성·개발 및 수정 비용에 어떤 영향을 미치는가다. 유명 프로젝트의 채택 여부는 적용 맥락이며 효능의 인과 증거가 아니다.

| 증거 축 | 확인하는 것 | 확인할 수 없는 것 |
|---|---|---|
| 공식 기여·테스트 지침 | 공개적으로 요구하거나 권하는 규칙 | 모든 기여자가 실제로 따르는지 |
| 유지관리자·실무자의 설명 | 의도, 경험, 예외, 구체적인 작업 사례 | 전체 프로젝트의 사용률·인과 효과 |
| PR·커밋·CI | 공개 브랜치에서 관찰 가능한 코드·테스트·실행의 순서 | 공개 이전 로컬 작업 순서, 정리된 커밋의 원래 순서 |
| 통제 실험·ablation | 해당 비교군·모델·과제에서의 결과 차이 | 바뀐 요소가 여러 개일 때 테스트 순서만의 효과 |
| 커뮤니티 | 반례·문제 제기·추가 원자료의 발견 | 독립적으로 검증된 효능 |

TDD는 작은 동작별 실패 확인→최소 구현→통과→정리의 반복으로 정의한다. 전체 테스트를 먼저 만드는 방식은 test-first이지만 반드시 TDD는 아니다. 구현 후 테스트는 작은 동작별 반복과 전체 구현 후 일괄 테스트를 구분한다. 기존 테스트를 먼저 읽는 것, 임시 재현 스크립트를 먼저 실행하는 것, 테스트 작성 의무도 별도로 기록한다.

## 문헌 탐색과 채택

검색어 `test-driven development`, `test-first`, `test-last`, `test-after`, `LLM`, `coding agent`, `controlled experiment`를 조합하고, 검색 결과의 원 논문·부록·저장소·데이터를 따라갔다. 에이전트 직접 비교를 우선하고 사람 대상 실험·메타분석으로 배경을 보완했다. 개선·무효·악화 결과를 모두 포함했다. 최근 에이전트 논문에는 심사 전 원고가 많으므로 학회 출판 여부와 버전을 구분한다.

비교군에 없는 테스트 도구·반복 실행·추가 컨텍스트를 실험군에만 주었다면, 개선을 TDD 순서만의 효과로 귀속하지 않는다. 자체 생성 테스트·자체 LLM 판정과 숨겨진 외부 평가를 구분한다. 공개 test set을 입력에 제공한 결과는 표준 벤치마크 결과와 나란히 순위화하지 않는다. 실패한 평가 사례를 분모에서 제외했는지 확인한다.

이 조사는 모든 데이터베이스에 대해 사전 등록한 체계적 문헌고찰이 아니다. 서로 다른 과제·모델·비용 정의의 수치를 통합해 단일 평균 개선율을 만들지 않는다. 같은 연구의 개정판이나 겹치는 실험을 독립 증거로 세지 않는다.

## PR 표본과 분류

대상은 Django, Rails, React, Next.js, GitLab, OpenHands, SWE-agent, Superpowers다. 2024-09-12~2026-09-12 병합 기록에서 신규 기능·버그 수정·리팩터링별로 저장한 검색 후보 안에서 병합 시각이 최신인 2건을 기본 표본으로 삼고, 기본 6건 중 4건 이상 순서 불명이면 유형별 다음 1건을 추가하는 규칙을 사용했다. 봇·문서 전용·자동 생성 변경은 제외한다. 유형은 제목·본문·실제 변경의 주된 목적을 함께 보고 분류한다. 검색·목록 API의 조회 범위와 구체적 제외 사유는 상세 조사와 후보 JSON에 남긴다. 일부 후보 목록은 첫 100건이며 리팩터링에는 제목 검색도 사용했다. 전체 24개월 모집단을 완전히 열거하지 않았으므로 실제 최신 적격 PR의 누락 가능성이 있다.

| 분류 | 허용하는 해석 |
|---|---|
| 테스트 선행 + 의미 있는 실패/후속 통과 확인 | 공개 기록에서 test-first 실행 흐름을 확인 |
| 테스트 커밋 선행, 실패 실행 미확인 | 공개 커밋 순서만 확인 |
| 구현 커밋 뒤 테스트 추가 | 공개 커밋에서 code-before-test. 로컬 작업 순서 미확정 |
| 코드·테스트 같은 커밋 / 혼합 | 순서 불명 또는 동작·계층별 순서 상이 |
| 기존 테스트 유지 / 새 테스트 없음 | 해당 변경의 사실. TDD 여부는 별도 |
| 기록 부족 | 판정 불가 |

head CI 성공은 앞선 테스트가 의도한 이유로 실패했다는 증거가 아니다. 환경·의존성·lint 오류로 실패한 CI를 RED로 인정하지 않는다. squash·rebase·force-push는 관측 가능성을 줄이며, 기존 테스트로 보호되는 변경도 존재한다. 이 표본으로 프로젝트 전체 또는 오픈소스 전체의 TDD 사용률을 추정하지 않는다.

## 브라우저 확인과 보관

Aside 브라우저로 HN 두 스레드와 Reddit 한 스레드의 본문·댓글을 실제 열람했다. 최초 Aside 에이전트 호출은 계정에 지정 모델이 없어 실행되지 않았고, 이후 Aside REPL의 브라우저 snapshot으로 확인했다. 성공/실패 기록을 분리해 보관했다. 로그인·댓글 게시·추천은 수행하지 않았다.

핵심 공개 원문은 `originals/`, API·실험 집계 근거는 `data/`에 저장했다. 원문, PDF 추출 텍스트, 브라우저 snapshot은 보관 형식이 다르므로 원문 목록에서 구분한다. Git 문서는 고정 커밋, 논문은 가능한 명시적 버전을 사용한다. 웹 HTML 보관은 사이트 전체의 오프라인 미러를 뜻하지 않는다.

검토에서는 수치의 분모·비교군·독립 판정 기준·출처 연결과 반대 근거 누락을 확인한다. 최종 권고는 연구 결과와 구분한 적용 판단이며, 문서 다운로드·공개 데이터 재집계는 원 실험의 재현 성공으로 표현하지 않는다.
