화면에 각각 한 번만 나온다.\n\n- 버튼 라벨: **「청구 철회」**\n\n### 5.2 확인 단계 (U4)\n\n별도의 확인 대화상자. 무엇이 일어나는지 · 그 결과 · 되돌리는 길을 함께 적는다.\n\n| 자리 | 문구 |\n|---|---|\n| 제목 | 청구를 철회하시겠습니까 |\n| 본문 1 (무엇) | 청구 ⟨2026-0001⟩ 의 심사를 중단하고 청구를 철회합니다. |\n| 본문 2 (결과) | 철회하면 이 청구의 심사는 더 진행되지 않습니다. |\n| 본문 3 (되돌리는 길) | **⟨결정 대기 #2⟩** — 예: 「철회 후 ⟨N⟩일 이내에는 고객센터(⟨전화번호⟩ · ⟨운영시간⟩)를 통해 되돌릴 수 있습니다.」 |\n| 실행 버튼 | 청구 철회 |\n| 닫기 버튼 | ⟨결정 대기 #3⟩ — 잠정 「돌아가기」 |\n\n- 실행 버튼은 동작 이름을 그대로 쓴다. 「예/아니오」 · 「확인/취소」 는 쓰지 않는다.\n- **파괴적 버튼은 기본 포커스가 아니다** — 대화상자를 열면 포커스는 제목으로 간다.\n- 본문 3 은 U4 의 절반이다. 「되돌릴 수 없습니다」로 끝내면 정책 위반이다.\n\n### 5.3 결과 화면\n\n| 자리 | 문구 |\n|---|---|\n| 상태 | **⟨결정 대기 #1⟩** — 다섯 어휘 밖. 여섯 번째 어휘를 만들지, `종결` 에 흡수시킬지는 오너 결정 |\n| 「다음 예정」 (U2) | ⟨결정 대기 #1 과 함께⟩ — 예: 「⟨무엇이 언제 일어나는지⟩」 |\n| 되돌리는 길 (U4) | 확인 단계와 같은 안내를 결과 화면에도 둔다 — ⟨결정 대기 #2⟩ |\n\nU2 는 상태 낱말과 「다음 예정」 한 줄을 한 덩어리로 요구한다. 맨 배지 · 맨 낱말만 두는 화면은 없다.\n\n### 5.4 실패 문구 (U1 — 무엇이 안 됐는지 · 왜 · 다음 행동)\n\n1. **상류 타임아웃 / 알 수 없는 실패** (원인은 시스템도 모르므로 「왜」를 비운다)\n   > 청구를 철회하지 못했습니다. ⟨N⟩분 뒤에 다시 시도해 주세요. 계속 실패하면 고객센터(⟨전화번호⟩ · ⟨운영시간⟩)로 문의해 주세요.\n   - ⟨N⟩ · 전화번호 · 운영시간은 오너 값(§8-4). 「잠시 후」로 대체할 수 없다(U3).\n2. **세션 만료**\n   > 청구를 철회하지 못했습니다. 로그인이 만료되었습니다. 다시 로그인한 뒤 철회를 진행해 주세요.\n3. **없는 청구 · 권한 없는 청구** — 두 경우에 **똑같은 문구**를 쓴다(S6)\n   > 청구 내역을 찾을 수 없습니다. 청구 번호를 확인한 뒤 다시 조회해 주세요.\n4. **철회 불가 상태**\n   > 청구를 철회할 수 없습니다. 이 청구는 「⟨지급완료 | 종결⟩」 상태입니다. ⟨다음 행동 — 결정 대기 #5⟩\n5. **이미 철회된 청구(중복 제출)**\n   > 이 청구는 이미 철회되었습니다. ⟨되돌리는 길 — 결정 대기 #2⟩\n6. **상세 조회 실패**\n   > 청구 상세를 불러오지 못했습니다. ⟨N⟩분 뒤에 다시 시도해 주세요.\n\n`ERR_CLAIMS_CORE_TIMEOUT (500)` 같은 내부 코드 · 상태 코드 · 상관관계 ID 는 화면에 넣지 않는다.\n그 값은 로그·감사 기록에만 남긴다(U1 · C3).\n\n### 5.5 대기 문구 (U3)\n\n- 철회 요청 전송 중:\n  > 청구 철회 요청을 보내는 중입니다. 보통 ⟨N⟩초 걸립니다.\n- 결과를 화면이 아니라 통지로 알린다면:\n  > 철회 결과는 ⟨채널⟩ 으로 ⟨시점⟩ 에 알려 드립니다.\n- 「잠시만 기다려 주세요」 단독 금지. 「처리 중입니다」도 안 된다 — 「처리중」은 B4 금칙 동의어다.\n\n### 5.6 통지 (C4 · C5)\n\n- 수신 동의가 기록된 채널로만 보낸다. 동의 상태를 확인하지 못하면 보내지 않는다(C4).\n- 본문에는 근거(어느 청구 · 어떤 상태 변경)와 문의 경로만. 사유 상세 · 금액은 싣지 않는다(C5).\n- 본문에도 U2 가 적용된다 — 상태 낱말 + 「다음 예정」 한 줄.\n\n---\n\n## U4(되돌리는 경로)다.\n- **C3** 로그 · 오류 메시지 · 감사 이벤트에 PII 없음. 식별자는 청구 번호와 내부 ID.\n  **철회 사유를 받지 않는 이유가 이것이다** — 자유 입력은 PII 를 끌고 들어오고, 그 값이 로그·감사로 흘러가면 C3 위반이 된다.\n  사유를 꼭 받아야 한다면 C2 근거 조항과 함께 다시 설계한다.\n- **C4** 철회 통지는 동의가 기록된 채널로만. 확인 못 하면 보내지 않는다.\n- **C5** 통지 본문 = 근거 + 문의 경로. 사유 상세 · 금액 산정 근거 없음.\n- **C6** 감사 기록: 누가(role=customer · 내부 ID) · 무엇을(청구 번호) · 언제(UTC). 보존 3년.\n- **C7** 이번 판은 본인 철회만이라 대리 조회 경로가 없다. 사정인·상담사 대리 철회를 열면\n  본인확인 기록 ID 를 함께 남겨야 한다 — 범위 밖.\n\n---\n\n## 8. 정책 오너에게 묻는다 (이게 닫혀야 spec 이 닫힌다)\n\n1. **철회된 청구의 상태 어휘.** B4 는 다섯 개로 못박고 「철회」는 그 안에 없다.\n   여섯 번째 어휘를 만들 것인가, `종결` 에 흡수시킬 것인가. 흡수시킨다면 「다음 예정」 줄에 무엇을 적는가.\n   (S4 README 「정책 오너에게 묻는다」 1번과 같은 질문 — 이번에 실제로 걸렸다.)\n2. **되돌리는 경로.** U4 는 확인 단계 **와** 되돌리는 길을 함께 요구한다. 철회에 무엇을 인정하는가 —\n   실제 취소 유예 기간(길이 명시)인가, 재신청 절차인가, 상담사 조작인가, 고객센터 경로인가.\n   (README 7번.) **없다고 답할 수는 없다 — 없으면 U4 를 못 지킨다.**\n3. **버튼 낱말.** 대화상자를 닫는 「돌아가기」와 업무 동작 「청구 철회」가 한 화면에 있다.\n   닫기 버튼에 「취소」를 쓰면 「청구 취소」와 섞인다. 어떤 낱말을 쓰는지는 U4 도 B4/B5 도 정하지 않는다.\n4. **U3 · U1 에 넣을 수치.** 재시도 간격 ⟨N⟩분 · 철회 전송 소요 ⟨N⟩초 · 고객센터 전화번호와 운영시간.\n   그리고 **S5 예산 계산에 넣을 예상 철회 요청률(rps)**. 근거 없는 값은 쓰지 않는다.\n5. **철회 불가 상태의 다음 행동.** `지급완료`·`종결` 청구에 대해 고객이 할 수 있는 일이 무엇인가(이의 절차 등).\n   U1 은 「다음에 할 행동」을 요구하는데 지금 그 자리가 비어 있다.\n6. **장식 아이콘.** `/img/doc.png` 에 붙일 뜻이 없다면, U6 의 「모든 아이콘·이미지」에 장식용 예외(빈 alt)를\n   둘 것인가.
