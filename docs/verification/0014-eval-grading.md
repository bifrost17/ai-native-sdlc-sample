# 0014 — 우선순위 3: 실제 assertion 채점과 오류 구분

구현 핀 `fb87006`. 범위는 제작 저장소의 평가기 보완이다. 가벼운 사용 템플릿에는 이 평가기나
새 검증 스크립트를 넣지 않았다. 정제 근거는 [0014-grading-evidence.json](0014-grading-evidence.json),
원래 생성 결과는 [0013-policy-evidence.json](0013-policy-evidence.json)에 보존한다.

## 변경과 판정

`check.sh`는 grep의 일치·불일치·오류를 구분한다. 잘못된 정규식이나 읽기 오류가 금지 패턴의
‘없음’으로 접혀 통과하던 경로는 판정 불가(rc=2)다. `make evals`는 생성 후 결정론 검사와
독립 Sonnet·low assertion 채점을 모두 실행한다. 근거 없는 인용·누락·모델 오류도 rc=2이며,
실제 의미 위반은 rc=1이다. 실패 뒤에도 다른 케이스를 실행하고 전체 케이스를 분모로 집계한다.
기존 기본 호출은 호환을 유지하되 결정론 전용·assertions 미채점을 명시한다.

네 부분 사례에는 단계에 맞는 스킬 선택·성공한 읽기/호출·산출물 적용도 포함했다. 특정 이름을
언급한 것만으로 통과시키지 않는다. 사례 04의 ‘전체 스킬 목록에 적용 판단’은 해당 제작 사례의
요구이며, 일반 사용 템플릿이나 전체 프로세스 실험에 강제하는 규칙이 아니다.

## 실제 Sonnet·low 결과

| 실행 | 결과 | 의미 |
|---|---|---|
| 원래 0013 산출물 재채점 1 | 판정 불가, rc=2 | 모델의 인용에 존재하지 않는 문장이 있었다. 거짓 통과를 차단했다. |
| 지시 보완 뒤 재채점 2 | 판정 불가, rc=2 | 누락 스킬은 발견했으나 떨어진 목록 항목을 한 인용으로 합쳤다. |
| 근거를 읽기 쉬운 줄 단위로 제공한 재채점 3 | 5 pass / 1 fail, rc=1 | 인용 검증 통과. 원본 spec의 전체 스킬 적용 판단 누락을 실제 실패로 남겼다. |
| 손으로 만든 한국어 JWT 양성·음성 대조 | 1 pass / 1 fail, rc=1 | 한국어 게이트웨이 JWT 인증 요구는 통과, JWT 단어가 있어도 익명 접근 허용은 실패했다. |

마지막 대조는 **합성 채점기 입력**이며 개발 에이전트의 실제 실행 증거가 아니다. 원래 spec을
수정하지 않았고 실패한 앞선 두 기록도 보존했다. 인용 검증은 그대로 두고 trace의 표현만
사람과 모델이 인용하기 쉬운 형태로 바꿨다. 채점기는 기대한 긍정·부정 구분을 보였으므로
우선순위 3의 보완은 통과로 판단한다. 사례 04 산출물 자체의 실패를 통과로 바꾸지는 않는다.

## 검증

수정 전 새 회귀 시험에서 실패를 확인했다. 기존 추적 테스트는 변경하지 않았다.

```text
make check → rc=0
Ran 81 tests in 16.539s
OK (skipped=1)
test_hooks: 28 passed, 0 failed
8 passed, 0 failed
PASS  managed-settings 키·훅 계약
```

별도 verifier는 Sol·high로 수행했다. 네 부분 보고:

1. **실행:** `make check` rc=0(81 tests, skip 1); 새 regex 9·assertions 10·runner 7 시험 각각 rc=0.
   Python 컴파일·Bash 구문·`git diff --check` rc=0. 기존 추적 테스트 불변 확인.
2. **관측:** 양쪽 검사와 실패 전파·분모 처리는 통과. 당시 실제 채점 2회는 인용 오류로 rc=2였다.
   잘못된 JSON을 보호 hook에 넣은 인접 흐름은 예상 rc=2와 `hook input is not valid JSON; refused`.
3. **계획 대조:** 당시 구현·검증 문서가 미커밋/미작성이라 계획 대조가 불완전했다. 구현은 `fb87006`,
   문서·근거는 이 기록의 커밋으로 연결한다. 이전 0013의 계획에서 CLAUDE.md·README.md가 누락된
   사실도 남겼다. 과거 계획을 소급해 고치지 않았다.
4. **미확인:** 실제 canonical 네 케이스 전체, 호스티드 CI, 조직의 승인·배포. verifier 뒤의 최종
   실제 대조는 위 표와 근거 JSON으로 root가 확인했고 전체 검사를 다시 실행했다.

macOS에서 대소문자를 구분하는 파일시스템 대조 1건은 실행 환경 때문에 skipped다. 모델 채점에도
오판 가능성이 남으므로 결과는 사람 판단의 근거다. 전체 SDLC 실험은 별도
[방법·데이터·페르소나](../experiments/README.md)에 따라 진행한다.
