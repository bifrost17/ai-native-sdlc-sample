## 핀과 인용

**인용은 `경로 + 축자 인용문`이다. 줄 번호는 쓰지 않는다.** 핀이 있으면 줄 번호는 군더더기다 —
위치는 인용문이 잡고, 번호가 필요하면 `git grep -F "‹인용문›" ‹핀› -- ‹경로›` 가 그 시점 값을 돌려준다.
결정적인 이유는 따로 있다: **줄 번호는 조용히 틀릴 수 있고 인용문은 그럴 수 없다.** v2 라운드에서
`docs/ADOPTING.md` 표에 행이 끼어들며 아홉 블록의 `:27`·`:28` 이 엉뚱한 행을 가리켰고,
`METRICS.md:69` 는 gate wait time 줄을 survival rate 의 근거로 인용했는데, 어느 것도 잡히지 않았다.

분량을 말하는 수(`CODEOWNERS` 27줄)는 위치가 아니라 사실이므로 남긴다.

핀은 **그 문면을 읽은 시점**을 말한다. 재판정은 **인용문이 사라졌을 때** 한다(문면이 바뀐 것이 신호).

- v2 `main@0daf655` · **v3 `main@5599dcf`**(현재 · 챕터 2~13 전부 이 핀)
- 실험 산출물(`docs/RUNS.md` · `intent/0002·0008·0009` · `evals/cases/04-*`)은 체인 0010 이 브랜치로
  뺐으므로 두 번째 핀 `experiment/2026-09-09-claims-status@cebc0e5` 를 쓴다.
- 라운드의 작업 목록: `git diff --name-only <이전 핀>..<새 핀>`. 그 목록에 없는 파일로 간 인용은
  손대지 않는다. 어느 챕터가 어느 라운드에 있는지는 `CHAPTERS.md` 가 정본이다.
- 블록 본문은 **누적하지 않고 교체한다** — `템플릿`·`실험` 문단은 늘 마지막 라운드의 실측만 담는다.
  라운드별 이력은 `CHAPTERS.md` 의 `· vN` 행이 진다. 판정이 바뀐 경우에만 summary 에
  `이전 → 새` 로 전이를 남긴다(예 `V2-07`, `V2-05`).

## 방식
# ai-native-sdlc-sample 검증 — 플레이북 문단별 증거 주석

`bifrost17/ai-native-sdlc-sample (옛 이름 intent-sdlc-sample)` 이 AI-Native SDLC Playbook 이 지향하는 방향대로 도는지를,
플레이북 한국어판 문서의 **가이드 문단마다 증거를 삽입하며** 검증한 기록이다.
플레이북 자신이 검증 기준이다 — 별도 점검표를 만들지 않는다.

- `source/playbookkoen3.html` — 원문(개인 열람용 사본 · 무변경 · 이 레포는 비공개).
- `playbook-annotated.html` — 원문 + 가이드 문단 아래 `<details class="verify …">` 블록.
  원문 문장은 한 글자도 바꾸지 않는다; 서술 문단은 비워 둔다.
- `CHAPTERS.md` — 챕터별 집계와 반영 PR.
- `INDEX.md` — 검증 항목 ID 색인. ID = `V<챕터>-<문서 순서>`(예 `V4-07`), 주석판의 `#V4-07` 앵커이자 각 블록 제목의 링크.
  ID 는 삽입·치환 뒤 매번 문서 순서로 다시 매긴다 — 블록이 끼어들면 뒤 번호가 밀리므로, 라운드 사이 대조는 커밋 SHA 와 함께 쓴다.

블록 판정은 넷뿐: **충실** · **부분** · **팀 몫(미검증)** · **보완 필요**.
블록 = 템플릿 `경로:줄` 인용 / 실험(사슬·턴·raw·시각·PR) / 보완.
쓰다 드러난 빈틈이 템플릿 몫이면 그 자리에서 샘플 레포에 PR 을 내고 블록에 번호를 적는다 —
주석은 산출물이 아니라 검증 절차다. 이력은 이 레포의 커밋이다(챕터 하나 = 커밋 하나 이상).
