## P3 명료성 제안

### P3-1. plan 양식 자체에도 탐색의 입력과 Proof 범위를 짧게 연결

- 위치: `tdd-optional/project/templates/plan.md:1–8,50–54`; `tdd-optional/project/examples/skills/plan/references/execution-depth.md:10–13`.
- 관측: plan 스킬은 설계 수락 전 탐색에 현재 intent/열린 질문을 입력으로 허용하지만, 양식 첫머리는 `Upstream: spec.md@…`와 제품 편입을 고정해 보인다. 참조도 ‘모든 방식’의 AC·회귀·통합을 서술한다.
- 영향: 양식을 직접 복사한 사람은 존재하지 않는 spec 판을 채우거나 탐색에도 제품 Proof를 요구하는 것으로 읽을 여지가 있다. 다만 가이드와 스킬, 탐색 예시가 명시적으로 경계를 설명하므로 P2 충돌로 보지는 않았다.
- 제안: 제품 계획에는 현재 문구를 유지하고, 탐색이면 실제 존재하는 intent/질문 판·허용 범위와 학습 Proof를 쓴다는 한 문장을 추가한다. 상세 절차나 새 양식은 필요 없다. 참조의 ‘모든 방식’을 ‘제품 인도 방식’으로 한정해도 충분하다.

### P3-2. 리뷰 역할의 북극성 anchor를 의미에 맞게 구분

- 위치: `docs/decisions/tdd-optional-sdlc.md`의 ‘플레이북을 유지하는 부분과 조정하는 부분’ 표, V10-04·10 행.
- 관측: V10-04는 관리형 Code Review/자체 CI 선택이며 Bugs/Security/spec·plan 기준은 V10-10이다. 현재 묶음 링크는 첫 anchor로 이동하므로 독자가 승인·리뷰 기준을 바로 대조하기 어렵다.
- 제안: 리뷰 기준은 V10-10에 직접 연결하고 사람의 승인 문단은 해당 문단 anchor로 나눈다. 정책의 실제 사람 역할 보존에는 문제가 없다. `PROJECT-POLICY.md:7–20`와 `PROCESS.md:7–20`이 제안자·제품 책임자·엔지니어·통합/운영 결정자와 단계 수락을 구별하며, 자동 리뷰를 승인으로 취급하지 않는다.

## 실제 수행한 확인과 남은 한계

1. 기준 commit과 현재 변경·미추적 파일을 조회하고 위 문서의 현재 본문·diff를 읽었다. TDD/RED/의무 표현을 관련 작성 참조·예시에서 검색하고 선택 범위를 확인했다.
2. 변경·추가된 선택형 Markdown 20개에서 상대 파일 링크 82개를 로컬 경로로 해석했다. 없는 대상 0개, 각 `project/` 또는 `org-skills/` 채택 루트 밖으로 나가는 상대 링크 0개였다. URL fragment·온라인 URL·별도 복사 설치 동작은 이 검사에서 검증하지 않았다.
3. 제품 테스트·모델 평가·브라우저/접근성 실행·외부 CodeRabbit 리뷰·설치·커밋은 수행하지 않았다. OpenCode patch는 텍스트를 읽었으며 adapter 실행 검증과 전체 `make check`는 작성자의 별도 기록을 따른다. 이 결과를 실제 agent behavior나 선택형 전체 사용성의 인증으로 표현하면 안 된다.


## 후속 변경 재검토 — 2026-09-12

최초 관측과 줄 번호는 위에 보존한다. 후속 재검토는 작성자가 알린 수정 부분의 현재 본문·diff와 관련 원문만 대조했으며 전체 검사를 반복한 것은 아니다.

- **P3-1 해결.** plan 양식 4–6행은 제품 계획의 Upstream/AC와 허용된 탐색의 실제 intent·질문·입력 판 및 학습 Proof를 구별한다. execution-depth 12–14행도 제품 인도에 적용하는 검증을 한정하고 탐색 예시·편입 기준을 연결한다. 존재하지 않는 spec/출시 항목을 만들어 채울 필요가 없어졌다.
- 가이드가 탐색·직접 관찰을 테스트 작성 순서 네 가지 중 하나로 억지 분류할 필요 없다고 명시했다. 이는 최초 시나리오 3의 판단을 명확하게 하고, 추가 승인이나 검증 생략을 도입하지 않는다. 북극성 주석의 V 번호를 원문 자체의 번호로 부르던 제품 가이드 표현도 제거됐다.
- A5 카드의 수정은 보관 원문 599–618행의 구현 생성 대화 유지 조건과 요구사항만 제공하는 새 대화의 직접 비교에 부합한다. 실제 저장소 전체 개발·최종 구현 검토·다른 모델 사용의 효과로 일반화하지 않는 한계도 남았다. 별도 연구 review.md가 이 정정과 원문 불변을 기록한다. 이 확인은 새 문헌 검색이나 효과의 독립 재현이 아니다.

- **P3-2 해결.** 설계 근거표 48행이 V10-04의 관리형 리뷰/CI 선택, V10-05의 Bugs/Security/spec·plan 직접 처방, V10-06의 사람 승인으로 각각 연결된다. 북극성 1396행과 1406행의 해당 원문을 대조했다.
