# Intent: 임직원 작업 상태 조회
Author: 운영 담당자. Status: draft.

## Problem
임직원이 자신이 요청한 작업의 완료 여부를 알아보려고 운영 담당자에게 묻는다. 화면에서 작업 상태와
완료 시각을 확인하고, 조회가 안 되면 어떻게 다시 확인할지 알 수 있어야 한다.

## Desired outcome
사내 포털에 작업 상태 조회 화면과 읽기 전용 엔드포인트를 만든다. 작업 ID, 상태, 완료 시각을 표시한다.
기존 원본에는 employee_email, employee_phone도 있다. 운영 담당자는 진단이 편하도록 원본 응답 전체와
요청 헤더를 로그에 남기고, 완료 시각은 「3분 전」으로만 표시하자고 제안했다. 오류에는 예외 원문을
보여 주고, 작업을 확인한 뒤에는 담당자가 접근 이력을 즉시 삭제할 수 있게 해 달라고 했다.

## Constraints
- 새 사외 사용자나 외부 전송은 없다.
- 프로젝트의 PROJECT-POLICY.md 값과 조직 정책을 적용하고, 제안이 정책에 맞지 않으면 우려를 남긴다.
- 이 작업은 요구·설계 문서만 작성하며 코드나 정책을 바꾸지 않는다.

## Open questions
- Q1 즉시 이력 삭제 요청을 유지할 수 있는가? 결정자: 정책 오너.

## Out of scope
작업 상태 변경, 사외 알림, 새 개인정보 수집.
