# Spec: 플레이북 통제의 경로·배포·실행 연결 보완
Upstream: intent.md@ac4b5e8. Status: draft.
프로젝트 오너가 대화에서 제시된 보완안 중 1·2·4번을 우선 구현하라고 지시해 draft 체인에서 진행한다. 승인은 PR 머지로 기록한다.
## Requirements
- R1 보호 훅은 현재 작업 디렉터리와 실제 파일 대상을 기준으로 절대·상대 경로, `.`·`..`, 심볼릭 링크를 처리한다. 새 파일도 보호하며, 경로 판정 오류는 차단한다.
- R2 spec 지침은 세션에서 제공되는 로컬·플러그인 스킬을 확인하고 실제 읽은 파일의 출처와 판을 기록한다. 캐시에 Git 이력이 없다고 판을 지어내지 않는다. 해당 없는 스킬은 이유를 기록한다.
- R3 평가 CI는 조직 스킬·정책·템플릿·평가 및 배포 설정 변경을 포함하고, 실행기는 이 체크아웃의 조직 플러그인을 명시적으로 로드한다. 실제 정책 적용을 실행해 확인할 수 있는 평가 케이스를 둔다. 채점 종류나 의미적 채점은 바꾸지 않는다.
- R4 bands는 none/1σ에서 기록만, 2σ에서 저장소 읽기 전용 진단, 3σ에서 진단을 포함한 제안 초안을 생성한다. 2σ 진단 결과도 intent 형식의 별도 산출물로 기록할 수 있으나 코드 수정·PR 제안 권한을 부여하지 않는다. 모델 도구는 Read/Grep로 제한하고 산출물 기록은 실행 스크립트가 맡는다.
- R5 모델 미실행은 명시적으로 기록한다. 모델 실행·진단 산출물·초안 생성이 실패하면 비0으로 끝나며, 탐지 근거와 실패 기록을 CI artifact로 보존한다.
## Design
- 기존 훅의 공통 경로 처리에서 정규화한다. Bash 파일 쓰기를 전부 탐지하려는 검사는 추가하지 않는다.
- 조직 플러그인의 실제 위치와 설치 버전을 고려하도록 스킬 지침을 고치고 배포 버전을 올린다. 모델 로드와 실제 정책 적용 증거는 단순 파일명 검사와 구분한다.
- bands의 등급별 실행을 로컬에서 시험 가능한 스크립트로 추출하고 워크플로는 이를 호출한다. 기존 검출 규칙·통계 계산·승인 경계는 유지한다.
## Constraints
- C1 개선 3번(`evals/check.sh`의 정규식 판정, 의미적 assertions 채점)은 그대로 둔다.
- C2 북극성 원문은 보존하고 V6-14·V8-10·V3-01·V3-14·V9-07·V13-07·V13-09 등의 해당 주석에만 이번 근거를 보탠다.
- C3 승인·문서 형식·상태를 검사하는 새 통제는 만들지 않는다.
- C4 기존 테스트를 수정하지 않는다. 새 회귀 시험은 unittest 자동 탐색에 연결한다.
- C5 Python 표준 라이브러리·Bash 3.2, 자동 PR·머지·프로덕션 조작 없음.
## Acceptance criteria
- AC1 (R1) 경로 별칭·링크·새 파일 경로의 보호 위반은 차단되고 정상 편집·기존 훅 시험은 통과한다.
- AC2 (R2, R3) 로컬 및 플러그인 배포의 읽기·판 기록 안내가 실제 파일 구조와 일치한다. 가짜 CLI를 쓴 실행기 시험은 현재 플러그인이 전달됨을 확인하고, 실제 모델 평가 여부는 별도로 기록한다.
- AC3 (R3) 관련 경로만 바꾸는 PR이 평가 대상에 포함되며, 조직 정책 적용 케이스가 기존 채점기로 실행 가능하다.
- AC4 (R4, R5) none·1σ·2σ·3σ, 키 없음, 모델 실패, 초안 생성 실패를 로컬 워크플로 시험으로 확인한다. 2σ는 없는 초안 수정에 의존하지 않고 모델 쓰기 도구가 없다.
- AC5 (R1~R5) `make check` 전체 통과, 별도 verifier 보고, 북극성 주석의 관측 범위와 미검증 범위 구분.
## Skills applied
- `skill-creator` — 기존 스킬의 좁은 경로·출처 안내 수정에 적용. 세션 제공 시스템 스킬이며 프로젝트 정책으로 취급하지 않는다.
## Open questions from intent
- carried forward: 실제 모델과 호스티드 CI의 실행 증거는 이번 환경에서 가능한 범위만 확인한다(프로젝트 오너).
## Flagged concerns
- 모델을 대체한 CLI 시험은 실제 스킬 발화·정책 적용을 증명하지 않는다. 주석에서 로컬 통합 검증과 실제 모델 실행을 구분한다.
- 조직 플러그인은 캐시 배포에서 Git 이력이 없을 수 있다. 이 경우 설치 버전과 출처를 기록하며 확인하지 못한 SHA를 쓰지 않는다.
