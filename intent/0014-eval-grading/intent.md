# Intent: 에이전트 평가가 의미적 실패와 채점 오류를 실제 결과에 반영한다
Author: 프로젝트 오너 (요청자). Status: draft.
## Problem
현재 evals의 assertions는 산문으로만 남고 실행되지 않는다. 잘못된 정규식도 불일치와 같게 처리되어 regex_absent가 통과할 수 있다. 0013의 실제 Sonnet 결과는 인증 요구를 한국어로 썼지만 영어 문자열 검사에서 실패했다. 따라서 현재의 통과 수만으로 정책 적용과 채점기 정상 작동을 구분할 수 없다.
## Proposed outcome
각 assertion을 실제 산출물·입력·도구 기록으로 판정하고 근거를 보존한다. 평가 실패와 채점 불가를 구분하며, 전체 평가의 성공은 필요한 판정이 모두 실행되어 통과했을 때만 나온다.
## Affected users and systems
템플릿을 사용하는 팀, 평가 사례 작성자, 정책 오너, evals 실행기·채점기·CI와 북극성 평가 주석.
## Constraints
- C1 사용자가 앞서 제외했던 우선순위 3을 이제 보완하라고 지시했다. 0013에서 보완한 1·2·4는 유지한다.
- C2 북극성 V9-06·V9-07·V9-11·V9-12의 실제 평가와 실행 기록을 기준으로 한다. 일반 산출물의 승인·상태를 검사하는 새 통제는 만들지 않는다.
- C3 Python 표준 라이브러리·Bash 3.2를 사용하며, 기존 테스트를 바꾸지 않고 새 회귀 시험으로 증명한다.
- C4 실제 Claude 실행은 Sonnet·low를 사용한다. 생성과 채점은 분리하며 채점 모델에는 쓰기·실행 도구를 주지 않는다.
- C5 일부 단계 시험은 임시 워크스페이스에서 한다. 전체 프로세스 실험만 제작 자료를 뺀 실제 사용 템플릿 브랜치에서 파생하여 기록을 보존한다(사용자 후속 설명).
- C6 기존 실패 증거는 보존한다. 미실행·잘못된 입력·모델 오류를 통과로 표시하지 않는다.
## Open questions
- 호스티드 CI 및 전체 프로세스 실험은 이번 부분 검증과 구분한다. 필요한 환경·실험 범위의 결정자는 프로젝트 오너다.
