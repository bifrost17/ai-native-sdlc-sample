# Spec: 결정론 검사와 의미적 assertion을 모두 실행하는 평가
Upstream: intent.md@bcff43d. Status: draft.
프로젝트 오너가 우선순위 3의 구현을 직접 지시해 draft 체인에서 진행한다. 승인은 머지로 기록한다.
Skills applied: none — 이 변경은 제작 프로젝트 평가 실행기의 동작 보완이며 조직 정책 스킬을 적용했다고 주장하지 않는다.
## Requirements
- R1 정규식 검사는 grep의 일치(0)·불일치(1)·실행/구문 오류(그 외)를 구분한다. 잘못된 regex_present·regex_absent 및 검사 파일 읽기 오류는 판정 불가(rc=2)다.
- R2 각 assertion은 생성 모델과 다른 새 Sonnet·low 채점 세션에서 판정한다. 입력 픽스처·실제 출력·성공한 도구 기록·관련 정책 근거를 제공하고, 채점 모델에는 파일·실행·외부 도구를 제공하지 않는다.
- R3 각 assertion에 번호·pass/fail/undecidable·이유·출처 인용을 기록한다. 번호의 누락·중복, 잘못된 판정 형식, 존재하지 않는 출처 인용, 모델 오류·불완전한 trace는 rc=2다. 모든 assertion 통과만 rc=0이며 의미적 실패는 rc=1이다.
- R4 canonical `make evals`는 `evals/run.sh --semantic`을 실행한다. 같은 루프에서 케이스마다 생성 1회 후 결정론 검사와 의미적 채점을 모두 실행한다. 한쪽 실패가 다른 쪽을 숨기지 않으며 2 > 1 > 0 우선순위로 최종 종료한다.
- R5 각 실행의 케이스별 결과·모델 설정·근거·summary.json을 보존한다. 전체 케이스를 분모로 pass rate를 계산하며 판정 불가를 제외해 비율을 올리지 않는다.
- R6 기존 `run.sh` 기본 호출은 생성+결정론 검사 호환 경로로 남기되 의미적 채점 미실행을 명확히 출력한다. 기존 테스트와 유효한 결정론 검사 계약을 유지한다.
- R7 정책 인증 요구는 언어에 무관하게 의미적으로 판정한다. 사례 04의 `JWT` 식별자 검사와 실제 인증 요구의 assertion을 분리하여 한국어 표기도 평가한다. 인증을 제거한 출력은 단순 키워드가 있어도 의미적 검사에서 실패해야 한다.
## Design
- `check.sh`의 grep 종료 코드를 보존한다. 기존 5개 kind의 의미나 ERE 엔진은 바꾸지 않는다.
- `run.sh --semantic`은 stream-json으로 생성 기록을 받고, `record.py`가 결과 envelope와 상태·집계를 기록한다. 기본 경로는 JSON 출력 계약을 유지한다.
- `grade_assertions.py`는 임시 작업 디렉터리에서 도구 없는 독립 채점 세션을 실행한다. Python이 증거를 수집·검증·저장하며, 모델이 출력한 산출물과 도구 내용은 명령이 아닌 검증 대상으로 취급한다.
- 생성·채점은 Sonnet·low로 고정해 현재 사용자의 비용 선호를 따른다. 미실행이나 채점 한계는 결과에 드러낸다.
## Constraints
- intent의 C1~C6을 유지한다. 새 테스트를 추가하며 기존 테스트·기존 실패 증거를 고치지 않는다.
- 실제 전체 SDLC를 실행하는 것이 아니라 채점 단계만 부분 검증한다. 전체 프로세스용 실제 사용 브랜치는 제작 자산을 제외하고, 직접 만든 스킬만 선택적 예시로 둘 수 있다는 후속 사용자 지침을 따른다. 해당 브랜치 제작은 별도 작업 폴더에서 진행한다.
## Open questions from intent

## Flagged concerns
- LLM 채점에도 오판이 가능하다. 판정·근거를 검토 가능한 형태로 남기며 사람의 승인으로 취급하지 않는다.
- 기존 생성기 테스트가 기본 호출의 CLI 형식을 고정한다. 호환 경로를 숨은 우회로로 만들지 않도록 canonical 명령과 미채점 경고를 명시한다.
## Out of scope
- 제품 산출물의 승인·상태 전이 검사기, CI 비밀 설정, PR 생성·머지·배포, 전체 SDLC 프로세스 실험 실행.
## Acceptance criteria
- AC1 → R1 잘못된 두 regex kind, 선행 하이픈, 정상 일치/불일치와 검사 오류의 종료 코드를 새 회귀 시험으로 확인한다.
- AC2 → R2/R3 fake CLI로 모든 판정·오류·누락·중복·근거 인용·도구 경계와 원본 파일 불변을 확인한다.
- AC3 → R4/R5/R6 canonical 연결, 실패 전파·다음 케이스 계속 실행·집계와 기존 시험 전체 통과를 확인한다.
- AC4 → R7 실제 Sonnet·low 채점으로 한국어 인증 설명과 인증 부재 반례를 구별하는지 확인한다. 실제 판정 실패나 판정 불가도 그대로 기록한다.
- AC5 → R1~R7 별도 verifier와 원문 보존 비교 후 해당 북극성 주석의 근거를 갱신한다.
