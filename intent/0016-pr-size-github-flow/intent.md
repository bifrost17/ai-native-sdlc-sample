# Intent: AI 리뷰에 맞는 PR 크기와 GitHub Flow를 사용 템플릿에 포함
Author: 프로젝트 오너 요청, Codex 기록. Status: draft.
## Problem
현재 사용 템플릿은 한 변경의 단계 인계만 안내한다. 큰 요구의 계획을 여러 작업·브랜치·PR로 연결하는 기준이 없어 과도한 일괄 변경이나 형식적인 분할 모두 가능하다. 사람의 읽기 속도에 맞춘 과거 줄 수 기준을 AI 리뷰에도 그대로 적용할 근거는 확인되지 않았다.
## Proposed outcome
일차 연구와 실제 사례를 비교해 유연한 PR 크기 가이드를 만들고, GitHub Flow를 템플릿의 기본 브랜치 전략으로 명시한다. 실제 사용판에서 대화형 개발·검토·통합 실험을 실행하고 관측 범위만 북극성 주석에 반영한다.
## Affected users and systems
사내 동료용 소프트웨어를 개발하는 채택 팀, 사용 템플릿, 제작 저장소의 조사·실험 기록.
## Constraints
오너가 조사 후 정책 반영과 최종 실험까지 지시했다. 단계 초안에서 후속 작업을 진행할 권한을 위임받았으며, 이는 실제 조직의 PR 승인 기록을 대신하지 않는다. 얇은 정책과 사람의 판단을 유지하고 LOC 제한·새 승인 검사기·필수 특정 스킬을 추가하지 않는다. Claude Code는 Sonnet·low, 설계 검토는 이번 세션에 허용된 최고 수준을 쓴다. 기존 기준선과 실험 이력을 보존한다.
## Open questions
AI 전담 리뷰의 보편적 최적 PR 크기는 조사로 근거와 한계를 확인한다. 실제 조직의 권한 분리·운영 배포는 이 작은 실험이 증명할 범위를 벗어난다.
