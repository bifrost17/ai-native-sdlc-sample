# Intent: 후속 요구에서도 설계·계획을 최신 상태로 유지
Status: draft.

## Problem
사용자가 “plan spec이 업데이트 되지 않는다는건 큰 문제야”라고 지적했다. 0016 부분 실험에서
에이전트는 새 JSON 요구를 코드·시험·README에 반영했으나 spec/plan은 누락했고 완료를 보고했다.
HUMAN의 문서 수정 지시 후 복구됐다는 사실은 이 중요한 인계 실패가 해결됐음을 입증하지 않는다.

## Desired outcome
에이전트가 후속 요구·구현 발견을 해당 설계·계획의 변경 범위로 판단하고, 필요한 문서 갱신과
수락 판 연결을 완료 조건으로 다룬다. 사람이 문서 누락을 지적하기 전에 문서·코드가 일치해야 한다.

## Constraints
사내 동료용 얇은 템플릿, 영향받는 문서만 갱신, 기존 수락 반복 금지. 새 checker/hook/필수 스킬 없음.
Claude Code Sonnet·low로 실제 대화하며 원래 판·실패·환경 한계를 보존한다. root가 개선·검증을 판단한다.

## Success
지침 전달을 확인한 새 세션에서 업무 변경만 전달해 spec/plan 개정과 올바른 커밋 인계를 관측한다.
기존·새 동작이 맞고 문서 누락·허위 수락·잘못된 참조를 남긴 완료 보고가 없어야 한다.
