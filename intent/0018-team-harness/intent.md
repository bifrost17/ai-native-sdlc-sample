# Intent: 중요한 문서 인계를 실제 실행 과정에서 확인하기
Status: draft.

## Origin
사용자는 템플릿 지침의 실험 통과와 실제 팀의 검토 실행을 구분한 뒤 "목표 수정하고 달성시켜"라고
요청했다. HUMAN 역할의 Codex root에게 구현·설치·실험·판정까지 위임했다.

## Problem
지침만으로는 후속 업무 결정이 spec/plan에 반영되는지 보장할 수 없다. 이전 실행에서 코드와
시험만 갱신됐고 사람이 누락을 지적해야 복구했다. 독립 검토도 사람이 직접 호출하면 생략될 수 있다.

## Goal
팀이 사용하는 실행 진입점에서 개발 응답과 인도 사이에 독립 검토가 실제로 실행되고,
중요한 spec/plan 누락은 사람의 별도 문서 갱신 상기 없이 보완으로 이어지게 한다.
정상 질문·수락 대기·문서 변경이 필요 없는 작업을 방해하지 않는다.

## Constraints
- 북극성과 사내 서비스의 얇은 정책·에이전트 재량을 유지한다. 문서 의미·승인 상태를 정규식으로 판정하지 않는다.
- 사용 템플릿은 유지하고 실행 도구를 별도 팀 자산으로 제공·설치한다. 선택하지 않은 스킬을 강제하지 않는다.
- Claude 개발과 독립 검토는 Sonnet·낮은 추론을 기본으로 한다. HUMAN의 업무 결정·수락은 대체하지 않는다.
- 도구 미실행·오류·오래된 근거를 통과로 표시하지 않는다. 모든 개발 경로·의미의 무오류를 보장한다고 주장하지 않는다.

## Acceptance direction
실제 누락·형식적 수정·정상 작업·질문/수락 대기와 실패 인계를 확인하고, 실제 Claude 대화와
자동 검토/피드백·최종 산출물·중요한 회귀를 기록한다. 코드가 있다는 사실만으로 완료하지 않는다.
