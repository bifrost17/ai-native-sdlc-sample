# Spec: 이벤트 기반 문서 동기화와 완료 검토
Upstream: intent.md@c190fc7 (사용자가 설계·실험·반영을 위임). Status: draft.

## Requirements
- R1. `org-skills` 플러그인의 `sdlc-feedback` 스킬은 요구·설계 변경, 계획 이탈, 수락 판 변경,
  관련 커밋 준비, 구현 완료 보고, PR의 spec/plan 대조에서 사용을 인식한다. 질문·현황 조회는
  완료 검토로 취급하지 않으며 영향 없는 문서를 형식적으로 수정하지 않는다.
- R2. 최신 사람 합의와 현재 문서를 실제 구현·검증 근거와 대조한다. 과거 편집/검토 주장만으로
  현재 정합성을 인정하지 않는다. 필요한 spec/plan을 갱신하고 이미 받은 수락 판을 재질문하지
  않는다. 변경된 plan과 이유는 관련 구현과 같은 커밋에 담고 상류 수락은 프로젝트 정책을 따른다.
- R3. 작업 중에는 자체 피드백을 사용한다. 구현 완료 전에는 동등한 프로젝트 검증자 또는 기본
  팀 `sdlc-verifier`를 새 문맥에서 호출한다. 중요한 변경의 독립 검토에도 활용한다. 검증자는
  보고만 하며 개발 세션이 수정한다. 단순 문서 정정까지 독립 호출을 강제하지 않는다.
- R4. 검토는 기준부터 현재 작업 트리의 변경과 미추적 파일을 포함한다. 호출자는 업무 합의와
  수락, 기준·대상 경로와 검증 근거를 인계한다. 검증자는 현재 파일을 직접 읽고 중요한 누락과
  회귀를 확인한다. 서브에이전트 내부에서 운영 스킬/검토자를 다시 호출하지 않는다.
- R5. 모델·추론은 난도·영향·불확실성과 사용자 한도에 맞춘다. 여러 문서의 중요한 합의 대조에
  쓰는 기본 독립 검증자는 강한 모델·높은 추론을 사용하며, 작업 중 일반 구현은 Sonnet을 쓴다.
  도구가 없거나 검증이 실패하면 사실과 인계 사항을 남기며 미실행을 독립 검증 통과로 쓰지 않는다.
- R6. 원본·공통 검토 기준·기본 agent·출처·설치/갱신 안내를 같은 플러그인으로 배포한다.
  사용 템플릿에는 필수 스킬을 내장하지 않는다. 기존 PR 관리 스킬의 댓글/CI/push 루프와
  역할을 중복하지 않는다. 승인/병합은 사람과 프로젝트 권한에 남는다.
- R7. 기존 `sdlc-claude`는 0018의 별도 실험 실행 경로로 보존한다. 해당 입력 형식의 reviewer
  프롬프트를 새 스킬의 정본으로 확장하지 않으며, 설치 안내/목표에서 기본 팀 스킬 경로와 구분한다.

## Design
주 개발 세션에서 `sdlc-feedback/SKILL.md`를 읽고 이벤트에 맞는 작업만 수행한다. 공통 의미 판단은
`references/review-criteria.md`에 한 번 적는다. 네이티브 `sdlc-verifier` agent는 그 기준을 읽고
제한된 도구로 독립 검증한다. 별도 프로그램·hook·판정 JSON 스키마를 추가하지 않는다.
커밋 직전 및 후속 요구/수락 판 이벤트는 북극성의 같은 커밋·단계 인계를 실천하는 팀 선택이다.

## Acceptance criteria
- AC1 → R1/R6: 영구 설치한 새 일반 Claude Code 세션에서 스킬/agent 목록과 실제 읽기 경로·판을
  확인한다. 최소 두 자연어 업무 표현으로 사용을 관측하며 이름을 직접 지시한 시험과 구분한다.
- AC2 → R1/R2: HUMAN이 문서 갱신을 상기하지 않은 재개 대화에서 후속 요구·수락 판이 spec/plan에
  반영되고, 관련 구현과 계획이 같은 커밋에 담긴다. 정상 질문·현황 조회·문서 영향 없는 작업은
  불필요한 수정이나 독립 검토 반복으로 막지 않는다.
- AC3 → R3–R5: 실제 native Agent 호출·별도 문맥·현재 파일 읽기·검토 결과를 보존한다.
  자연 발견 또는 별도 통제된 문서 누락에 대한 검토/보완·재검증을 관측한다. 주입/명시 시험은
  자연 트리거 성공으로 계산하지 않는다.
- AC4 → R2/R4: PR 범위의 문서·diff 대조, 기존 제품 시험/fixture·인접 동작, 전체 인계 범위를
  평가한다. 기존 고정 설명은 불변 확인으로 재사용하고 실험 범위 밖 운영은 미관측으로 남긴다.
- AC5 → R6/R7: 설치 검증·제작 `make check`·독립 verifier를 통과하고, 실제 기록을 실험 브랜치에
  보존한다. 북극성 원문과 이전 실패를 보존하며 새 관측만 주석에 반영한 뒤 로컬 main에 통합한다.

## Risks
스킬 미호출, 개발 가정의 재사용, 미커밋 변경 누락, 질문을 완료로 오인, 불필요한 승인/반복 검토,
설치 메타데이터만으로 실제 로드를 주장하는 위험을 본다. 이 실험은 무오류나 일반 성공률을 증명하지 않는다.
