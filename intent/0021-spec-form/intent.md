# Intent: 사람과 에이전트가 함께 검토하고 계획할 우리 spec 양식
Author: 프로젝트 오너의 요청을 정리한 Codex root. Status: draft.

## Problem
intent 양식 작성 이후 요구사항·설계 spec 양식을 만들 차례다. 현 양식은 Design을 한 줄로 안내하고,
질문과 우려를 intent의 질문·정책 충돌에 좁혀 표현한다. 선택 이유, 유지할 동작, 중요한 실패 상태가
작성자의 추측에 남을 수 있다. 큰 RFC나 SDD 양식을 통째로 가져오면 반대로 사내 개발에 과해진다.

## Proposed outcome
북극성의 요구·설계 통합 취지에 맞춰 사람이 중요한 결정을 검토하고 에이전트가 구현 계획을 세울
spec 양식을 만든다. 조사 결과와 설계 방향을 다시 정독하고 충분히 검토한다. root가 작성하며
이전 intent 작업처럼 Astra와 Claude Code Fable의 독립 리뷰를 받고 중요한 지적을 보완한다.

## Affected users and systems
사내 서비스를 개발하는 팀, spec 작성자·제품 오너·계획 작성자, templates/spec.md와 design-spec
작성 지침, 관련 기존 평가 입력. 선택 팀 스킬과 실제 사용판의 배포 경계도 함께 확인한다.

## Constraints
- Anthropic Playbook이 최우선이며 우리 주석과 타 프로젝트의 절차를 원문 요구로 간주하지 않는다.
- 정책과 기본 양식은 얇게 유지한다. 상세도는 결정·영향·불확실성에 맞추고 사람의 판단을 남긴다.
- root가 양식과 예시를 작성한다. 리뷰어는 읽고 보고하며, 설계에는 높은 모델과 추론을 사용한다.
- plan 사용 양식 재설계, 새 문서 의미 검사기, 상태 엔진이나 필수 외부 스킬은 추가하지 않는다.

## Open questions
어떤 공통 항목과 조건부 상세가 충분한지, 현재 소비자와 사용판에 어떤 동시 수정이 필요한지는
조사·예시·독립 리뷰로 root가 판단한다. 이는 사용자에게 추가 승인을 요청할 미결 조건이 아니다.
