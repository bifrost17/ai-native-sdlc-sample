# Intent: 작은 PR로 실행하고 바뀐 판단을 이어받는 우리 plan 양식
Author: 프로젝트 오너의 요청을 정리한 Codex root. Status: draft.

## Problem
intent·spec 양식 다음으로 실행 계획 양식을 완성할 차례다. 기존 네 절은 플레이북과 가깝지만
파일·순서·검증의 연결이 약하고, 제작 스킬의 문서별 merge 수락과 일률적인 실패 테스트 순서는
현재 GitHub Flow 정책 및 원문의 적용 범위와 어긋난다. 큰 요구가 큰 PR로 굳어져서도 안 된다.

## Proposed outcome
조사 결과와 북극성을 정독해 기존 설계 방향을 되살리고, 사람과 에이전트가 대화 없이도 실행·검토할
plan 양식을 만든다. 작은 작업은 짧게, 여러 PR이나 병렬 작업은 각 통합 뒤 동작·의존·검증이
드러나게 한다. root가 작성하고 강한 독립 설계 리뷰와 좁은 실제 실행으로 충분함을 판단한다.

## Affected users and systems
사내 서비스 개발자·계획 작성 에이전트·리뷰어, templates/plan.md와 작성 스킬, 계획 소비자,
별도 사용 템플릿의 선택형 예시. 기존 intent·spec 양식과 브랜치·PR 정책은 연결 기준이다.

## Constraints
북극성이 최우선이다. 얇은 양식과 상황별 상세를 유지하고, 새 상태 엔진·문서 의미 검사기·필수 외부
스킬을 만들지 않는다. 작업·커밋·PR·에이전트를 일대일로 묶지 않는다. 실제 실험은 초기 사용판에서
파생해 보존하며 HUMAN 개입과 미검증 범위를 숨기지 않는다.

## Open questions
네 정보 역할 안에서 충분한 PR·인계 상세를 어떻게 배치할지는 예시·대안 비교·리뷰로 root가 결정한다.
사용자가 이미 요청한 설계·반영 범위이며 추가 승인 요청을 위한 미결 조건은 아니다.
