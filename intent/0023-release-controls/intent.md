# Intent: 작은 PR로 통합하면서 미완성 기능은 테스트 대상에게만 공개
Author: 프로젝트 오너의 요청을 정리한 Codex root. Status: draft.

## Problem
항상 배포 가능한 main에 여러 PR로 기능을 통합할 때, 개발 중인 기능을 일반 사용자에게 열어서는
안 된다. 매번 PR 전에 노출 코드를 지우고 테스트 때 복원하는 방식은 반복 비용과 실수를 만든다.

## Proposed outcome
널리 쓰이는 방법과 실제 사례를 조사하고, 배포와 기능 공개를 분리하는 얇은 정책을 양식·스킬·
사용판에 연결한다. 같은 제어를 유지한 채 테스트하고, 합의된 공개 단위의 완료 후 공개한다.

## Affected users and systems
사내 제품 개발자·에이전트·운영 담당자, GitHub Flow 및 PR 크기 정책, spec·plan 작성과 리뷰.

## Constraints
북극성의 사람 판단·작은 통합·검증 흐름이 우선이다. 모든 변경에 플래그를 강요하거나 SDK·서비스·
새 의미 검사기를 만들지 않는다. 실제 실험은 사용 템플릿에서 파생하고 대화·결과·한계를 보존한다.

## Open questions
상황별 제어 선택과 최소 기록은 조사 및 독립 리뷰로 root가 결정한다. 사용자 요청 범위의 위임이다.
