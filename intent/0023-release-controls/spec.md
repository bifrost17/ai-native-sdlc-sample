# Spec: 배포와 기능 공개를 분리하는 조건부 지침
Upstream: intent.md@2214490. Status: draft.
Skills applied: skill-creator, 로컬 시스템 SKILL.md를 2026-09-11 읽고 적용; 버전 표기 없음.
사용자의 조사·적용 위임으로 draft에서 진행한다. 실제 제품 공개 승인을 뜻하지 않는다.

## Requirements
- R1: 공개 단위가 미완성인 동안 일반 사용자 OFF와 선택한 테스트 ON을 함께 지원한다. 독립적으로
  완성·수락된 다른 공개 단위는 먼저 제공할 수 있다. main의 빌드·기존 동작·호환성은 계속 유지한다.
- R2: 단기 release flag 등 상황에 맞는 방법을 안내한다. 같은 제어와 외부 설정을 PR 사이에 재사용하며,
  초기 도입·필요한 수정·최종 제거 외에 테스트/공개 전환마다 소스 코드를 편집하지 않는다.
- R3: 미설정·잘못된 값·평가 오류에서 미완성 기능이 열리지 않고, 직접 호출·부수 효과를 해당 경계에서
  제어한다. 인증을 대체하지 않는다. OFF가 기존 데이터·진행 중 작업·비호환 migration을 되돌리지는 않는다.
- R4: spec에는 공개 계약, plan에는 PR별 실행/노출 상태·시험·공개/복구·제거 순서를 필요한 경우에만
  기록한다. 공개 결정자와 기록 위치는 프로젝트가 정한다. 기존 네 plan 절·선택형 스킬을 유지한다.
- R5: 출처와 팀의 선택을 구별하고 연구 결과를 보존한다. 사용판 전달, 독립 설계 리뷰, 실제 Sonnet
  대화 실험, make check 및 독립 검증으로 적정 수준을 판정한다. 역사 자료·원문·등급은 보존한다.

## Acceptance criteria
- AC1 → R1–R4: 정책과 양식에서 작은 완결 변경·미완성 다중 PR·내부 구현 교체의 선택을 구별할 수 있다.
- AC2 → R1–R3,R5: 파생 실험에서 첫 불완전 PR과 다음 완성 PR을 같은 제어로 통합한다. 일반 OFF,
  테스트 ON, 기존 동작, 입력 보존과 같은 코드의 설정 전환을 관측한다. 실험 범위 밖은 명시한다.
- AC3 → R4,R5: 독립 리뷰의 중요한 지적을 처리하고 활성 소비자/사용판 일치, make check, 기존 양식·
  브랜치 정책과 북극성의 회귀 여부를 확인한다. 결과와 HUMAN 개입을 기록한다.

## Design
새 짧은 RELEASE-CONTROL 안내를 기준으로 기존 정책에서 연결한다. 양식의 기존 Design/Order/Proof에
조건부 질문을 추가하고 선택 스킬의 상세 참조에서 실행 판단을 돕는다. 별도 플래그 엔진은 제공하지 않는다.
새 실험은 F02의 작은 CLI 데이터를 재사용하되 목록+요약을 한 공개 단위로 합의한 변형임을 밝힌다.
