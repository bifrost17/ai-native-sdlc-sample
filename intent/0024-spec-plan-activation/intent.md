# Intent: 보완한 spec·plan을 실제 개발에서 사용
Author: 프로젝트 오너의 2026-09-11 요청, Codex가 기록. Status: draft.

## Problem
spec·plan 설계 후보는 리뷰와 읽기 전용 인계를 마쳤지만 활성 양식·설치된 팀 스킬·실제 제품 개발에는 아직 반영되지 않았다.
문서가 좋아 보인다는 판단만으로 TDD와 구현 중 문서 갱신이 실제로 동작한다고 할 수 없다.

## Proposed outcome
보완 후보를 활성 템플릿과 선택 가능한 자체 스킬에 반영하고 Claude Code에 영구 설치한다.
깨끗한 사용 기준에서 파생한 작은 제품을 실제 대화로 개발해, 사람이 인계·검토하는 AI-native SDLC가 대체로 잘 동작함을 확인하고
통과한 범위와 한계를 북극성 주석에 연결한다. 활성화→설치 확인→제품 구현 실험을 단계별 검증 후 연속 진행한다.

## Affected users and systems
이 템플릿으로 사내 동료용 프로그램을 만드는 팀, maker의 양식/작성 지침, 선택형 org-skills 플러그인,
사용 템플릿 브랜치와 별도 Claude Code 실험 복제본. 기존 제품이나 운영 서비스의 변경은 이 요청에 없다.

## Constraints
북극성이 최우선이며 완벽한 재현을 목표로 템플릿을 비대화하지 않는다. 정책은 얇게, 구체 설계·작업 예시는 충분히 둔다.
spec의 구조·동작·계약, plan의 파일·시험·PR·통합 역할과 TDD·GitHub Flow·같은 구현 커밋의 영향 문서 갱신을 유지한다.
사용 템플릿은 제작 자료/필수 스킬을 포함하지 않으며 자체 기본 예시는 선택 자료로 제공할 수 있다.
원 연구·기준 브랜치·실패 기록은 보존한다. root가 HUMAN, Claude Code가 AGENT이며 후속 대화는 실제 응답에 따라 작성한다.
모델/추론은 난도·영향에 맞춘다. 전체 흐름의 회귀를 보되 변하지 않은 가이드를 매번 모두 재평가하지 않는다.

## Open questions
- 실험 오너가 위임한 판단으로 작은 CLI 사례를 우선 선정하고, 그 선택과 웹/운영 미관측 범위를 실행 계획에 기록한다.
- 원 요청: “기존 계획 취지 디시 한번 상기하고 잔여 작업 진행햐보자 하나씩 아니면 한번에?”
  앞서 명시한 잔여 세 작업의 실행 요청으로 기록한다. 기존 설계 패키지의 범위 제한을 이번 활성화 요청에 그대로 적용하지 않는다.
