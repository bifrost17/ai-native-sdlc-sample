# Intent: 설계 인계 검토의 충분성과 적용 확인
Author: 프로젝트 오너의 2026-09-14 요청, Codex가 기록. Status: draft.

## Problem
복잡한 설계에서 공유 계약의 미결정과 독립 장애의 복구 공백을 구현 상세로 이월한 채 리뷰가 통과했다.
현재 지침에도 구체 계약 요구는 있으므로 문서를 늘리는 것보다 그 요구를 실제 검토에 적용할 방법과 시점이 필요하다.

## Proposed outcome
검토한 보완 설계를 두 TDD 배포판의 기존 작성·검토 자산에 반영한다. OpenCode Muse Spark 1.3/xhigh를
대상으로 어려운 설계와 충분한 대조 사례를 시험하고, 중요한 실패는 최소 보완 후 별도 브랜치에서 재검증한다.
북극성이 제시한 사람과 에이전트의 인계가 대체로 잘 동작하는 수준을 목표로 한다.

## Affected users and systems
사내 소프트웨어를 개발하는 템플릿 사용자, 두 배포판의 선택 가능한 작성·피드백 스킬과 검증자,
OpenCode 실험용 사용판과 기록. 원인분석 대상 제품은 읽기 전용 근거이며 직접 수정하지 않는다.

## Constraints
기존 사람의 결정, spec→plan 역할, TDD 판별 차이와 구현 완료의 새 문맥 검토를 유지한다.
새 필수 UML·검토자 수·승인 장부·의미 검사기를 만들지 않는다. 근거와 실패를 보존하고 설치·실제 사용·효과를 구분한다.
root가 HUMAN과 평가자이며 실제 응답에 따라 대화한다. 과제별 브랜치와 원본 입력·설치판·프롬프트·응답·판정을 남긴다.

## Open questions
- 후보 효과와 과잉 반려 여부는 실제 실험으로 판단하며, 기준 실행도 잘 작동하면 개선 우월성을 주장하지 않는다.
- 원 요청: “보완 후 어려운 과제로 오픈코드 뮤즈 스파크 대상으로 실험 진행해서 결과 확인하고 보완하는 루프 돌려줘.”
  설계 단계의 실행 금지는 이번 구현 요청으로 해제됐으며 별도 제품 구현이나 운영 배포까지 허용한 것은 아니다.
