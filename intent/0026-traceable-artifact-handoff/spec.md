# Spec: 고정 식별자와 문서 인계 대조
Upstream: intent.md@5385148. Status: draft.
Skills applied: skill-creator, spec-policy-pass, sdlc-feedback, stop-slop-ko의 현재 로컬 지침을 읽었다.
사용자 설치 feedback은 선택형 0.1.6이며 maker의 정책·기존 허가가 우선한다. 개인정보·외부 API 동작은 변경하지 않는다.

사용자는 추적 구조와 정책·스킬의 구현을 허용했다. 북극성 L2의 의도, L3의 요구·설계,
L4의 실행 계획·동시 개정, L8/L10의 피드백·검토를 잇는다. FR/NFR/SP/T의 표기와
중단·재개 대조는 팀의 구체화이며 플레이북의 축자 요구로 주장하지 않는다.

## Design
### SP01 — 문서 집합 안의 안정 식별자 (FR01, NFR01, NFR02)
FR은 기능, NFR은 품질 요구다. 근거는 intent 문단·답변·팀 정책·기존 계약에서 가져온다.
없는 품질 수치를 만들거나 모든 요구를 intent에 역작성하지 않는다. 요구의 AC는 독립된 관찰 기대다.
SP는 독립적으로 변경·검토할 주요 설계 계약·결정 또는 컴포넌트 책임을 식별한다. 모든 클래스·메서드에
번호를 강제하지 않는다. 하나의 설계가 여러 요구를 충족하거나 여러 설계가 한 요구를 나눌 수 있다.
한 SP는 한 정본에서만 정의하며, 큰 spec의 설계 문서 색인은 ID·소유 경로와 필요한 범위를 연결한다.

ID는 개발건의 문서 집합 안에서 유일하고 이동·순서 변경에도 유지한다. 수정은 같은 대상을 계속
가리키면 ID를 유지하고 Git이 판을 기록한다. 별개 항목·분할은 새 ID와 대체 관계를 남긴다.
폐기 ID를 재사용하지 않는다. 다른 개발건은 문서 경로+ID로 식별한다. 표의 ID를 자동 anchor로
가정하지 않으며 실제 제목/anchor 또는 경로+ID를 사용한다. 판 정보는 기존 Upstream에서 유지한다.
기존 R1/AC1/P1 등은 계속 유효하며 일괄 재번호하지 않는다. 쌍방 조회를 위해 양쪽 관계표를 중복 유지하지 않는다.

### SP02 — 설계에서 실행 작업으로 (FR02, NFR02)
기존 plan 스킬 개정 설계의 핵심을 활성 원본에 반영한다. 의미 있는 작업 T는 SP와 관련 AC를 읽고,
어디를 어떤 방법으로 구현할지·확인할지·무엇을 넘길지 설명한다. 계획의 Files/Proof는 색인으로 쓴다.
작업·서브에이전트·커밋·PR은 1:1이 아니며, 의존성·소유 파일·공유 계약으로 병렬 가능성을 판단한다.
구현 전 기존 계획 수락에서 첫 PR·위험한 단계·버린 대안·근거·Done을 확인한다. 새 승인은 만들지 않는다.
하위 완료만 늘고 같은 인도 결과가 열리면 남은 작업을 재평가하고 현재 요약을 다시 쓴다.

### SP03 — 사건별 정합성 확인 (FR03, FR04, NFR01, NFR02)
프로젝트 CLAUDE에는 짧은 현재성 원칙, Git/PROCESS에는 커밋·인계·재개 사건을 기록한다.
기존 sdlc-feedback에서 실제 diff와 관련 미포함 변경·합의를 시작점으로 T→SP→요구/AC·intent 제약을
대조한다. 변경된 문서만 보고 통과하지 않으며, 필요한 실제 결정·관찰을 읽는다. 갱신 뒤 실제 commit
포함 내용을 확인하고, 부분 stage에 무관한 작업을 묶지 않는다. 설계 개정은 다음 의존 작업 전에
영향 정본을 고친다. 코드 결함이면 요구를 낮추지 않고 코드를 고친다. plan-only 변경도 관련 구현과 커밋한다.
중단 시 기존 plan의 현재 요약·실행 기록에 코드판, 미커밋 작업, 완료·미검증, 다음 작업을 남긴다.
미해결 충돌은 드러내고 영향을 받는 후속 작업을 준비 완료로 보지 않는다. 강제 중단을 예방한다고
주장하지 않는다. 재개하면 문서·근거·실제 Git 상태 차이를 먼저 판단한다. 상태 질문만으로 실행하지 않는다.
중요 검토는 기존 verifier를 재사용하며 매 커밋 새 reviewer나 별도 commit 스킬을 만들지 않는다.

### SP04 — 양 배포판과 제공 어댑터 (NFR01, NFR02)
작성 양식·스킬은 각 project가 정본이다. org 패키지는 feedback/verifier 수정에 맞춰 기본형 0.1.11,
선택형 0.1.7로 올리고 카탈로그·안내·제공 patch를 맞춘다. Codex는 현재 선택형 adapter만 제공한다.
개인 설치본과 별도 제품은 자동 갱신하지 않는다. 과거 연구·실험과 원문/주석의 판정을 덮어쓰지 않는다.

## Constraints and scope
활성 양식·작성 자산·정책·팀 스킬과 패키지를 수정한다. 문서 연결의 행동 확인은 작게 시행할 수 있으나
실제 제품 구현 전체나 두 판의 TDD 실행 통과로 확대하지 않는다. 새 모델/외부 서비스 설정은 추가하지 않는다.

## Open questions
없음. 기존 판의 번호 보존과 새 양식의 번호 체계를 함께 지원한다.

## Flagged concerns
고정 ID가 있어도 본문 변경 뒤 참조 의미가 낡을 수 있다. 그래서 링크 존재보다 내용·기대·현재 범위를
검토한다. 서술이 길어지는 위험은 기존 안내의 교체·짧은 정책·작은 예시 유지로 줄인다.
