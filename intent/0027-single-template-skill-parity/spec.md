# Spec — 단일 템플릿과 스킬 전달 동등성

Status: draft
Upstream: [intent](intent.md), 현재 변경의 사용자 요청. 기준 코드 `b9af49a`.

## Requirements
- FR01: `tdd-first/`를 현재 소스와 설치 카탈로그에서 제거하고 `tdd-optional/project/`를 유일한 채택 경로로 안내한다.
- FR02: Codex와 Claude Code에 작성 3개·팀 13개 스킬과 같은 독립 검토 기준을 제공한다. 설치·갱신·명시 호출·출처 확인을 재현할 수 있어야 한다.
- FR03: 제작 도구·평가·CI의 기본 실행이 남은 템플릿을 사용한다. 폐기한 판을 요청하면 명확히 거부하며 다른 판으로 조용히 대체하지 않는다.
- NFR01: 기존 `tdd-optional/` 경로와 패키지 식별자를 유지한다. 과거 근거는 당시 판으로 남기고 현재 채택 지침과 구분한다.
- NFR02: 명시 사용 정책, 작업별 검증 방식, 동반 자료와 기존 프로젝트 정책을 보존한다. 개인 설치·비밀값·제품 코드를 변경하지 않는다.

## Design
### SP01 — 현재 소스와 역사 경계 (FR01, FR03, NFR01)
`tdd-first/`의 추적 파일을 삭제한다. 삭제 직전 소스는 Git `b9af49a`로 찾는다.
루트·배포 카탈로그는 `intent-sdlc-skills-optional` 하나만 제공한다. 경로 재배치는 하지 않는다.
활성 README, CLAUDE, 채택 안내, 작성 라우터와 실행 기본값을 선택형으로 정리한다.
이전 intent·연구·실험·검증 원본은 재작성하지 않는다. 역사 색인에는 폐기 사실과 당시 Git 판을 명시한다.
OpenCode의 기존 어댑터는 보존하되 이번 동등성 대상은 Codex와 Claude Code다.

### SP02 — 공통 스킬과 도구별 설치 (FR02, NFR02)
스킬 정본은 기존 `project/examples/skills/`와 `org-skills/skills/`이다. 별도 Claude 복제본은 만들지 않는다.
Claude는 팀 플러그인과 프로젝트 작성 스킬 폴더 복사를 명시적으로 구분한다. Codex는 현재 패치 방식으로
같은 16개 폴더와 검증 기준을 전달한다. 도구별 호출명·명시 사용 설정·검증자 정의 차이는 설명한다.
전체 폴더를 복사하고 기존 설치가 있으면 비교·병합한다. 전역 설정·기존 제품의 설치를 묵시적으로 덮어쓰지 않는다.
확인은 파일/메타데이터/패치·출처 확인과 실제 모델 실행을 구별한다. 두 설치 경로의 공통 기준·자료가
유지되는지 임시 제품 복사본으로 확인한다. 템플릿 채택에 새 실행 검사기를 요구하지 않는다.

### SP03 — 배포와 검증 (FR01–03, NFR01–02)
패키지는 `0.1.8`로 올리고 현행 카탈로그·설치 안내를 맞춘다. 기존 단위·실행 시험을 단일 판으로
전환하고 폐기 판 거부·자료 격리·경로가 실제로 동작하는지 확인한다. 삭제로 시험을 우회하지 않는다.
북극성 주석은 현재 배포 구조와 확인한 설치 범위만 추가하며 이전 행동 판정을 승격하지 않는다.

## Acceptance criteria
- AC01: 활성 기본형 폴더·카탈로그·기본 실행 경로가 없고 남은 기본 실행과 잘못된 판 거부가 검증된다.
- AC02: 두 도구 설치 예시로 같은 16개 스킬과 참고 자료를 얻으며 명시 사용·검토 기준이 유지된다.
- AC03: `make check`, Claude manifest strict 검사, 임시 Claude/Codex 설치 및 기존 어댑터 회귀 확인을 통과한다.
- AC04: 역사 근거·미추적 연구·전역 설치·제품 작업을 보존하고 실제 검증 한계를 기록한다.

## Skills applied
`skill-creator`(Codex system): 공통 정본·필요한 참고 자료·기존 호출 정책 보존.
`sdlc-feedback`(사용자 설치 0.1.7), `spec-policy-pass`, `brand`, `stop-slop-ko`(사용자 설치 0.1.6):
현재 합의·실제 diff·문서와 검증 연결, 출처·한계 보존, 정확한 이름과 간결한 문구.
제품 endpoint·데이터 계약 변경이 없어 data-compliance/secure-api-review는 적용하지 않는다.

## Flagged concerns
없는 모델 실행이나 자동 로드·동작을 파일 검사 통과로 주장하지 않는다. 새 전체 SDLC 실험은 이번 변경의 필수 범위가 아니다.
