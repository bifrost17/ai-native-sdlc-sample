# Spec policy pass

L3 282: "Apply the skills available to you so the plan conforms to our brand guidelines, security policies and UX standards."
L3 279: spec, originating prompt and "the skill versions in force" belong in version control.

이것은 팀이 제공하는 기본 정책 검토 예시다. 요구·설계 작성 스킬을 보완하며 정책의 정본을 새로 만들지 않는다.
프로젝트가 사용하는 spec 양식과 수락 절차를 따른다. 기존 허가·결정은 재사용하고 같은 질문을 다시 승인받지 않는다.

## Apply relevant policies

프로젝트와 실제 세션에서 제공되는 팀 스킬 목록을 함께 확인해 이 변경에 적용할 정책 스킬을 고른다.
관련성이 있는 스킬을 이름만 알고 빠뜨리지 않는다. 관련 있어 보이지만 적용하지 않는 정책은 이유를 짧게 남긴다.
무관한 모든 도구/스킬을 나열하거나 표를 채우기 위해 적용하지 않는다.

선택한 스킬의 본문을 실제로 읽고, 그 제약을 요구·설계·AC에 적용한다. 파일을 읽지 않고 이름이나 SHA만
얻은 것은 적용 근거가 아니다. 스킬을 통해 확인한 공식 정책의 경로·조항·현재 판을 기준으로 삼는다.
스킬과 정책 정본이 어긋나면 그 차이와 영향을 드러내고 필요한 정책 오너의 판단을 받는다.

Skills applied에는 실제 읽고 적용한 스킬의 이름, 출처(namespace와 실제 파일 경로), 확인한 판을 기록한다.
- Git 이력이 있으면 그 스킬 저장소의 실제 파일 기준 SHA와 로컬 변경 여부를 쓴다.
- 캐시/설치본에 Git이 없으면 확인한 manifest/설치 버전과 출처를 쓴다. 사용하는 제품 저장소의 SHA로 대신하지 않는다.
- 판을 확인할 수 없으면 version-unverified와 이유를 쓴다. 소스 폴더가 있다고 설치/로드됐다고 하지 않는다.

관련 스킬이 없거나 접근할 수 없으면 none 또는 그 한계를 적고, 직접 확인한 정책/입력의 근거를 구별한다.
스킬 부재가 의도·프로젝트 정책의 부재를 뜻하지 않는다. 원 prompt와 적용 판은 기존 versioned spec/PR 기록에 보존한다.

## Review the complete spec

spec.md와 선언된 설계 정본 전체를 같은 판으로 읽는다. 하나의 파일이어도 여러 파일이어도 된다.
정책의 영향을 받은 결정을 그 정본에서 고치고 spec 진입점에서 찾을 수 있게 한다.
요구는 사용자가 관찰할 결과로, 설계는 필요한 구조·인터페이스·상태·실패까지 구체적으로 쓴다.
구체화 때문에 중요한 클래스/계약을 plan으로 밀거나, 문서 하나로 줄이기 위해 내용을 생략하지 않는다.
수치가 실제 정책/요구에 있으면 제안 결과가 지키는지 확인한다. 미확인 수치를 새 정책으로 만들지 않는다.

## Surface material concerns

정책 충돌이나 사람의 결정이 필요한 중요한 우려는 spec의 Flagged concerns와 요약에서 먼저 드러낸다.
근거·영향·필요한 결정·담당 역할/확인할 주체·필요 시점을 쓴다. 결정자가 미정이면 그렇게 밝힌다.
충돌은 양쪽 조항이나 intent 제약을 연결한다. 조항이 없다는 사실만으로 위반이라고 판정하지 않는다.
정책 공백, 확인되지 않은 사실, 제안 가정은 서로 구별하고 그 영향에 맞춰 다룬다.

표는 여러 우려를 비교할 때 선택한다. 중요한 미해결 우려가 없으면 살핀 범위와 함께 없다고 쓸 수 있다.
해결된 기술 위험은 Design/AC에 근거와 대응을 남기면 된다. 우려 수를 채우거나 모든 가정을 승인 건으로 만들지 않는다.
이미 내려진 사람 결정을 지우고 결정 칸을 다시 비워 두지 않는다. 미결 판단을 완료/승인으로 만들지도 않는다.

설계를 무효화할 미정이나 실제 정책 충돌은 의존하는 인계 전에 해당 오너와 해결한다.
뒤 단계에서만 필요한 운영 입력은 영향·해결 주체·필요 시점과 함께 이월할 수 있다.
허가된 내부 선택은 근거와 함께 설계에 기록한다. 정책을 재해석해 충돌을 숨기거나 임의로 정책 조항을 고치지 않는다.

## Non-interactive runs

주어진 결정과 허가된 선택 범위에서 작성하고 근거를 남긴다. 사람만 결정할 미해결 사항은 영향과 함께
명시하며 그에 의존하는 설계를 인계 준비 완료로 표시하지 않는다. 질문할 수 없다는 이유로 수락을 발명하지 않는다.
이 스킬은 plan·제품 코드·새 승인 체계를 만들지 않으며, 정책 적용과 충돌을 검토하는 권고적 수단이다.
