# PROJECT-POLICY — ‹프로젝트 이름›
Owner: ‹이 프로젝트의 파트 담당›. Upstream: 팀 조항 `policies/*.md`@‹sha›. Status: draft.

팀 조항(`B`/`C`/`U`/`S`)은 이 프로젝트에도 그대로 걸린다. 이 파일은 팀 조항이 「프로젝트가 정한다」고 남긴 **여섯 슬롯**만 채운다.
비워 둘 때는 지우지 말고 「해당 없음 — 사유」로 남긴다. 스킬은 이 슬롯 ID 를 인용한다.

| 슬롯 | 무엇 | 값 |
|---|---|---|
| **P1** | 이름과 표기 — 제품·기능·환경·상태의 공식 이름 목록, 날짜·시각·수량 형식, 시간대 | ‹› |
| **P2** | 민감 데이터 — 무엇이 민감한가, 어떻게 가리는가, 이력 보존 기간과 근거 | ‹› |
| **P3** | 사내 전제를 벗어나는 것 — 사외 노출·외부 사용자·규제 대상이면 추가 규칙(동의·통지·접근성 기준). 없으면 「해당 없음」 | ‹› |
| **P4** | 인증과 권한 — 인증 방식, 검증 주체, 역할과 그 경계 | ‹› |
| **P5** | 외부·상류 호출 — 한도, 캐시 정책, 실패 시 동작 | ‹› |
| **P6** | 스키마 — 어디에 있고 민감 필드를 어떻게 표시하는가 | ‹› |

채운 예시: `org-skills/examples/claims-status/PROJECT-POLICY.md` — 플레이북의 청구 상태 서비스를 한 프로젝트로 보고 채운 것(그 예시는 사외 고객 대상이라 P3 이 채워져 있다).
