# policies — 조직 정책의 정본

플레이북 L3(spec 은 조직 정책을 제약으로 받는다) · L6(정책 스킬은 오너의 문서화된 source of truth 에서 쓴다)의 그 정책이다.

## 전제

**사내 임직원이 쓰는 소프트웨어만 만든다.** 외부 고객에게 팔거나 제공하지 않는다.
그래서 정책은 「지키지 않으면 회사 밖에서 문제가 되는 것」이 아니라 **「지키지 않으면 동료가 시간을 잃거나 사내 데이터가 새는 것」**만 담는다 — 조항 열 개 남짓.
외부로 나가는 프로젝트가 생기면 그 프로젝트가 `PROJECT-POLICY.md` 의 **P3** 에 추가 규칙을 적는다.

## 두 층

| 층 | 어디 | 누가 | 무엇 |
|---|---|---|---|
| **팀 조항** | 이 폴더의 `brand.md` · `compliance.md` · `ux.md` · `api-security.md` | 정책 오너(팀) | 어느 프로젝트에나 걸리는 것. ID `B`/`C`/`U`/`S` + 번호 |
| **프로젝트 슬롯** | 각 프로젝트 레포의 `PROJECT-POLICY.md`(양식 `PROJECT-POLICY.template.md`) | 그 프로젝트 파트 담당 | 프로젝트마다 달라지는 값. ID `P` + 번호, 여섯 개 |

팀 조항은 값을 정하지 않는다 — **무엇을 정해야 하는지**만 정하고 값은 슬롯이 받는다.

## 서명과 판

- 정책을 바꾸는 것은 PR 이고 **오너가 머지하는 것이 서명이다**(L6 460 · `.github/CODEOWNERS` 의 `policies/**`).
- 정책이 바뀌면 인용하는 스킬도 같은 PR 에서 바꾸고 `org-skills/.claude-plugin/plugin.json` 의 `version` 을 올린다 — 안 올리면 팀 세션에 갱신이 가지 않는다.
- spec 은 실제 읽은 스킬의 출처와 판을 `Skills applied` 에 남긴다(`templates/spec.md`). Git 이력을 확인할 수 있으면 `name@sha`, 설치 캐시에 이력이 없거나 Git 접근이 없으면 해당 플러그인의 manifest/설치 메타데이터에서 확인한 버전과 출처를 적는다. 로컬 체크아웃의 manifest만 읽은 경우에는 미커밋 변경 여부를 확인하지 못했음을 함께 적고, 판 자체를 확인하지 못하면 이유와 함께 `version-unverified` 로 남긴다.

## 🔴 지금 문면의 지위

지어낸 조직 값은 두지 않았다 — 값이 필요한 자리는 전부 슬롯이다.
조항 자체는 정책 오너가 팀의 실제 문서에서 다시 쓸 자리이고, 지금은 **어느 사내 SW 에나 걸리는 바닥선**만 적혀 있다. 미결 물음은 `docs/decisions/OWNER-QUESTIONS.md`.
