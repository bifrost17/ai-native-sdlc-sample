# API 보안 정책 — 팀 조항 (S)
Owner: 정책 오너. Status: draft — 바닥선(`policies/README.md`).

전제: **사내 임직원이 쓰는 소프트웨어**다 — 외부 고객에게 팔거나 제공하지 않는다. 그래서 조항은 얇다.
외부로 나가는 프로젝트(사외 사용자·외부망 노출·규제 대상)는 그 프로젝트가 **P3 에 추가 규칙을 적는다.**

S1~S4 는 플레이북 레슨 6 의 worked example 그대로이고 **문면의 정본은 템플릿 스킬 `.claude/skills/secure-api-review/`** 다 — 여기서는 ID 만 준다.

- **S1** 인증: 모든 엔드포인트가 인증을 요구한다. 익명 경로는 명시된 것(헬스체크 등)뿐. 방식과 검증 주체는 **P4**.
- **S2** 입력 검증: 요청 본문을 스키마로 검증하고 알 수 없는 필드를 거부한다. 스키마의 자리는 **P6**.
- **S3** 감사: 상태를 바꾸는 엔드포인트는 actor · action · entity · timestamp 를 남긴다(C3 과 같은 이력이다).
- **S4** 데이터 분류: 민감으로 표시된 필드는 로그·오류 메시지에 나오지 않는다(C2).
- **S5** 역할이 둘 이상이면 권한 경계를 **P4** 에 적고, 한 핸들러는 자기 역할의 것만 읽는다.

외부망 노출·열거 방지·레이트 리밋 같은 조항은 사내 전제 밖이다 — 해당하는 프로젝트가 **P3**·**P5** 에 적는다.
