# API 보안 정책 v0
Owner: 정책 오너(이 레포 소유자). Status: draft v0 — 오너 서명 대기(서명 = 개정 PR 머지). 조항 ID 는 스킬·coverage 가 인용하는 고정 키다.
대상: 보험 청구 상태 조회 서비스(고객 포털 · 사정인 · 상담사 경로)와 그 고객 통지.

S1~S4 는 템플릿의 `secure-api-review` 스킬(플레이북 예시 축자)이 이미 덮는다 — 문면은 그 스킬이 정본이고 여기서는 ID 만 준다.
- **S1** 인증: 모든 엔드포인트는 게이트웨이 JWT 를 요구, `/health` 밖의 익명 경로 없음. (org note: 포털이 JWT 를 검증해 세션으로 넘기므로 세션만 읽는 코드는 S1 을 만족.)
- **S2** 입력 검증: 요청 본문을 OpenAPI 스키마로 검증, 알 수 없는 필드 거부.
- **S3** 감사: 상태를 바꾸는 엔드포인트는 actor · action · entity · timestamp 의 audit 이벤트.
- **S4** 데이터 분류: 스키마에 pii 로 표시된 필드는 로그·오류 메시지에 나오지 않는다.
## 4항목 밖
- **S5** 상류 호출 예산: 청구 상태 상류(claims-core)는 50 rps 한도 — 새 경로는 캐시 정책과 호출 수 계산을 spec 에 적는다.
- **S6** 열거 방지: 존재하지 않는 청구 번호와 권한 없는 청구 번호는 같은 응답(not_found)과 같은 지연.
- **S7** 세션 계약: 역할(customer · adjuster · agent)마다 세션 키 이름이 다르고, 한 핸들러는 자기 역할의 키만 읽는다.
- **S8** 비밀값: 코드·설정·diff 에 자격증명 금지(훅 no-secrets 가 뒤를 받친다).
