# PROJECT-POLICY — 청구 상태 조회 서비스 (예시)
Owner: 서비스 오너(청구 상태 API). Upstream: 팀 조항 `policies/*.md`. Status: **예시** — 실제 프로젝트의 것이 아니다.

플레이북의 worked example 을 한 프로젝트로 보고 슬롯을 채운 모습. 팀 전제(사내 전용)를 벗어나는 프로젝트라 **P3 이 두껍다.**

| 슬롯 | 값 |
|---|---|
| **P1** 이름·표기 | 상태 어휘 다섯: 접수 · 심사중 · 보완요청 · 지급완료 · 종결(동의어 금지) · 회사·상품·기관은 공식 표기 · 날짜 `YYYY-MM-DD` · 금액 천 단위 + 「원」 · 시각 24시간제 KST |
| **P2** 민감 데이터 | 주민등록번호 · 계좌번호 · 연락처 전체는 마스킹(뒤 4자리)만 · 조회·통지 이력 3년 보존 |
| **P3** 사내 전제 밖 | **사외 고객 대상**: 통지는 수신 동의가 기록된 채널만, 확인 불가 시 발송 안 함 · 통지 본문에 근거와 문의 경로, 민감 상세 금지 · 대리 조회(상담사·사정인)는 본인확인 기록이 있을 때만 기록 ID 와 함께 · 외부 노출이라 열거 방지(없는 번호와 권한 없는 번호의 응답·지연이 같다) |
| **P4** 인증·권한 | 포털이 게이트웨이 JWT 를 검증해 세션으로 넘긴다(앱은 세션만 읽음) · 역할 customer · adjuster · agent, 역할마다 세션 키 이름이 다르고 핸들러는 자기 것만 읽는다 |
| **P5** 외부·상류 호출 | claims-core 50 rps — 새 경로는 캐시 정책과 호출 수 계산을 spec 에 적는다 |
| **P6** 스키마 | OpenAPI 스키마, 민감 필드는 `pii` 표시 |
