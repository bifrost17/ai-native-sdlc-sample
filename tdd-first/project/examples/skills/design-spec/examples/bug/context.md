# B01 예시 입력과 후속 답변

root가 작성한 합성 사례다. 실제 수락·구현·테스트 실행 기록이 아니다.

- Q1: 양끝의 ASCII space, tab, CR, LF만 허용한다. 다른 유니코드 공백은 확대하지 않는다.
- Q2: 내부 공백과 대소문자를 유지한다. 그런 입력과 공백뿐인 입력은 기존 없는 요청처럼
  rc=1이며 파일을 바꾸지 않는다.
- Q3: show와 complete 모두 같은 규칙이다. list는 변경하지 않는다.

코드 읽기 관측: baseline은 show/complete가 공유하는 조회에서 저장 ID와 args.id를 그대로
비교한다. 저장 데이터는 대문자 R-와 세 자리 숫자다. 이 읽기 결과는 재현 테스트 실행을 뜻하지
않는다. 요청자가 알고 있던 원인으로 거슬러 기록하지 않는다.

대표 데이터(합성): R-201=open/hana, R-202=open/min, R-203=done/hana.
기존 complete는 대상 status만 done으로 바꾸고 이미 완료된 대상은 파일을 다시 쓰지 않는다.
실패 문구는 `Request not found: ` 뒤에 전달한 ID를 표시하며 rc=1이다. 다른 I/O 오류 처리는
이 변경에서 유지한다. 검증 사례마다 별도 데이터 복사본을 시작한다.

제작 출처는 datasets/v1/B01의 공개 카드·HUMAN 답변 D1~D3와 baseline/tracker.py다.
intent의 데이터 보존 문장은 기존 complete까지 금지한 것으로 읽히지 않도록 명시했다.
이는 예시 입력의 명료화이며, 실제 사용자에게 새 답을 받았다고 주장하는 기록이 아니다.
