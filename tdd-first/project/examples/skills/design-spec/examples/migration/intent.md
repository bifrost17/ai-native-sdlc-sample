# Intent: 여러 동료의 요청 처리 결과가 서로 덮어써지지 않게 보존
Author: 합성 업무 오너 M01. Status: draft.

## Problem
사내 요청 서비스가 JSON 파일을 읽고 고쳐 통째로 저장한다. 서로 다른 요청을 동시에 완료하면
나중 저장이 먼저 저장한 상태를 덮을 수 있다. 수동 복구에 의존하지 않도록 바꾸고 싶다.

## Proposed outcome
여러 동료가 처리한 결과가 모두 보존되고 기존 요청도 그대로 이용할 수 있기를 바란다.
담당 개발자는 SQLite 전환을 제안했으나, 이행·복구를 포함한 설계는 아직 정하지 않았다.

## Affected users and systems
사내 웹 화면·요청 API·JSON 저장소. 별도 내보내기나 보고서 소비자가 있는지는 확인이 필요하다.

## Constraints
기존 요청 ID·필드·목록 순서와 API의 정상 응답을 유지한다. 기존 사내 인증과 요청 담당자/운영자
권한 범위를 바꾸지 않는다. 외부 서비스·계정은 추가하지 않는다. 짧은 서비스 중지는 허용되지만
처리된 결과와 기존 데이터를 잃어서는 안 된다.

## Open questions
- Q1 현재 API 밖에서 JSON을 읽거나 쓰는 소비자가 있는가? 업무 오너가 운영 담당과 확인한다.
- Q2 이행 전후 복구와 재실행의 기대는 무엇인가? 업무 오너·운영 담당이 정한다.
- Q3 실제 실행 환경과 저장소를 관리할 역할은 누구인가? 운영 담당이 확인한다.
