# 채택한 SDLC feedback을 프로젝트 지침에 연결하기

팀이 이 스킬을 채택한 경우에만 아래 예시를 제품 `CLAUDE.md`에 합친다. 기존 팀 규칙과 동등한
검토가 있으면 그 경로를 사용하며 중복 단계는 만들지 않는다. 설치는 스킬을 사용할 수 있게 하는
일이고, 이 예시는 팀이 언제 사용하기로 했는지를 알려준다. 자동 실행을 보장하는 장치는 아니다.

## Claude Code

```markdown
## Adopted team workflow

계획한 구현이나 동작·요구·설계·계획에 영향을 주는 후속 요청을 처리할 때 채택한
`intent-sdlc-skills-optional:sdlc-feedback` 스킬을 읽고 현재 이벤트에 해당하는 절을 따른다.
구현 완료 보고 전에는 그 절차에 따라 최신 변경 범위를 검토하고 결과를 기다린다. 앞선 검토 이후
바뀐 동작을 이전 검토로 갈음하지 않는다. 현황 질문·단순 산문 정정에는 이 구현 검토를 실행하지 않는다.
```

## OpenCode

위 예시에서 스킬 이름을 아래 로컬 경로로 바꾸고 같은 제품 `CLAUDE.md`에 넣는다.

```markdown
`.opencode/skills/sdlc-feedback/SKILL.md`
```

두 플랫폼 모두 실제 설치 경로·판이 맞는지 확인한다. 스킬 본문이 문서 개정·같은 커밋·선택한 검증
방식·검증자 인계를 담당하므로 그 전문을 프로젝트 지침에 복제하지 않는다. 팀이 다른 동등한 스킬을
채택했다면 이름/경로를 바꾼다. 사람의 결정·수락·병합 권한은 프로젝트 정책을 그대로 따른다.
