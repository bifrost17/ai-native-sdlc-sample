# F01 예시 입력과 후속 답변

root가 작성한 합성 사례다. 실제 수락·구현·테스트 실행 기록이 아니다. intent 이후 다음 답변을
받았다는 조건으로 spec을 작성한다. 다른 프로젝트의 기본 요구나 정책으로 사용하지 않는다.

- Q1: 완료 건도 포함하고 원래 파일 순서를 유지한다. 최근 완료 건도 함께 확인하기 때문이다.
- Q2: 담당자 문자열이 정확히 일치해야 한다. null은 어떤 문자열과도 일치하지 않는다.
  미배정 선택은 이번 범위 밖이다. 없는 담당자는 빈 stdout, rc=0이다.
- Q3: `list --owner <ID>`를 제공하고 옵션 없는 list는 기존 전체 목록 그대로다.

코드 읽기 맥락: baseline은 argparse의 list/show/complete 명령과 공통 display 함수를 사용한다.
list는 JSON의 requests 배열을 순서대로 읽어 ID·상태·담당자·제목을 탭으로 출력한다.
show/complete는 ID 조회를 공유한다. complete만 대상 상태를 done으로 저장하며 반복 완료는
파일을 다시 쓰지 않는다. 새 아키텍처나 저장소가 필요한 입력이 아니다.

대표 데이터(합성): R-101=open/hana, R-102=open/min, R-103=done/hana, R-104=open/null 순서다.
시험은 각자 새 데이터 복사본을 사용한다. 이 문서의 예시 ID는 고정된 제품 요구가 아니다.

제작 출처는 저장소의 datasets/v1/F01 공개 카드와 HUMAN 답변 D1~D3, baseline/tracker.py다.
여기에는 합의 후의 예시를 위한 답변만 옮겼다. 개발 대화 실험의 AGENT 입력으로 이 문서를
사용하면 아직 받지 않은 답이 노출되므로, 자연 질문 능력을 측정하는 실험에는 그대로 쓰지 않는다.
